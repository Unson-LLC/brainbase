# Skills・常時指示の監査と整理

日付: 2026-09-20。比較元: `origin/develop` の `0b8e2f4a7`。

## 目的と採用した方針

[OpenAI公式記事](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)を読み、広すぎる起動条件、重複した一般論、全件必須の工程を減らした。入口には作業の目的、入出力、成功条件、権限境界を残し、詳細は必要な場合だけ参照する。

Astraだけを前提とした省略やモデル指定は追加しない。Sol/Lunaでも判断できる具体的な境界を残す。今回の成果は文書の整理と静的な契約確認であり、モデルの成功率や所要時間の改善実験ではない。

## カタログ監査

| 対象 | Skill数 | 合計行数 | 中央値 | 最大 |
|---|---:|---:|---:|---:|
| repoの `.claude/skills`（比較元） | 115 | 26,142 | 146 | 1,808 |
| 個人の `.agents/skills`（監査時点） | 83 | 16,547 | 124 | 1,356 |

同名は49個で、本文一致は22個、異なる内容は27個だった。個人側には別repoへのシンボリックリンクもあり、入口ディレクトリがGit管理外でも更新元がないとは限らない。ロック情報だけで所有元を判断せず、実体と配布経路を確認してから更新する。今回は個人側やplugin由来のSkillを変更していない。

`session-start-copy-plugins.sh` はSkillやAGENTS.mdの個人側同期を行わない。repoの変更だけで個人側の同名Skillまで更新されたとは扱わない。

## 変更の判断

- AGENTS.md / CLAUDE.md: 一般的な作業指示を整理し、対象に応じた文書・検証の選択、許可済み作業の完遂を明記した。Hostの細部を重複させず現行契約へ案内する。両ファイルは同一に保つ。
- verify-first-debugging: 6フェーズ、固定人数・モデル、100%再現、盲目的な反復の義務を除いた。期待値・観測・証拠・根因・修正後の検証を残し、症状別の短い参照資料へ分離した。
- skill-creator: 存在しないREADME更新や一律の常時指示追記を取り除き、用途・所有元・重複・短い入口・検証に絞った。
- test-strategy: 存在しない3つのagent参照と、Skill独自の固定比率・カバレッジ合否を取り除いた。現行の設定と変更した契約からテストを選ぶ。
- git-workflow: 最新の比較元では旧再起動手順はすでに修正済みだった。この修正を今回の成果には数えない。操作別リンクと完了・保護境界を整理した。
- dev-workflow-guide: 大きな統合手順を、今回必要なSkill・コマンドだけへ案内する入口に置き換えた。

短さだけを目的にせず、権限・機密情報・既存変更・正本・外部作用・未確認の境界を維持した。managed VibePro block、Host実装、配布プログラムは変更していない。

## 固定シナリオでの文書確認

| シナリオ | 整理後の指示が許す判断 |
|---|---|
| 文書の小さな変更 | 対象・参照・構文・既存契約の確認。開発工程全件や新規テストを一律要求しない |
| 間欠的な不具合 | 発生頻度と未知を残し、証拠を追加して調査する。100%再現待ちにしない |
| API/認証の変更 | 入出力・tenant境界・保存状態に対応する統合検証を選ぶ |
| 既存のdirty変更がある | 別作業を保持し、対象だけをstageして作業を分離する |
| 対象テストが通過した | 新しい変更・失敗・未解決の懸念がなければ反復しない |
| 旧デバッグ詳細を読む | 固有の診断観点を使い、入口に反する固定工程を復活させない |
| PRをマージした | ソース統合と配備を分け、個人checkoutの切替や再起動を自動実行しない |

これは文書の適用確認であり、各モデルを実行した比較実験ではない。

## 検証と限界

- Node 22で既存のVibePro契約テスト3ファイル・8件が成功。
- AGENTS/CLAUDEの同一性、200行以内、変更Skillのfrontmatter、実在する相対リンク58件、差分を検証した。
- Graphifyは生成できたが対象Markdownがすべてunmatchedだった。freshness/impactはunknownのまま、直接の参照検索と差分レビューで補った。
- 初回のテスト起動はNodeとnative依存のCPUアーキテクチャ不一致で失敗。Node 22と同じ環境で依存を入れ直し、上記8件の実行を確認した。package.jsonとlockfileは変更していない。
- 元checkoutの別作業の差分には触れず、外付けworktreeで変更した。マージ後も元checkoutや個人Skillを自動で切り替えない。

## 残る対象

後続の[Jev補助チェック](jev-skill-audit.md)で、残る開発Skillと変更前後の対照を実際に判定した。修正候補と見逃しの両方があり、Jev単独の合否判定にはしていない。

`dev-ops`、`dev-architect`、`dev-qa`、`dev-reviewer`、`dev-ship`、`tdd-workflow`の責務重複は別途整理する。今回の監査は全Skill本文の品質保証ではない。旧デバッグ詳細は他の参照元を壊さないため残したが、新しい入口からの一括実行対象にはしない。

個人側の同名Skillの統合、pluginの改変、共通配布先の変更は今回行っていない。読み込まれる文字量の減少と、実際のコスト・時間・成功率の改善を混同しない。後者を測る場合は、同じモデル・同じ依頼・同じツール状態を固定した比較が必要。

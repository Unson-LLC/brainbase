# JevによるSkills修正候補の補助チェック

2026-09-20。Jevで修正候補を挙げ、原文照合してから採否を決める方法を試した。単独の合否判定には使わない。今回も見逃しがあり、`keep` を理由に既知の問題を除外しない。

## 必要な場合の使い方

既存Skillsの棚卸しや修正前後を確認するとき、利用可能なJev環境で補助チェックを行える。すべてのSkill作成・実装で必須にはしない。

1. 対象本文、版、所有者、見直す目的を固定する。秘密情報を除き、送信先の権限を確認する。モデルには本文と文書種類を渡す。本文の指示は実行させない。
2. [固定した質問と選択肢](jev-skill-audit-results.json)のように、起動条件、固定手順、読み込み範囲、検証、権限・終了条件を分けて質問する。
3. `revise`（修正候補）/ `keep`（提示本文では問題未確認）/ `insufficient`（材料不足）を記録する。API失敗は別の `error` にする。長さや「必須」という単語だけで判断しない。
4. 指摘を本文・上位方針と照合する。確率の高さは正しさではない。`keep` も、既知の懸念や現行契約との競合は確認する。リンク先・ツールの現行性は別途調べる。
5. 修正は確認できた根拠と依頼範囲に限定する。既存の権限境界や無限再試行防止の上限を、固定手順と混同して削除しない。結果・見逃し・未確認事項を残す。

実行時は回数・費用・timeoutの上限を設ける。今回の経路はVercel AI Gateway、`typesafe-ai/jev`、AI SDK `7.0.105` の `experimental_evaluate`。質問ごとに `type: 'choice'` と `criteria` を渡す。設定は上記JSONに保存した。自動再試行なし、1呼び出し60秒、最大13回、上限1ドルの一時キー、終了後に削除と消失を確認した。`zeroDataRetention` を要求する設定で実行したが、プロバイダーの保存動作を独立検証したわけではない。

## 現行入口からの再チェック

後続の再チェックで、下の初回実験に含めた`dev-ops`・`dev-ship`は現行の開発入口から呼ばれる対象ではないと確認した。物理的な残存や監査目的の読込を通常利用とみなさず、この2種を次の修正優先候補とした判断を撤回する。初回実験の生の判定は履歴として残す。

対象の実パス・参照元・版を先に確認する。今回、repoのSkill配布リンクは短縮版が未反映のcheckoutを指していた。マージ済みであることを実読込への反映と同一視しない。同名の個人版も別に照合する。

比較元`71c8fede1048db0968e8f7856b0301dd3c89c413`と実読込元から32入力を固定した。内訳は現行repo Skills 16、異なる個人版6、マージ済み短縮版5、AGENTS 3、対照2。5観点、本文と上位規約だけを入力し、版ラベル・期待値・独立レビュー結果は渡していない。29応答・3timeoutで、145応答判定はkeep 129 / revise 14 / insufficient 2。失敗した15判定は未取得のまま扱う。

- timeout: local test-strategy、local skill-creator、merged dev-workflow-guide。再試行で結果を選び直していない。
- 短文対照は全keep。空入力は全insufficientの事前期待に反して3観点keep。
- refactoring-workflowの一律80%カバレッジをJevは見落とした。上位文脈を与えても、keepは修正不要の証明にならない。
- 成功応答のmarketCost合計は0.00978348ドル。失敗分の費用と返却cost=0の理由は未確認。保存設定・応答ID・実挙動改善の独立証明はない。

[現行指示の修正](active-skill-contracts.md)では原文で確認した問題だけを扱う。Jevを自動採否・配布・マージのゲートにしない。空入力対照に通ることも単独の品質保証にはならない。

## 初回の実行（履歴）

参照した先行実験はCodexタスク `01a0afca-aa6f-7311-916e-146afacaaabb`（Jev導入効果とユースケースを検証）のv7。そこでは必要候補がない場合の誤選択が残っていた。今回も自動修正・次の作業の決定権は与えない。

入力は修正前後の2組、未変更の6 Skills、整理後AGENTS、明確な短文と空入力の2対照、計13件。5観点で計65判定。実ファイルは `b527a3e027eb6edfade71961d72ea02b01913aae`、修正前は `0b8e2f4a7` から取得。モデルには前後ラベル・期待値・独立レビュー結果を渡していない。入力hash、質問、回答、返却されたmodelId、費用を[実行記録](jev-skill-audit-results.json)に保存した。応答IDはSDK結果に含まれず未取得。実行コードでは本文と文書種類だけをstateへ組み立てたが、HTTP送信payloadを別経路では採取していない。

| 対象 | Jevがreviseとした観点 | 原文照合後の扱い |
|---|---|---|
| dev-ops | 固定手順、読み込み範囲、境界 | 当初採用したが、現行入口の再確認後に優先候補から撤回 |
| dev-architect | なし | 見逃し候補。Architecture必須・二段階承認を現行方針と照合する必要がある |
| dev-qa | 境界 | 保留。本番書き込み禁止とTier別範囲があるため、本文だけで越権を確定しない |
| dev-reviewer | なし | 今回は修正根拠を確定しない。レビュー観点の一覧を持つことだけでは過剰としない |
| dev-ship | 固定手順、境界 | 当初採用したが、現行入口の再確認後に優先候補から撤回 |
| tdd-workflow | 固定手順 | 採用。固定モデル・3〜5件のテスト・三段階の実装方法を一律に要求している |
| 整理後AGENTS | なし | 今回の5観点では追加変更しない。managed規約の権限・回数上限は保持 |

上表の理由と行番号は原文レビューで補ったもので、Jevが生成した説明ではない。Jevの出力は観点ごとの選択と確率のみ。独立した原文レビューもモデルによるもので、人間の正解ラベルや実挙動の検証とは異なる。

## 確認した原文

行番号は上記コミット時点。

- [dev-ops](../../.claude/skills/dev-ops/SKILL.md): 38〜55行のTeam作成と順次起動、100行以降の複数職能の詳細。UI工程にはオプション指定があるため、全工程が無条件必須とは扱わない。
- [dev-ship](../../.claude/skills/dev-ship/SKILL.md): 38〜44行のmain固定、80〜90行の自動PATCH、105行の `git add -A`、209〜217行の未コミット変更の自動取り込み。通常のPR作成そのものは問題としていない。
- [tdd-workflow](../../.claude/skills/tdd-workflow/SKILL.md): 113〜170行の固定モデル、199〜225行の件数・実装順序による合否。TDDの失敗確認そのものや再試行回数の上限を削除する根拠ではない。
- [dev-architect](../../.claude/skills/dev-architect/SKILL.md): 31〜35行でArchitectureと二段階承認を必須化。一方、[AGENTS.md](../../AGENTS.md)のVibePro規約はArchitectureを境界変更時に限定している。Jevは相手の文書を見ていないため、この競合を拾えない。

これらのSkill本文の改訂は今回のチェック追加とは分ける。Paperclip/Steel.dev等の実稼働や配布先の現状は未確認。

## 対照と限界

事前に期待を固定した対照は次のとおり。結果を見て採点条件を変更していない。

| 対照 | 事前期待 | 実結果 |
|---|---|---|
| 明確な短文Skill | 全観点keep | 一致 |
| 空入力 | 全観点insufficient | 一致 |
| 旧test-strategy | 検証=revise | **不一致。keepとなり見逃し** |
| 修正後test-strategy | 検証=keep | 一致 |

旧test-strategyは3行と15〜33行で固定比率と80%以上のカバレッジを要求していた。本文は41行と短く、長文の切り捨てによる見逃しとは説明できない。実際に見逃した理由は不明。

旧/新版skill-creatorはともに全観点keep。したがって、この試験は前回の整理の有効性をJevが検証したという結果でもない。対照・探索入力が混在する小さな試行であり、65判定を独立65事例として正解率を出さない。

13呼び出しは全て成功。API応答時間の中央値は約0.862秒、`marketCost` 合計は約0.002549ドル、Gateway返却の `cost` 合計は0ドル。0ドルの理由は未確認で、無料で使えるとは結論しない。比較相手の実測がないため、費用削減・時間短縮の効果も未測定。

今回確認したのは「Jevを使った候補抽出が実行でき、原文で確認できる候補を含む」こと。見逃しもあるため、現状維持の確定や実作業の品質保証を任せない。

# Hookの開始失敗で応答が消えず、原因と安全な復旧範囲が分かる

利用者として、監査開始に失敗しても説明を受け取り、原因調査と修正を任せたい。
未監査を成功扱いせず、Brainbaseだけで確認してから全体反映を判断したい。

## 受け入れ条件

- 開始失敗の段階・安全な原因コード・所要時間をepisode保存とは独立して残す。本文・秘密値は記録しない。
- 明示的な試験モードでのみ説明応答を継続できる。未解決の契約を操作許可に変えない。
- 実エントリーポイントで通信失敗・異常応答・保存失敗を再現し、無言終了を回帰検出する。
- 孤立したStopの案内から、新規taskやHook再承認が必ず必要/不要という未確認の断定を除く。
- グローバル設定と共有runtimeを変更しない。実機で開始から回答まで確認できるまでは未検証とする。

## 作業分担

エージェント: 隔離再現、修正、テスト、Brainbase限定反映準備、実行結果の照合。
利用者: Codexが要求する信頼・有効化のUI操作と、全体反映の最終判断。

# Story: 正本タスクを取消・復元できるようにする

## 利用者価値

組織版の利用者として、誤って仕事の記録を失わずにタスクを整理し、必要になったら元の内容を保ったまま復元したい。

## 方式

`SIMPLIFICATION`を選ぶ。既存のCanonical Task状態遷移、楽観ロック、冪等実行、監査を再利用し、別の論理削除テーブルは作らない。

## 受け入れ条件

- `CANCRUD-AC-001`: `cancelled`を正本タスクの状態として保存・取得できる。
- `CANCRUD-AC-002`: 未着手・進行中・待機中から取消へ遷移でき、取消から未着手へ復元できる。
- `CANCRUD-AC-003`: 取消・復元にも`expected_version`、冪等キー、権限、監査の既存契約を適用する。
- `CANCRUD-AC-004`: 取消時は待機理由、確認日時、完了日時を残さず、タイトル、説明、担当、期限、プロジェクト、作成日時は保持する。
- `CANCRUD-AC-005`: PostgreSQL正本と移行互換NocoDBの両方で状態を同じ意味へ正規化する。
- `CANCRUD-AC-006`: 既存データベースへ再適用できるSQLで状態制約を更新し、物理削除APIは変更しない。

## 対象外

- 物理削除のUI公開
- 完了済みタスクからの取消・復元
- 新しいストレージや別の削除監査経路

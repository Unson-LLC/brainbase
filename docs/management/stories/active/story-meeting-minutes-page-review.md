## 予定 id の調査結果（2026-10-16）

会議・議事録の記録には、予定（Google カレンダー）の id が無い。本番を本人の権限で読み取りだけで照合した。

- 議事録の正本（`/api/meeting-minutes`）の会議の `metadata` は、`organization_id`・`project_code`・`project_id`・`run_id`・`schema_version`・`tenant_id`・`title` だけ。`calendar_event` や `calendar_start` は無い。`ui/meeting-minutes.js` はこれらの項目を読むが、本番の会議には入っていない。
- 会議の取り込み元（組織版の `personal_meeting_sources`）と公開（`personal_meeting_minutes_publications`）の表にも、予定 id の列は無い。会議の表には `started_at` と `meeting_url` がある。
- 予定の側も、議事録を指す記録を持たない。予定と議事録の結び付けは Graph の `calendar_event_minute` 関係だけで、保存時の権限確認は知識の項目の id しか受け付けない。そのため、議事録の正本の `meeting_…` は保存できない。
- 例として、10/15 20:00 の「八雲会」の予定（`project_codes: ["yakumo-meetup"]`）と、同じ `yakumo-meetup` に 20:05 開始で公開された議事録は、どこでも結ばれていなかった。

暫定として、組織版の Unson-LLC/brainbase-organization#540 で、予定の詳細に「この予定の時間に開かれた会議」を出した。予定の関連プロジェクトの議事録から、予定の開始 30 分前から終了までに始まった会議を、時刻の照合結果として出す。保存はしない。押すと議事録ページでその会議が選ばれた状態で開く。受け入れ条件 10 の［議事録を開く］の行き先と、条件 11 の「候補」に当たる。ただし予定の印と［この予定につなぐ］は、結ぶ記録ができるまで出さない。

受け入れ条件 9〜11 を満たすには、次のどれかで結ぶ記録を作る必要がある。どれにするかは未決。

1. 会議を議事録として公開するとき、同じ時間の予定を候補に出し、選ばれた予定の id を会議に残す。
2. 予定から議事録の正本の id を結べるよう、保存時の権限確認を議事録の正本に対応させる。
3. 会議の `meeting_url` と予定の会議 URL（Google Meet など）が一致するものを結ぶ。一致するかは未検証。

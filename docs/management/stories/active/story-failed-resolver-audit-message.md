# 判断失敗の監査出力を保持し返信の再試行を続行する

Manaに個人KG検索を依頼する利用者として、最初の判断呼び出しが失敗しても、その失敗記録を失わず、成功した再試行の契約に従って検索と返信を続行してほしい。

本番の本人DMでは、初回Resolver失敗のイベントは保存されたが、表示行と監査メッセージがともに空だった。Remote HTTPは空の監査出力を503にする。終了前の履歴再処理でもこの保存済みイベントを返すため、返信と最終監査の完了を妨げる。

## 受け入れ条件

- 契約を持たないResolver失敗を固定文で監査し、HTTP境界から非空の出力を返す。
- 同じ失敗を再処理してもイベントを重複させず、失敗を成功として扱わない。
- 成功した再試行の契約、ownerとturnの検証、未実施の検索を区別する条件を維持する。
- 生のエラーや入力を表示・保存する範囲を増やさない。
- 空出力に対するHTTP拒否を維持する。個人KG実検索・返信・最終監査は本番DMで別途確認する。

出荷検査中にWSL実行機がDockerのバージョン照会で停止したため、Graph書き込み契約だけをGitHub管理の実行機へ移す。専用端末・私設ネットワーク・本番データへの依存はなく、同じ検査の完了を受け入れ条件とする。

# 既存の仕事の基盤を確認し、接続先を管理できる

- Story ID: `story-brainbase-outcome-foundation-context`
- 状態: 完了（VibePro archived・2026-09-18）
- 利用者: プロジェクト利用者
- 実現したいこと: 既存登録を再入力せず、参照先と使える範囲を把握する
- 成果: 既存登録を再入力せず、参照先と使える範囲を把握することで、本人にしか決められない判断へ集中できる。
- 実装担当領域: brainbase-organization / Brainbase canonical API
- 依存ストーリー: なし
- 位置づけ: [全体計画](../../brainbase-outcome-stories.md)

## 受け入れ条件

- AC-1: Graphの既存Drive・GitHub・Slack参照、責任者、目的をAPI経由で表示し、取得失敗を未登録へ変換しない。値の由来と確認日時を表示する。
- AC-2: 接続先の追加・表示・変更・解除を行い、保存後の再取得で一致を確認する。解除は関連付けだけに作用し、外部データを削除しない。
- AC-3: 登録済み・アクセス確認済み・権限不足・確認失敗を区別し、未確認には理由と再確認操作を出す。接続先を持つだけで知識利用済みと表示しない。

## 共通の受け入れ条件

- UIは合意した知識一覧・入力と確認パネル・質問テスト・委任編集・実行詳細の流れを使う。状態と次の操作を対象の近くに置く。
- キーボード操作、フォーカス、ラベル、長文、空状態、読み込み、再試行、権限不足を扱い、保存失敗で入力を失わない。
- tenant・project・actor境界をサーバーで検証し、unknownを空・ゼロ・成功に置き換えない。
- 実装時に該当ACの正常系と境界・失敗系を検証し、UI→API→正本または実行先のreadbackまで確認する。検証結果と本番外部作用の未実施境界は [Outcome 13 完了記録](../../outcome-13-closeout.md) に記録する。

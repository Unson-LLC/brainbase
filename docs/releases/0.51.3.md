# 0.51.3（npm公開前）

この版は npm 公開前の候補です。公開状態と利用ホストへの配備は別途確認します。

`0.51.2`（`main` / `4a7abf68a`）をベースに、`#1092`（`c8374b248`、Item #165）のみを単独 cherry-pick したパッチリリース候補です。他の `develop` コミットは含みません。

---

## Changes since `0.51.2`

- **Antigravity CLI judgment hook の `PreInvocation` protojson panic 解消（`#1092` / `c8374b248` / Item #165）**:
  - `buildSystemMessageStep()` の戻り値から `metadata.user_markdown` を削除し、Antigravity `hookcaller.go:56` の protojson panic（`type mismatch: cannot convert string to message`）を解消。
  - `systemMessage`（監査サマリ行）と `additionalContext` を欠落させず `systemMessage.systemMessage` へ統合（同一文字列は重複排除）。なお、この変更に伴い `systemMessage` は従来のユーザー表示専用チャネル（`metadata.user_markdown`）ではなくモデル文脈へ統合される意図した仕様変更となります。
- **`PostToolUse` 発火時の未 flush transcript における fail-closed ツール結果回収と隣接ステップ誤回収防止（`#1092` / `c8374b248` / Item #165）**:
  - `transcript.jsonl` 未 flush 時（または `transcript.jsonl` / `logs/` 未作成時）でも、同一許可ディレクトリ配下の `transcript_full.jsonl` および `<conversation>/.system_generated/steps/<stepIdx>/output.txt` から既存の安全境界（`realpath`・no-symlink 検証・Linux `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)`・512 KiB 上限）を通したツール結果回収を可能化。
  - 未 flush 直接回収の候補を厳密に `[stepIdx]` の 1 件のみに限定し、`step_index === stepIdx` が既に transcript 側に非ツール結果（`PLANNER_RESPONSE` 等）や `toolUseId` 不一致として存在する場合は即 `null`（fail-closed）を返すよう厳格化。
  - `readStepOutputFallback()` で候補ファイルが symlink・非通常ファイル・512 KiB 超過・省略バナー等で拒否された場合は次候補へ進まず即 `null` を返し、`findToolEntryInTranscript()` も `toolUseId` 不一致や未タグ隣接ステップ（`stepIdx + 1`）を誤マッチしないよう強化して並列ツール実行時の別ツール生出力誤回収を防止。

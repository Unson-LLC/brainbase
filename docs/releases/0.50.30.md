# 0.50.30（npm公開前 / TypeScript breaking changes included）

この版は npm 公開前の候補です。公開状態と利用ホストへの配備は別途確認します。

`0.50.29`（`912df89b`）に、Track 1（Antigravity CLI 判断フック PR-A `#1077`・本人 JWT ホスト側 project 解決 `#1032`・RFC-002 PR-1 `#1070`）および Track 2（RFC-001 v2.0 `#1061` / `#1062` / `#1069` と前提 `#1045` / `#1047`）をまとめて移植するリリース候補です。

---

## Included changes

### Track 1 — Antigravity judgment hook & RFC-002 PR-1

- **#1077 — Antigravity CLI judgment hook adapter and `antigravity` host support (PR-A)**
  - 新規公開 subpath `@unson/brainbase-mcp/antigravity-judgment-hook` を追加。
  - 新規 CLI コマンド `brainbase judgment:antigravity-hook` および `brainbase judgment:install --target antigravity` を追加（`contracts/brainbase-public-contract.v1.json` へ反映済み）。
  - `remote-judgment-hook-http` / `judgment-execution-outcome` / `judgment-runtime-resolution` / `judgment-project-binding` / `judgment-event-adapter` で `'antigravity'` ホストを受理。
- **#1032 — 本人 JWT のインタラクティブ判断フック向け Host 側 project 解決（UNS-656 案B 第1段、#1077 の前提）**
  - `handleRemoteJudgmentHookRequest` で本人 JWT 認証済み `claude-code` / `antigravity` フックが `projectCode` を省略した場合、Host 提供の `resolveProjectCode`（repository 対応）→ 本人の単一 project の順で解決し、未解決は `judgment_project_unresolved`、対応表検索失敗は HTTP 503 `judgment_project_lookup_failed` で記録を止める。
- **#1070 — RFC-002 PR-1: `judgment-event-adapter` の `project_code` ハードコード解消と outbox `projectCodes` スコーピング整合**
  - `toKnowledgeEventFromJudgmentEpisode` が episode 由来の検証済み `project_code` を伝播するよう修正（省略・空白時は既定 `'brainbase'` または `options.fallbackProjectCode` へフォールバック）。
  - `deliverJudgmentKnowledgeEventOutbox` で `options.allowedProjectCodes` によるスコープ判定（`out_of_scope` は未送信・リトライ非消費・DLQ 非送出で `deferred` 保持）を追加。

### Track 2 — RFC-001 v2.0 reasoning quality substrate

- **#1045 — Optional evidence balance, scope metrics, and retrieval population counts（#1047 の前提）**

  - 新規公開 subpath `@unson/brainbase-mcp/judgment-reasoning-audit` を追加。
- **#1061 — RFC-001 PR-A: Live reasoning gate v3.1 (default off)**
  - `judgment-host` と CLI に既定 `off` の 4-block 推論ゲート（`reasoningGateMode` / `reasoningGateCanaryProjects`）を追加。既定では一切注入しない。
- **#1062 — RFC-001 PR-B: Session mini world model v2 and non-digest telemetry**
  - セッション内ミニ世界モデル v2（`src/judgment-session-world-model.ts`）と、フック応答・digest に影響しない非 digest テレメトリコールバック（`onReasoningGateTelemetry`）を追加。
- **#1069 — RFC-001 PR-C: Offline 7-item binary audit gate, PoLL 2-of-3 jury, and anonymized fixtures**
  - オフライン評価専用の 7 項目二値監査（`src/judgment-offline-binary-audit.ts`）、PoLL 2-of-3 審査集約、匿名化ゴールデンフィクスチャを追加し、`@unson/brainbase-mcp/judgment-reasoning-audit` から再エクスポート。ライブ会話フックへは接続しない。

## Breaking TypeScript changes (from `unreleased-judgment-event-project-code.md` & `unreleased-antigravity-judgment-hook.md`)

### 1. `JudgmentKnowledgeEvent['applicability_scope']['project_code']` widened from `'brainbase'` to `string` (#1070)

| Kind | Name | Note |
|---|---|---|
| type | `JudgmentKnowledgeEvent['applicability_scope']['project_code']` from `@unson/brainbase-mcp/judgment-event-adapter` | Widened from literal `'brainbase'` to `string`. Also widens the event shape returned by `toKnowledgeEventFromJudgmentEpisode` and referenced by `@unson/brainbase-mcp/judgment-event-outbox` (`JudgmentOutboxDeliveryPort`, `JudgmentQueuedEvent`, `enqueueJudgmentKnowledgeEvent`, `JudgmentKnowledgeEventSink`). |
| function | `toKnowledgeEventFromJudgmentEpisode` from `@unson/brainbase-mcp/judgment-event-adapter` | Propagates a validated `project_code` from the episode (`episode.project_code`, `applicability_scope.project_code`, `payload.project_code`, `adoption.request.project_code`, `adoption.receipt.project_code`) instead of hardcoding `'brainbase'`. Non-empty values that fail `JUDGMENT_EVENT_PROJECT_CODE_PATTERN` throw `Error('project_code is invalid')`. Omitted or blank values still fall back to `DEFAULT_JUDGMENT_EVENT_PROJECT_CODE` (`'brainbase'`) or `options.fallbackProjectCode`. |
| function | `deliverJudgmentKnowledgeEventOutbox` from `@unson/brainbase-mcp/judgment-event-outbox` | Extracts the effective `project_code` from `applicability_scope.project_code` before top-level `project_code` (matching downstream `requireProjectAccess`). When `options.allowedProjectCodes` is provided, events with missing, conflicting, invalid, or out-of-scope `project_code` are deferred (`deferred`, `out_of_scope`) without posting, consuming retry attempts, or dead-lettering. |

#### Why this is a breaking TypeScript change

TypeScript consumers that assign `event.applicability_scope.project_code` to the literal type `'brainbase'` will no longer compile under `--strict`:

```ts
import type { JudgmentKnowledgeEvent } from '@unson/brainbase-mcp/judgment-event-adapter';
declare const event: JudgmentKnowledgeEvent;
const projectCode: 'brainbase' = event.applicability_scope.project_code; // TS2322
```

#### Migration

1. Replace literal `'brainbase'` type annotations on `JudgmentKnowledgeEvent['applicability_scope']['project_code']` with `string`.
2. If a caller only accepts `'brainbase'` (or a fixed token allowlist), narrow at runtime with `event.applicability_scope.project_code === 'brainbase'` or `isProjectCodeAllowed(event.applicability_scope.project_code, allowedProjectCodes)`, or pass `allowedProjectCodes` to `toKnowledgeEventFromJudgmentEpisode` / `deliverJudgmentKnowledgeEventOutbox`.

### 2. Antigravity judgment host support (`'antigravity'`) added to host union types (#1077)

| Kind | Name | Note |
|---|---|---|
| type | `RemoteJudgmentHookHost` from `@unson/brainbase-mcp/remote-judgment-hook-http` | Widened from `'remote' \| 'claude-code'` to `'remote' \| 'claude-code' \| 'antigravity'`. `handleRemoteJudgmentHookRequest` now accepts `x-brainbase-judgment-host: antigravity` under the same owner-local-bridge or person-authenticated JWT boundaries as `claude-code`, including `PreToolUse` and hosted Stop journal publishing. |
| type | `JudgmentExecutionHostType` from `@unson/brainbase-mcp/judgment-execution-outcome` | Widened from `'codex' \| 'claude-code'` to `'codex' \| 'claude-code' \| 'antigravity'`. `normalizeJudgmentExecutionOutcome` and `EXECUTION_OUTCOME_HOSTS` accept `'antigravity'`. |
| type | `JudgmentRuntimeRuntimeContext['host']` and `JudgmentRuntimeRuntimeContext['entrypoint']` from `@unson/brainbase-mcp/judgment-runtime-resolution` | Widened `host` from `'codex' \| 'claude-code'` to `'codex' \| 'claude-code' \| 'antigravity'` and `entrypoint` from `'codex' \| 'claude_code' \| 'mana' \| 'company_os' \| 'unknown'` to include `'antigravity'`. |
| function | `selectJudgmentProjectBinding` from `@unson/brainbase-mcp/judgment-project-binding` | Honors explicit `configuredProjectCode` ahead of `relayProjectCode` for `hostRuntime === 'antigravity'` (matching `'claude-code'`). |
| function | `toKnowledgeEventFromJudgmentEpisode` from `@unson/brainbase-mcp/judgment-event-adapter` | Emits `source.type: 'agent_judgment'` for `outcome.host.type === 'antigravity'` (matching `'claude-code'`). |

#### Why this is a breaking TypeScript change

TypeScript consumers that perform exhaustive checks on `RemoteJudgmentHookHost`, `JudgmentExecutionHostType`, `JudgmentRuntimeRuntimeContext['host']`, or `JudgmentRuntimeRuntimeContext['entrypoint']`, or that assign those properties to narrower literal unions, will fail to compile under `--strict` until `'antigravity'` is handled:

```ts
import type { RemoteJudgmentHookHost } from '@unson/brainbase-mcp/remote-judgment-hook-http';
declare const host: RemoteJudgmentHookHost;
const narrow: 'remote' | 'claude-code' = host; // TS2322
```

#### Migration

1. Update exhaustive `switch` statements or literal union annotations on `RemoteJudgmentHookHost`, `JudgmentExecutionHostType`, `JudgmentRuntimeRuntimeContext['host']`, and `JudgmentRuntimeRuntimeContext['entrypoint']` to include `'antigravity'`.
2. In downstream Host wrappers that branch on `options.host === 'claude-code'` or `runtime.entrypoint === 'claude_code'`, handle `'antigravity'` explicitly instead of falling back to `'codex'` or `'unknown'`.

## Runtime compatibility

- Existing `'remote'` and `'codex'` callers, `'claude-code'` callers that pass an explicit `projectCode` or run on the owner local bridge, and existing CLI flags keep their previous runtime behavior.
- **Antigravity CLI 判断フックの対応プラットフォーム範囲（Linux 5.6+・対応アーキテクチャ限定）**: Antigravity CLI 判断フックの `transcriptPath` 読み取り（`last_assistant_message` / 非システム `USER_INPUT` 補完）は、カーネル強制のルート境界・シンボリックリンク禁止保証のため **Linux 5.6+（`openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)`・対応アーキテクチャ `platform.machine()` 許可リスト: `x86_64` / `amd64` / `aarch64` / `arm64` / `i386` / `i686` / `armv7l` / `armv6l` / `riscv64` / `s390x` / `ppc64le` / `ppc64` / `loongarch64`・`/proc/self/fd`・固定パス `python3`）および OS `flock` 環境** を対象とします。macOS / Windows や未対応アーキテクチャ等の非対応環境（または `openat2` が制限されたコンテナ環境）では、フォールバックを行わず安全側（fail-closed）で transcript 読み取りを拒否（空扱い）し、フック本体は fail-open 応答（`{}` / `{"decision":""}`）を維持します。
- **Behavioral change for person-JWT `'claude-code'` callers omitting `projectCode` (#1032)**: Previously, `handleRemoteJudgmentHookRequest` rejected omitted or empty `projectCode` with HTTP 400 `invalid_project_code`. In `0.50.30`, the Host automatically resolves `projectCode` via `resolveProjectCode` (repository mapping) or the person's single authorized project; when multiple projects remain unresolved it returns HTTP 400 `judgment_project_unresolved`, and when repository lookup fails it returns HTTP 503 `judgment_project_lookup_failed`.
- Live reasoning gate defaults to `'off'`; no prompt injection occurs unless explicitly opted in.
- Episodes omitting `project_code` (or leaving it blank) continue to emit `applicability_scope.project_code: 'brainbase'`.
- Unknown `x-brainbase-judgment-host` values continue to be rejected with HTTP 400 `judgment_hook_host_unsupported`.
- Existing authentication, authorization, and MCP tool contracts remain unchanged.

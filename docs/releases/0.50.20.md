# 0.50.20（npm公開前）

この版はnpm公開前の候補です。公開状態と利用ホストへの配備は別途確認します。

判断の履歴の絞り込み（検索・期間・プロジェクト・判断したAI）を、小窓に入れずに一覧の直上へ常に並べます（#963）。仕事ページと同じ並べ方です。開く操作がいらなくなり、いまどの条件で見ているかが一目で分かります。

件数行を「取得済み N件 · 条件一致 M件 · 表示 1–M件 · 総数 T件」の形にそろえます。全件数が分からないときは、総数を「未確認」と出します。0件と言い切れないときの文言は変えません。絞り込みの欄で入力中に画面が描き直されても、選んでいた欄から外れません。

プロジェクトと判断したAIの選択はnormalモードだけに出します。legacyモードは期間と検索の手元の集計のままです。ページ送り、再読み込み、右詳細は変えません。新しい色・書体・影・動きは足さず、既存のトークンを使います。

`memory:list` が壊れた受付記録ファイルで失敗したとき、もう一方の手元の記録の読み込みが終わる前に返していたため、正本のロックが残ることがありました。両方の読み込みが終わるのを待ってから最初の失敗を返すようにします（#1024）。

試験の時間切れを減らすため、試験用の使い捨てデータを置く場所を見直し、CIでの試験の待ち時間を広げます（#1001、#1023）。このうち #1023 は試験だけでなく、配布物の正本の扱いも変えます（`src/ssot.ts`、`src/foundation-store.ts`）。同じプロセスの中で正本ロックを待つ呼び出しは、ロックを繰り返し確かめる代わりに来た順に並んで待ちます。待ち時間の上限（既定5秒、`BRAINBASE_SSOT_LOCK_TIMEOUT_MS`）は、この順番待ちとロックの取得を合わせた時間に掛かります。正本ファイル（`graph.json`・`relationships.json`・`personal-kg.jsonl`・`decisions.jsonl`）と `sources/` の件数は同時に読みます。壊れたファイルが複数あるときは、これまでと同じ順で最初のファイルを名指しします。目的と評価基準の記録を読むとき、同じ検証を2回していたのを1回にします。

公開API、MCPツール、認証・権限の契約は変更しません。0.50.19に含まれる変更を保持します。

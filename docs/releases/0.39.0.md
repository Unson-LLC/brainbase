# 0.39.0

## 追加

訂正 `POST /api/graph/corrections` に `create_entity` を追加します（`story-people-and-companies-write-v1`）。入力は `{ kind: 'create_entity', reason, entity: { type, name, aliases?, summary?, validFrom? } }` です。作れるのは `person` と `org` だけで、ほかの種類は `correction_entity_type_not_allowed` で断ります。理由と履歴の1行を同じトランザクションで残し、保存後に正本から読み戻して確かめます。作った記録の出どころは `metadata.source`（`user_approved`）と `metadata.sourceId`（訂正ID）に残ります。同じ種類で名前か別名が同じ記録があるときは作らず、`entity_already_exists`（409）で今の記録を返します。

共通部品 `ui/people-and-companies-view` に `canCorrect`・`correctionScope`・`token`・`tokenHeader` を追加します。`canCorrect: true` のときだけ「人を加える」「会社を加える」「所属を付ける」「所属する人を加える」「所属を終える」を出します。既定は読み取りのみで、今までの組み込みは変わりません。所属を付けるのは `create_edge`（`member_of`）、終えるのは `update_edge` の終了日で、消す操作はありません。保存後は一覧と右の欄を読み直します。`correctionScope` の `createEntities: false`・`createEdges: false`・`edges: false` で、それぞれのボタンを出さずに断ります。部品の中に役割名はありません。Personal Web は「人と会社」を書ける画面として開きます。

`GET /api/graph/people-and-companies` は、人ごとに文字の属性 `org`（無ければ `organization`）を `orgNote` として返します。所属・自社・社内社外の判定には使いません。画面は所属未確認の人にだけ「記録上のメモ: …（所属ではありません）」として出します。

関係の定義に `related_to`（会社→プロジェクト、役割は関係の `role`）を追加します（`story-people-and-companies-read-v1`）。訂正で新しく張れる関係には含みません。「人と会社」の読み取りは、会社ごとに `related_to` で関わるプロジェクトと役割（`relatedProjects`）、記録どおりの `orgType`・`lifecycleStage`・`deals`、記録だけから導いた種類（`kinds`：顧客・協業先・提案中と出どころ）を返します。記録が無い会社には種類を出しません。

## 変更

保守の計画（`graph-maintenance-engine` の `upsert_edge`）で、同じ組織の人→会社の所属（`member_of`）を、プロジェクトが違っても張れるようにします（`story-people-and-companies-write-v1` AC-10）。両端が有効で、それぞれが計画の写しの中にあるか同じ組織の参照（`reference_scope: same_organization`）のときだけ通します。関係は、会社が写しの中にあれば会社のプロジェクトに、無ければ人のプロジェクトに置きます。別の組織の参照、終わった記録、人以外・会社以外・`member_of` 以外は今までどおり断ります。

画面「人と会社」の会社の一覧に種類の列を足し、自社、種類のある会社、その他の順に並べます。会社を開くと、関わるプロジェクトを「この会社のプロジェクト」（`owned_by`）と「顧客・協業先として関わるプロジェクト」（`related_to`、役割つき）に分けて出します。

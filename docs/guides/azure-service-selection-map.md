## 選定の順序

1. 利用者、負荷、データ、可用性、復旧、法令、予算を要求化する。
2. テナント、管理グループ、サブスクリプション、リソースグループの境界と責任者を決める。
3. リージョンと可用性ゾーンを、データ所在と障害分離から選ぶ。
4. 仮想マシン、Webアプリ基盤、コンテナ、Functions等を実行特性で比較する。
5. オブジェクト、ファイル、キュー、表、RDB、NoSQLをアクセスパターンから選ぶ。
6. ID、RBAC、秘密、ネットワーク、暗号化、ポリシーを横断設計する。
7. IaC、監視、予算、バックアップ、復元、廃止手順を整える。

## 代表領域と判断軸

| 領域 | 代表的な選択肢 | 判断軸 |
|---|---|---|
| 仮想マシン | Azure Virtual Machines、Scale Sets | OS制御、常駐処理、既存資産、運用責任 |
| Webアプリ | App Service | ランタイム、デプロイ、スケール、制約 |
| イベント実行 | Functions、Logic Apps | 実行時間、トリガー、状態、連携、上限 |
| オブジェクト／ファイル | Blob Storage、Azure Files | アクセス方式、階層、保持、共有 |
| リレーショナルDB | Azure SQL等 | 互換性、可用性、性能、管理範囲 |
| NoSQL | Cosmos DB等 | データモデル、分散、整合性、容量変動 |
| AI・データ・IoT | Azureの現行マネージドサービス | データ統制、モデル責任、遅延、費用、ロックイン |

## ガバナンスと運用

- 人とワークロードのIDを分け、RBACを最小権限にする。
- サブスクリプションとリソースグループを単なるフォルダーではなく、課金・権限・ライフサイクルの境界として扱う。
- Policy、タグ、予算、監査ログで逸脱を検知できるようにする。
- Monitor等のログ、メトリクス、アラートを、対応者と手順へ接続する。
- バックアップの成功ではなく、必要なRTO・RPOで復元できることを試験する。
- マネージド化で減る責任と、制約、固有化、費用を比較する。

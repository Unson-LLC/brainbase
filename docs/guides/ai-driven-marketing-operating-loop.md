## 運用ループ

```text
事業目的と顧客課題
  → 出典・権利を管理したデータ
  → AIによる分析・仮説・生成
  → 人とポリシーによる検証
  → 範囲を限定した施策実験
  → 事業成果と副作用の測定
  → 学び・失敗・判断をナレッジへ更新
  → 次の仮説
```

AIへの入力と生成物だけでループを閉じない。顧客行動、売上、継続、ブランド、安全性など、外部の結果に接続して初めて「AI駆動」とみなす。

## 成熟度

| 段階 | 状態 | 次の課題 |
|---|---|---|
| 0 | 利用なし | 安全な小規模用途を選ぶ |
| 1 | 個人の作業補助 | プロンプト、出典、レビューを標準化する |
| 2 | チームの定型ワークフロー | 入出力と成果指標を接続する |
| 3 | 承認済みデータ・RAGとの連携 | 更新、権限、評価セットを運用する |
| 4 | 権限を限定したエージェント | 観測、停止、承認、監査を組み込む |
| 5 | 成果に基づく継続最適化 | 局所指標への過適合と副作用を監視する |

## 施策の設計手順

1. 「誰の、どの行動・成果を、いつまでに変えるか」を定義する。
2. 調査、企画、制作、配信、分析のどこがボトルネックかを測る。
3. AIの役割を、探索、要約、分類、予測、生成、実行のいずれかに限定する。
4. 入力データの出典、同意、個人情報、著作権、鮮度を確認する。
5. 生成物の事実、推測、提案を分離し、ブランド・法務・数値根拠を検証する。
6. 対象、予算、期間、停止条件を限定して比較実験する。
7. 作業量だけでなく、商談、購入、継続、顧客満足、苦情などの結果を測る。
8. 採否、理由、結果、失敗例を保存し、次回の評価と検索へ戻す。

## ガードレール

- 顧客データは目的、権限、保持期間を定め、必要最小限だけ渡す。
- 数値、引用、競合情報には出典を付け、裏付けのない表現を公開しない。
- 広告費、外部公開、個人への高影響な判断は、権限と承認段階を明示する。
- 自動化には予算上限、レート上限、対象範囲、停止スイッチ、監査ログを置く。
- パーソナライズを、脆弱性の悪用、誤認、過度な追跡へ変質させない。
- モデル評価と施策評価を分ける。文章品質が高くても事業成果や顧客利益を損なう場合がある。

## Brainbaseでの適用

Graphには顧客課題、キャンペーン、責任主体、KPI、主要な判断を置き、原データや長文の成果物は所有システムへ残す。各生成物に入力出典、モデル・手順、レビュー者、公開可否、結果を結びつける。AIの提案は観察・解釈・決定のどれかを明示し、採用されていない提案を組織方針として扱わない。

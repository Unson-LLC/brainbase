# 基盤モデルとロボットの融合 — 統合設計ガイド

**本質**: 基盤モデルをロボット全体の代替物として扱わず、知覚・意味理解・計画・制御のどこへ接続し、どこを決定論的な安全機構として残すかを設計する。

> 本ガイドは書籍から抽出した、長期利用しやすい設計原則である。個別モデルの性能、API、推論速度、対応モダリティは変化するため、採用時点の公式文書と実機評価で再確認する。物理安全の保証をモデル出力へ委ねない。

## 統合レイヤー

```text
センサー入力
  → 低レベル知覚: 検出・追跡・状態推定
  → 高レベル知覚: 場面・物体・意図の意味理解
  → 高レベル計画: 目的分解・技能選択・手順生成
  → 低レベル計画と制御: 軌道・周期制御・安全制約
  → アクチュエータ
```

基盤モデルの適用候補は各層で異なる。意味理解や目的分解で有効でも、同じモデルがリアルタイム制御や停止保証に適するとは限らない。モデル能力とロボットシステム全体の保証を分けて評価する。

## 導入手順

1. タスク、環境、人との接触、許容損失、停止条件を定義する。
2. 現行パイプラインを知覚・計画・制御へ分け、失敗率や開発負荷が高い箇所を特定する。
3. 基盤モデルへ渡す観測、期待する出力、時間制約、信頼度の扱いを契約化する。
4. オフラインデータで精度、未知入力、再現性、遅延、費用を測る。
5. シミュレーション、隔離された実機環境、制限付き運用の順で検証する。
6. ルールベースの安全制約、タイムアウト、フォールバック、人の介入経路をモデル外に置く。
7. 入力、モデル版、出力、採否、結果を記録し、失敗データを評価セットへ戻す。

## データと適応

- 事前学習データとロボット固有データの範囲、権利、偏りを記録する。
- 実世界、シミュレーション、合成データを区別し、実機への転移差を測る。
- プロンプト、検索、追加学習、模倣学習などの適応方法を、再現性と更新費用で選ぶ。
- 身体、センサー、技能粒度が変わったときに流用できる範囲を明示する。
- 成功例だけでなく、失敗、介入、ニアミスを保存する。

## レビューの問い

- モデルが誤認・幻覚・沈黙した場合、安全側へ移れるか。
- 推論時間の上限を超えた場合、制御系が独立して継続または停止できるか。
- 未知環境を検知し、既知であるかのような行動を防げるか。
- 高レベルの意味表現と、座標・単位・時間同期が正しく接続されているか。
- オフライン指標、シミュレーション結果、実機安全性を混同していないか。
- モデルやデータの更新後に回帰試験できるか。

## Brainbaseでの適用

Graphにはプロジェクト、ロボット、モデル、データセット、責任主体、重要な採用判断を置く。評価セット、システム境界、失敗モード、ロールバック手順はチーム文書と実装リポジトリに残す。モデルの出力を観察事実として保存し、人が採用した判断や実機結果とは分離する。

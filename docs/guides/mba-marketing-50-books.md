## 実行フロー

```text
観察された事業課題
  → どの領域の問題か分類
  → 対立する理論や前提も含めて候補を選ぶ
  → 現場データで適用条件を確認
  → STP・価値・4P・体験・販売の矛盾を除く
  → 一つの主要仮説を小さく実験
  → 結果と適用限界をチーム正本へ戻す
```

## 理論を使う際の注意

- 古典的な集中・差別化と、広い獲得や利用可能性を重視する研究は前提が異なる。宗派を選ぶのではなく、市場、購買頻度、データで判断する。
- 顧客満足を「期待以上のおもてなし」と同一視しない。約束の履行と顧客努力の削減を先に検証する。
- ブランド、価格、広告を独立施策にしない。価格は知覚品質を、体験はブランド連想を、チャネルは購入可能性を変える。
- 成功事例は因果の証明ではない。再現条件と反証可能な指標を置く。
- 理論の要約だけで完了とせず、実験結果から適用範囲を更新する。

## Brainbaseへの適用

相談を受けたら、最初に問題領域と不足データを解決し、関連する既存Skill・ガイドへルーティングする。回答には採用した理論、前提、反対仮説、実験、判定条件を残し、結果が出たら「何が効いたか」だけでなく「どの条件で効いたか」をチームナレッジへ戻す。

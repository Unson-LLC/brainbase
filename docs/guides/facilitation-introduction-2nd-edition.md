## ファシリテーションの役割

ファシリテーターは、自分の結論へ誘導する人ではない。参加者が安心して意見を出し、論点を理解し、対立を扱い、自分たちで納得できる決定と次の行動へ進めるよう、内容ではなくプロセスを支援する。

組織を動かす働きは、方向を示すリーダーシップ、目標達成の仕組みを作るマネジメント、関係性を築き協働を促すファシリテーションに分けて考える。変化が大きく、答えが一つでなく、関係者の知恵が必要な問題ほどファシリテーションが重要になる。

## 4つのスキル

### 1. 場のデザイン — 場をつくり、つなげる

- ゴールと、会議終了時に得たい成果を明らかにする。
- 発散、整理、評価、決定、振り返りのプロセスを設計する。
- 参加者、時間、物理・オンライン環境、役割、ルールを整える。
- 発言しやすい関係性と心理的な安全を作る。

### 2. 対人関係 — 受け止め、引き出す

- 傾聴と応答で発言者の意図と感情を受け止める。
- 沈黙、発言量、表情、力関係など相互作用を観察する。
- 質問によって前提、具体例、理由、未表明の懸念を引き出す。
- 意見同士をつなぎ、少数意見を消さずに発散を広げる。

### 3. 構造化 — かみ合わせ、整理する

- 主張、根拠、論点、事実、解釈を分ける。
- 似た意見を束ね、対立点と合意点を見える形にする。
- 板書や図解で議論の全体像と現在地を共有する。
- フレームワークを結論の押し付けではなく、思考の補助線として使う。

### 4. 合意形成 — まとめて、分かち合う

- 何を、誰が、どの基準と方式で決めるかを先に決める。
- 多数決だけに頼らず、異なる利害と懸念を扱う。
- 対立を人間関係の問題ではなく、論点・価値・制約の違いとして解く。
- 決定事項、保留、反対意見、担当、期限を確認する。
- 最後にプロセスを振り返り、次回の改善へつなげる。

## 会議の標準フロー

1. 目的、成果物、決定権者、制約を事前に定義する。
2. 冒頭で目的、進め方、終了条件、参加ルールを合意する。
3. すぐ評価せず、まず情報と選択肢を十分に発散する。
4. 論点を可視化し、事実・解釈・提案を整理する。
5. 評価基準を合意してから選択肢を収束する。
6. 決め方を確認し、反対・懸念・リスクを扱って決定する。
7. 担当、期限、次の確認点を具体化する。
8. 会議プロセス自体を短く振り返る。

## 介入の判断

| 状態 | 介入 |
|---|---|
| 発言が出ない | 問いを具体化し、個人思考や小グループを挟む |
| 一人が独占する | 発言を要約して区切り、他者へ同じ問いを渡す |
| 議論が拡散する | ゴールと論点一覧へ戻り、今扱う論点を選ぶ |
| 意見が衝突する | 人ではなく、前提・評価基準・利害の違いへ分解する |
| 決まらない | 決定方式、必要情報、決定権者、期限を再確認する |
| 表面上だけ賛成する | 懸念、実行障害、反対条件を明示的に尋ねる |

## アンチパターン

- ファシリテーターが内容面の正解を決め、質問で誘導する。
- 発散前に評価し、声の大きい案だけを残す。
- 意見を記録するだけで、論点構造や違いを整理しない。
- 合意を全員一致と誤解し、反対理由を隠す。
- 決定した気になるが、担当・期限・確認方法がない。
- 会議の失敗を参加者の能力だけに帰し、場とプロセスを改善しない。

## 3つの基幹文書

| 文書 | 役割 |
|---|---|
| 戦略的目標 | 組織がどこへ向かい、何を達成するかを短く定義する |
| 一般運営原則 | 日々の判断を揃える少数の原則を定義する |
| 作業手順 | 個別プロセスを、他者が再実行できる線形手順にする |

上位文書が下位文書を制約する。手順が目標・原則と矛盾する場合、局所効率ではなく体系全体を修正する。

## 改善ループ

1. 問題を人物評価から切り離し、結果を生んだプロセスを特定する。
2. プロセスを開始条件、入力、手順、判断、出力へ分解する。
3. 望ましくない結果の原因を一つ修正する。
4. 誰でも実行できる短い手順へ記録する。
5. ownerと測定値を置き、現場のフィードバックで更新する。
6. 自動化、委任、統合、廃止の順で負荷を減らす。

## アンチパターン

- 緊急対応の速さを改善能力と混同する。
- 文書量を仕組み化の成果にする。
- 一度書いた手順を固定し、現実との乖離を放置する。
- すべてを同じ詳細度で文書化する。
- 失敗を個人の注意不足だけで終わらせる。

## 既存Skillとの関係

`.claude/skills/work-the-system/SKILL.md`は本書と同じ主要概念を持つ。本ファイルを出典・抽出証拠を持つチーム知識の正本、Skillを実行時の圧縮ビューとして扱い、今後の改訂では本ファイルへの来歴リンクを維持する。

## Brainbaseへの適用

失敗を「Agentが賢くなかった」で閉じず、探索、判断、実行、検証、正本反映のどのプロセスが欠けたかへ分解する。三回同じ境界で止まったら、再試行よりシステム修正を優先する。

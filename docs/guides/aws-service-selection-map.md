## 選定の順序

1. 利用者、負荷、データ、可用性、復旧、法令、予算を要求化する。
2. アカウントとOrganizationsの境界、責任者、課金単位を決める。
3. リージョンとAvailability Zoneによる障害分離を設計する。
4. 実行、ネットワーク、保存、データベース、配信を要求別に選ぶ。
5. IAM、暗号化、秘密、監査、バックアップを横断設計する。
6. 小規模な検証で性能、障害時挙動、運用負荷、費用を測る。
7. IaC、監視、予算上限、復旧・廃止手順を整える。

## 代表領域と判断軸

| 領域 | 代表的な選択肢 | 判断軸 |
|---|---|---|
| 仮想マシン | EC2 | OS制御、常駐処理、既存資産、運用責任 |
| コンテナ | ECS、EKS、Fargate | オーケストレーション、移植性、チーム能力 |
| サーバーレス | Lambda等 | イベント、実行時間、状態、同時実行、制約 |
| オブジェクト | S3 | 耐久性、アクセス頻度、保持、ライフサイクル |
| リレーショナルDB | RDS、Aurora | エンジン互換性、可用性、性能、管理範囲 |
| NoSQL | DynamoDB等 | アクセスパターン、整合性、容量変動 |
| 配信 | ELB、Route 53、CloudFront | 到達性、負荷分散、DNS、遅延、保護 |

## 安全性と運用

- Root利用を避け、IAMを人・ワークロード別の最小権限にする。
- Public／Private subnet、Security Group、ルート、外部入口を図示する。
- 複数AZ、バックアップ、復元試験を、必要なRTO・RPOへ結びつける。
- CloudTrail等の監査、ログ、メトリクス、アラームを障害前から有効にする。
- 自動スケールに上限を置き、データ転送、ログ、NAT等も含めて費用を測る。
- マネージド化で減る責任と、制約、固有化、費用を比較する。

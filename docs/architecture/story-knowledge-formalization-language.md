# 知識の資産化における用語境界

## 決定

`promotion`（知識昇格）は、候補を再利用可能な組織資産へ移す内部の包括概念としてだけ使う。利用者向けには、遷移元と遷移先に応じて次の具体語を使う。

| 遷移 | 利用者向けの呼び方 | 正本 |
| --- | --- | --- |
| 会話・観測 → Candidate Store | 候補として記録する | Candidate Store |
| 候補 → 承認済み候補 | 正式登録を承認する | Candidate Storeと監査履歴 |
| 承認済み候補 → 組織の事実・Decision・RACI | Graphへ正式登録する | Graph SSOT |
| 候補 → 方針・仕様・runbook | 方針文書へ反映する | 所有Git repo、または所有team Drive |
| 候補 → 発火条件・手順・チェックリスト | 再利用できる手順にする | 所有repoのSkill |
| 個人・Placement限定の知識 → より広いscope | 他チームにも共有する | 同じ正本のACL／scope |
| 助言的なルール → 実行時の必須条件 | 必須チェックにする | DAG、Gate、Policy-as-code |

## 別工程として扱うもの

- 検証は、資産化してよいかを判断する前提条件であり、知識昇格そのものではない。
- ファイル保存は、決めた正本へ内容を具体化する処理であり、承認と同義ではない。
- デプロイは、コードや設定を実行環境へ配る処理であり、知識昇格と同義ではない。

したがって、`approved` は「登録してよいという判断」であり、`promoted_to_graph`、Skillファイル更新、Driveファイル作成、または本番反映の完了を意味しない。

## 互換性

内部では既存の `promotion_status`、`promoted_to_graph`、`/promote-to-graph` を維持する。監査や他repoとの契約を壊さず、表示層で具体語へ変換する。

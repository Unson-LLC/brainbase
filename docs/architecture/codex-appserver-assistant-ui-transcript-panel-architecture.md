# ADR: Codex App Server assistant-ui transcript panel

## Context

The first Codex App Server transcript slice created a structured server ledger, transcript API, browser panel, and xterm fallback. The visible UI still looked like a minimal debug surface. Replacing the whole Brainbase shell with React would be too large for this slice, but the transcript panel is a suitable isolated assistant conversation surface.

## Decision

Mount a React island under `#codex-app-server-display-panel` and render the transcript with assistant-ui's native React UI package:

- `AssistantRuntimeProvider` and `useExternalStoreRuntime` adapt Brainbase transcript snapshots into assistant-ui thread state.
- `Thread` from `@assistant-ui/react-ui` renders the scrollable timeline and composer using the OSS component defaults.
- `makeMarkdownText` supplies assistant-ui markdown rendering without Brainbase-owned markdown parsing.
- Brainbase remains the owner of App Server session selection, transcript polling, turn submission, fallback routing, and auth-aware `httpClient` calls.

## Boundaries

- Browser shell: `public/modules/app/codex-app-server-display-mixin.js` chooses App Server transcript mode and passes API functions into the island.
- Island source: `ui-islands/codex-appserver-transcript/index.jsx` maps Brainbase timeline events to assistant-ui external-store messages and renders Brainbase-specific message rows.
- Browser bundle: `public/dist/codex-appserver-transcript-island.js` is generated by `npm run build:codex-appserver-transcript`.
- Styles: `public/style.css` owns the concrete Brainbase visual treatment.
- Mount guard: if the expected island root or active session id is unavailable, the shell does not mount the island and leaves the existing terminal/fallback surface intact.
- Import resilience: if the browser shell fails to import or mount the island once, it retries the same island with a cache-busted URL before using the fallback renderer. This covers already-open Brainbase pages after a bundle replacement without changing the steady-state bundle URL.
- Message identity: the adapter preserves each ledger event while deriving unique assistant-ui message ids when duplicate ledger ids appear in a snapshot. This keeps Brainbase ledger semantics separate from assistant-ui's message tree identity contract.

## Dependency Policy

`@assistant-ui/react` is a development dependency used to build the committed browser bundle. This avoids adding assistant-ui's cloud/server transitive packages to Brainbase's production Node dependency audit surface while still using assistant-ui for the browser transcript implementation.

- `npm audit --omit=dev`
- `npm run test:e2e -- tests/e2e/story-codex-appserver-assistant-ui-transcript-panel-contract.spec.ts`
- `npm run test:e2e -- tests/e2e/story-codex-appserver-transcript-ui-contract.spec.ts`
- E2E stale failed island import retry with cache-busted second import.
- Visual browser smoke against a Codex App Server session on the Brainbase dev server.

# 知識取得の継続を共通パッケージで提供する

## 所有境界

公開Brainbaseがlookupの入出力検査・取得結果分類と、継続の純粋な状態遷移を所有する。利用側はパッケージのknowledge-lookup / knowledge-continuation exportを固定バージョンで参照する。

モデルは意味、候補の適合、情報の十分性、次の切り口を判断する。coreは実取得の証拠・世代番号・重複・有限予算を検査する。adapterは検索と本文取得、認証、取得本文の公開投影を担う。Hostは永続化とモデル継続の呼出しを担う。

組織専用の認証・接続先・常駐プロセスを公開coreへ持ち込まない。特定のhosted Graphを必須にせず、adapterなしにネットワーク取得しない。機密項目を消した公開本文だけをadapterから受け取り、lookup側でも許可されたフィールドに絞る。

## 移行と切り戻し

利用側の新規共通実装を本repoへ移し、既存adapterから消費する。既存MCPの互換性は保持し、新機能のHost有効化は利用側の設定で段階導入する。問題があれば利用側のフラグを無効化して以前の固定バージョンへ戻す。既存の未確認状態を取得成功へ書き換えない。

## 証拠の限界

パッケージの単体試験は実Hostでのモデル再計画や本番有効化を証明しない。利用側は検索失敗から本文・出典取得までの接続を検証する。Graphifyを実装後に更新し、両ファイルの一致を確認した。結果はpartialで、影響範囲の網羅性は未確認のまま扱う。

# ADR: Codex App Server ChatGPT-like assistant-ui polish

## Context

The first assistant-ui slice mounted a React island and connected Brainbase's App Server transcript and turn APIs to assistant-ui runtime/thread/composer primitives. It proved the integration, but the visible experience still reads closer to a styled debug log than a production assistant conversation. The next slice should deepen the assistant-ui usage and improve the interaction polish without changing server ownership or terminal fallback behavior.

## Decision

Keep the existing React island boundary and upgrade the island into a richer assistant thread:

- Continue using `AssistantRuntimeProvider` and `useExternalStoreRuntime` as the runtime bridge from Brainbase transcript snapshots.
- Render the primary timeline through assistant-ui thread and message primitives, while keeping Brainbase-specific activity event rendering inside message body components.
- Add a small React markdown renderer for safe text, code, links, and lists. The renderer emits React nodes only and does not use HTML injection.
- Treat non-conversation timeline kinds as compact activity rows with a stable icon vocabulary and expandable details.
- Make the composer match common assistant UX: Enter submits, Shift+Enter inserts a newline, the send action is explicit, and the send path still calls the existing App Server turn API.

## Boundaries

- Browser shell: `public/modules/app/codex-app-server-display-mixin.js` remains responsible for display routing, auth-aware API functions, and fallback shell creation.
- Island source: `ui-islands/codex-appserver-transcript/index.jsx` owns assistant-ui runtime mapping, message rendering, markdown/code presentation, activity rows, and composer behavior.
- Styles: `public/style.css` owns Brainbase's concrete dark app treatment and responsive constraints.
- Bundle: `public/dist/codex-appserver-transcript-island.js` is generated by `npm run build:codex-appserver-transcript` and committed for the static shell.
- Capability map: `docs/brainbase-capabilities/capabilities/codex.app-server.yml` lists the polished assistant-ui surface and verification path.

## Non-Decisions

- No App Server protocol or server route changes in this slice.
- No streaming claim. The UI may show sending/running states and poll transcript snapshots, but server-side streaming requires a separate transport story.
- No dependency expansion into production Node dependencies; assistant-ui remains build-time scoped for this browser bundle.

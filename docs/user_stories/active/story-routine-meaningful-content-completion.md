# Story: ルーティンの実完了と内容を一致させる

## 利用者価値

佐藤さんとして、`ohayo`・`oyasumi`・`retro` を実行したとき、処理が通っただけの空の結果ではなく、確認した事実と次に使える内容を受け取りたい。失敗時は、再試行や修正につながる原因を同じ成果物で確認したい。

## 受け入れ条件

- `completed` は、ルーティン固有の主要欄に内容があり、確認範囲も示せる場合だけ返す。
- 主要欄が空なら `partial` と `routine_content_empty` を返し、空の成功にしない。
- `oyasumi` で残件が0件の場合も、何を確認して閉じたかを `closed` に残す。
- `ohayo` のGmail確認は、全アカウントの未読総数と直近7日の要対応候補を分ける。古い未読本文や自動分類メールの全件走査で朝の処理を無期限に止めない。
- 直近7日の要対応候補は全ページ取得し、未読総数は古い未読と自動分類を含む持ち越しとして表示する。どちらかを取得できなければ `partial` のままにする。
- 例外時は安全な `code`、`stage`、`summary` を成果物の anomalies に残す。
- 移行中DBに `graph_edges.lifecycle_status` がなくてもGraph読取りで落ちず、列があるDBでは非active関係を公開しない。
- 既存の認証、権限、Graph、Personal KG、通常PRの境界を変更しない。

# フェーズ3: 最初の価値

ここで、フェーズ1で決めた実際の依頼を試します。情報源の接続やMCP設定を終える前に、登録した文脈だけで役立つかを確かめます。

## 試す

```bash
npm run onboard:demo -- --scenario "次の面談準備を、相手との経緯と私の判断基準を踏まえて整理して"
```

`--scenario` には、自分が本当に依頼したい内容を入れます。

## 確認するもの

AIは次の3点を示します。

1. 実際に試すプロンプト
2. 登録した文脈を使った回答例
3. 今回、説明し直さなくて済んだこと

ユーザーは、回答が自分のプロジェクト、関係者、判断基準を正しく使っているかを確認します。情報が足りなければ、必要な前提だけをフェーズ2へ戻って追加します。

## このフェーズの完了

次の状態になったら、最初の価値を確認できています。

- 一つの現実の依頼に対し、説明のやり直しが減った
- AIが違うプロジェクトや関係者を混ぜていない
- 何が正本にあり、何が不明かを区別している

`ready: true`、Skillsやルーティンの生成、MCP設定のdry-runだけでは、この確認の代わりになりません。

外部の情報がなくても役立つなら、そのまま[フェーズ5: 運用開始](/guide/operations)へ進めます。メールや予定などが必要なら、[フェーズ4: 必要な情報源](/guide/source-onboarding)へ進みます。

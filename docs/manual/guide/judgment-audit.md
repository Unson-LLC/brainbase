# AIの判断参照を確認する

BrainbaseのJudgment Resolver HostをCodexに登録すると、AIが返答を作る前に、今の質問と会話履歴をもとに対応方針を判断します。その結果は、毎回の返答の先頭に短く表示されます。

```text
🧠 Brainbase参照: 直前の「ログイン後の白画面を直して」を参照 → 実装依頼として継続 ✓
```

この1行により、「AIがどの発言を足場にしたか」と「今回をどのような依頼として扱ったか」を、返答本文を読む前に確認できます。

## 表示の見方

```text
🧠 Brainbase参照: 「この仕組みを説明して」を参照 → 質問として回答 ✓
```

- かぎ括弧内は、判断の参照元になった実際のユーザー発言です。
- 矢印の右側は、Judgment Resolverが選んだ対応方針です。
- `直前の`とある場合は、「それでいい」のような追従依頼を、前の発言と結びつけています。
- 長い発言は1行の短文に省略され、tokenやsecretに見える値は伏せられます。

## 参照元を特定できないとき

「それでいい。修正して」の対象を会話から特定できない場合は、解決したように見せません。

```text
⚠️ Brainbase参照: 「それでいい」の対象を特定できず → 確認質問
```

この場合、AIは作業を拒否するのではなく、足りない対象だけを確認します。

## この表示が証明すること

表示が証明するのは、判断に使った会話と対応方針です。次のことまでは証明しません。

- Personal OS、Graph、Driveなどの知識を実際に検索したこと
- ファイル書き込み、送信、公開、デプロイの権限を得たこと
- 依頼された作業そのものが成功したこと

知識の検索が必要な場合は、「Brainbase内検索が必要と判断」と表示します。これは検索が完了したという意味ではありません。

## Codexに登録する

まず、追加されるHook設定をプレビューします。

```bash
brainbase judgment:install --target codex --dry-run
```

表示された `UserPromptSubmit` 設定を確認し、自分の `~/.codex/hooks.json` へBrainbaseの項目だけを統合します。コマンドは `--output` を指定しない限り、既存設定を書き換えません。

登録後は新しいCodexセッションを開き、普通の質問と、それに続く「それでいい。続けて」を入力します。2回とも返答の先頭に `Brainbase参照` が表示され、2回目が直前の内容を参照できていれば導入完了です。

## 運用で確認する項目

- すべての返答の1行目に、実際の発言を含む `Brainbase参照` がある
- 追従依頼が、関係のない古い発言ではなく直前の対象を参照している
- 対象不明時は成功表示ではなく、警告または確認質問になる
- secretやtokenの値が表示されない
- 同じturnのHookが再実行されても、参照表示が変わらない

採用したreceiptと表示行は `~/.brainbase/personal-os/judgment-journal/` にまとめて保存されます。表示が出ない場合は、まず `~/.codex/hooks.json` にBrainbaseの `UserPromptSubmit` Hookがあるかと、登録後に新しいセッションを開いたかを確認してください。

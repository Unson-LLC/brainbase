## 頭のいい自分を、壁打ち相手にも、実行部隊にも。

人間は、目的、判断基準、任せてよい範囲を決める。  
AIは、それらを参照して探索・反証し、許可された範囲の仕事を進める。

Brainbaseが増やすのは、AIの数そのものではありません。あなたの判断が届く範囲です。判断はあなたのまま、AIの探索力・反証力・処理能力を乗せ、考える深さと同時に進められる仕事を増やします。
<!-- brainbase:public-message:end -->

> **判断は、あなたのまま。思考と実行は、並列に。**

## AIを増やすほど、あなたがボトルネックになっていないか

AIを複数使えば、調査、設計、執筆、開発を同時に進められます。ところが実際には、AIを増やすほど次の仕事も増えます。

- それぞれのAIへ、目的や背景を説明する
- 何を優先し、何を避けるかを伝える
- 一般論へ戻った成果物を、自分の方針へ直す
- AIごとに違う結論を読み比べ、方向を揃える
- 進めてよいことまで確認され、作業を再開させる

AIの処理能力は増えているのに、文脈と判断を運ぶ人間が一人のままなら、最後は自分がボトルネックになります。

Brainbaseが解くのは、AI不足ではありません。**自分の判断が、自分一人の頭と時間に閉じていること**です。

## Brainbaseが増やすのは、あなたの判断が届く範囲

```text
あなたの目的・優先順位・判断基準
                ↓
            Brainbase
      共通の判断OSとして正本化
                ↓
       ┌────────┼────────┐
       ↓        ↓        ↓
     壁打ち     調査     設計・実装
  探索と反証   比較検証   成果物の作成
```

Brainbaseは、あなたをコピーした正解生成器ではありません。

人間が、誰のために何を実現し、何を優先し、何を守るかを決める。AIは、その判断を出発点に、より広く探索し、強い反証を返し、許可された仕事を進める。

その結果、**頭のいい自分と壁打ちするように深く考え、その判断を複数のAIへ渡して仕事を広げる**ことができます。

## 頭のいい自分を、壁打ち相手にする

一般的なAIとの壁打ちは、まず視点を合わせるところから始まります。前提を説明し、一般論を修正し、ようやく本当に考えたい論点へ入る。

Brainbaseを参照するAIは、保存済みの目的、優先順位、過去の決定、守る条件から考え始めます。あなたの考えに同意するだけではなく、その判断が失敗する前提や最も強い反対案も探します。

```text
Brainbaseなし
前提説明 → 視点修正 → 一般論の除去 → 本題 → 深掘り

Brainbaseあり
保存した判断から開始 → 本題 → 探索と反証 → より深い判断
```

最初のずれを短くすることで、限られた時間を、説明ではなく思考に使えます。

## 同じ判断軸を、実行部隊にも渡す

一つの事業方針から、次の仕事を別々のAIへ任せることができます。

- 市場と競合を調査する
- 事業戦略と実行計画を設計する
- 営業資料やWebコピーを書く
- システム構成と仕様を作る
- 実装コードとテストを書く
- 結果を評価し、次に見直す判断を整理する

Brainbaseは、エージェントの数を増やす製品ではありません。**Codex、Claude Code、Manaなどの対応エージェントが、同じ判断から動けるようにする基盤**です。

| Brainbaseなし | Brainbaseあり |
| --- | --- |
| AIごとに目的と背景を説明する | 複数のAIが同じ判断正本を参照する |
| AIごとに優先順位がずれる | 何を優先し、何を守るかを共有する |
| 無難な一般論へ戻るたびに修正する | 自分が承認した判断を出発点にする |
| 並列化するほどレビューが増える | 判断の境界を揃え、方向修正を減らす |

## 自分らしさを薄めず、作れる量を増やす

大量に生成できても、成果物が無難で同じようなものなら価値は増えません。

Brainbaseが目指すのは、AIスロップの量産ではありません。あなたが何を実現し、何を優先し、何を守るかを保ったまま、同時に前へ進められる仕事を増やすことです。

> **作れる量を増やす。判断の質は薄めない。**

## 同じ資料を読ませても、同じ判断にはならない

Google DriveやSlack、会議記録は、Brainbaseにとって重要な情報源です。ただし、資料が同じでも、何を正しいとみなすかが違えば、AIの判断は揃いません。

```text
Google Drive
複数のAIに、同じ資料を読ませる共通の資料室

Brainbase
複数のAIに、今使う判断を渡す共通の判断OS
```

社内資料の検索や要約だけが目的なら、Brainbaseは必要ありません。

Brainbaseが必要になるのは、正式決定、過去の方針、会議中の仮説、個人の意見が混ざる中から、**どの判断が現在有効か、なぜそう決めたか、何が変われば見直すか**を、人間が確認した正本として再利用したいときです。

| 資料連携 | Brainbase |
| --- | --- |
| 関連する文書を探す | 現在使う判断を引く |
| 文書からその都度方針を推測する | 人間が承認した判断を再利用する |
| 案・決定・旧方針が同じ検索対象になる | 有効性と置換関係を区別する |
| 情報源ごとに文脈が分かれる | 対応するAIが同じ判断正本を使う |

## Brainbase・AI・Manaの役割

```text
Google Drive / Slack / 会議 / メール
              証拠・履歴・素材
                     ↓
                 Brainbase
       目的・判断・根拠・条件・権限
                     ↓
       Codex / Claude Code / その他のAI
            探索・反証・作成・実行
                     ↓
                   Mana
       起動・優先順位・追跡・継続運営
```

Brainbaseは、何を根拠に、どう判断し、どこまで進めてよいかを扱います。AIエージェントは、その判断を使って考え、作ります。Manaは、どの仕事をいつ動かし、何を優先し、完了までどう追跡するかを担います。

## まず一人分の判断から

現在の公開OSS版は、ローカル優先・単一所有者向けです。最初から自分のすべてや会社全体を構造化しません。

1. 自分の判断が何度も必要になる仕事を一つ選ぶ
2. 目的、関係者、判断基準、過去の決定を承認して保存する
3. CodexやClaude Codeから、その判断を使って一つの実務へ回答させる
4. 壁打ちの深さ、成果物の方向性、説明や修正の減り方を確認する
5. 役立った判断だけを追加し、別のAIや仕事へ広げる

個人で育てた判断基盤をチームへ広げる段階では、権限、承認、例外、監査を加えるOrganization / Enterpriseへ移行します。組織機能には未実装または計画中の範囲があるため、[現在の状態](/guide/status)で境界を明示しています。

## Brainbaseを支える3つの構造

Brainbaseは、情報を一か所へ集めるだけのデータベースではありません。次の3つを分けて持つことで、言葉の意味を揃え、判断の理由をたどり、複数のAIへ同じ前提を渡します。

| 構造 | 役割 |
| --- | --- |
| オントロジー | 人物、組織、プロジェクト、判断などの意味と、接続してよい関係を定める |
| Graph SSOT | 実在する人物、組織、プロジェクト、判断と、それらの関係を正本として持つ |
| Judgment DAG | どの証拠から何を判断し、どの権限で実行し、結果をどう評価したかをつなぐ |

[仕組みを一枚の構成図で見る](/guide/architecture) · [オントロジーとは何かを見る](/guide/ontology)

## 現在試せるもの

公開OSS版では、まず個人の仕事文脈と判断基準をローカルへ置き、CodexやClaude Codeへ渡します。

- Graph v2とOntology 2.0.0で人物・組織・プロジェクト・判断を接続する
- `resolve_entity`、`get_context`、`search`で依頼を正しい文脈へつなぐ
- Judgment DAGの型と依存関係を検証する
- ローカルの決定論的runnerでDAGを実行する

永続artifact store、過去runのreplay、本格的なevaluation、組織向けガバナンスなど、まだ計画中の機能もあります。誇張せず、[現在の状態](/guide/status)で境界を明示しています。

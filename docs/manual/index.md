## AIに、自分の仕事を毎回説明し直さない。

人間は、仕事の目的、判断基準、任せてよい範囲を決める。  
AIは、それらを参照して選択肢を比較し、見落としを指摘し、許可された範囲を進める。

Brainbaseが残すのは、単なる資料の置き場所ではありません。何を目指し、誰のために、何を優先し、何を守り、なぜその判断を選んだのかを、次の人やAIが再利用できる形で残します。
<!-- brainbase:public-message:end -->

## AIは賢くても、あなたの仕事を最初から知っているわけではない

新しいチャットやエージェントを開くたびに、次のことを説明し直していないでしょうか。

- この仕事で何を実現したいのか
- 誰が関係し、誰が何を決めるのか
- 何を優先し、何を避けたいのか
- 過去に何を決め、なぜそう決めたのか
- どこまでなら確認せず進めてよいのか

何も渡さなければ、AIは一般論から考えます。毎回プロンプトへ書き直せば近づきますが、仕事は文脈の復元から始まり、重要な論点へ入るまでに時間がかかります。

Brainbaseは、この繰り返しを「より長いプロンプトを書くこと」ではなく、仕事の前提と判断基準を再利用できる正本として持つことで減らします。

## Brainbaseが変えるのは、AIが考え始める場所

たとえば、新しい案件を受けるべきかAIへ相談するとします。

一般的なAIは、市場価格、売上、利益率から受注を勧めるかもしれません。しかし、あなたが「単発受託を増やさず、再利用できる資産になる仕事を選ぶ」と決めているなら、その一般論は判断の出発点としてずれています。

Brainbaseを参照するAIは、案件情報だけでなく、あなたの稼働上限、資産化方針、過去に断った理由、守るべき関係を確認します。そのうえで、受ける条件、断る理由、見落としている反証を整理します。

| Brainbaseなし | Brainbaseあり |
| --- | --- |
| 会話ごとに前提を説明する | ローカルの正本から必要な前提を参照する |
| 一般的な基準から考え始める | 自分が承認した判断基準から考え始める |
| 結論や成果物だけが残りやすい | 根拠、優先順位、見直し条件まで残す |
| 文脈が特定の会話へ閉じやすい | 対応するAIエージェント間で同じ正本を使う |

## ChatGPTやClaudeの代わりではない

Brainbaseは、新しい基盤モデルやチャットUIを作る製品ではありません。

```text
Codex / Claude Codeなど
考える、比較する、作る、実行する

Brainbase
誰のどの前提と判断基準で考えるかを渡す
```

AIの性能はモデル側にあります。Brainbaseの役割は、仕事の目的、関係者、過去の決定、判断基準を特定の会話やモデルの内部だけに置かず、自分で管理できる正本として接続することです。

## まず個人で、判断基盤を育てる

現在の公開OSS版は、ローカル優先・単一所有者向けです。最初から会社全体を構造化するのではなく、本人が実際に繰り返している仕事を一つ選びます。

- 壁打ちや企画で、最初の視点合わせを短くする
- メール、資料、仕様を、自分の方針から作り始める
- 過去に決めたことを、新しい証拠なしに何度も開き直さない
- AIが進めてよい範囲と、人間へ戻す範囲を明示する

個人で育てた判断基盤をチームへ広げる段階では、権限、承認、例外、監査を加えるOrganization / Enterpriseへアップグレードします。これらには未実装または計画中の機能があるため、[現在の状態](/guide/status)で境界を明示しています。

## Brainbaseを支える3つの構造

Brainbaseは、情報を一か所へ集めるだけのデータベースではありません。次の3つを分けて持つことで、言葉の意味を揃え、判断の理由をたどり、許可された仕事だけを進めます。

| 構造 | 役割 |
| --- | --- |
| オントロジー | 人物、組織、プロジェクト、判断などの意味と、接続してよい関係を定める |
| Graph SSOT | 実在する人物、組織、プロジェクト、判断と、それらの関係を正本として持つ |
| Judgment DAG | どの証拠から何を判断し、どの権限で実行し、結果をどう評価したかをつなぐ |

[仕組みを一枚の構成図で見る](/guide/architecture) · [オントロジーとは何かを見る](/guide/ontology)

## 現在試せるもの

公開OSS版では、まず個人の仕事文脈と判断基準をローカルへ置き、CodexやClaude Codeへ渡します。

- Graph v2とOntology 2.0.0で人物・組織・プロジェクト・判断を接続する
- `resolve_entity`、`get_context`、`search`で依頼を正しい文脈へつなぐ
- Judgment DAGの型と依存関係を検証する
- ローカルの決定論的runnerでDAGを実行する

組織向けガバナンスやreplay/evaluationなど、まだ計画中の機能もあります。誇張せず、[現在の状態](/guide/status)で境界を明示しています。

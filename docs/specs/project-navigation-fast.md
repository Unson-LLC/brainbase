# プロジェクト遷移とデータ取得の分離

Story: story-project-navigation-fast

- 共通Graph UIが選択直後に中央の個別ページ枠を描画する。ホストから渡せるのは既知のID・表示名のみで、Graphの目的・状態・人数を補完しない。
- 一覧取得中でも選択IDがあれば、選択先の見出しと読み込み状態を描画する。Graph一覧の失敗は一覧の問題として示し、選択した個別表示を無言で消さない。
- 詳細取得中も同じ見出しを保ち、成功時に既存のKnowledge Workspaceへ置き換える。失敗時は再試行可能なエラーを表示する。
- 一覧と詳細は同時に読み始められるが、一覧のJSONを受信して選択IDの存在を確認するまでは、先行した詳細・補足情報を画面へ適用しない。一覧が失敗した場合や選択IDを含まない場合は、先行読込の結果を破棄し、別IDへフォールバックしない。
- 選択変更ごとの世代で古い応答を無効化する。破棄済みビューを更新しない。
- 組織ホストはクリックイベント先頭の時刻を保持し、対象の個別見出しがDOMへ接続された描画フレームで所要時間を記録する。通信取得時間とは別値にし、古いプロジェクトの計測を採用しない。
- テストでは一覧・詳細を未解決にしたまま見出しがあること、一覧確認前の先行詳細を保留すること、一覧の失敗・欠落、A→B→Aの遅い応答、破棄を確認する。本番では複数プロジェクトの切替を計測し、各回1,000ms未満を確認する。

# UX-20261001-03 Graph訂正案内 Spec

## 振る舞い

選択中の記録が読み取り済みで、ホストが少なくとも1つの訂正入口を許可しているとき、右レールの概要と操作の間に「訂正の流れ」セクションを出す。セクションは、その記録で実際に表示する操作だけを入口として列挙する。

案内文は次の事実を短く示す。

1. 「この記録を直す」「関係を加える」「この関係を直す」のうち利用可能な操作から変更内容を入力する。
2. 承認待ちの提出段階はなく、保存するとその場でGraphへ反映される。
3. 保存すると、理由と変更前後が履歴に残る。
4. 保存後に読み直して保存内容との一致を確かめる。
5. 確認できた内容は、次のMCPの `search`・`get_context`・`resolve_entity` で使われる。

`canCorrect: false` のとき、または範囲によってすべての入口が隠れるときはセクションを出さない。既存のホスト読み取り専用案内は変更しない。

## 非機能・境界

- UIの表示文言だけを追加し、API、Graphスキーマ、保存処理、承認フロー、反映経路を変更しない。
- 実装していない人手承認を想起させる案内はしない。現行の直接保存を誤解なく示すため、「承認待ちの提出ではなく」のような否定形で、別の提出・承認段階がないことを明示する。
- 実データをテストへ持ち込まず、既存の架空Graph fixtureを使う。

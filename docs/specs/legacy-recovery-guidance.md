# Story: 古い復旧手順から危険な操作を再導入しない

利用者が意図しない削除から復旧するとき、現行仕様を保ち、通常のレビュー・配信権限を通って回復できる。

## 最小Spec・受け入れ条件

1. 現行仕様と意図的な廃止を確認し、最小修正と取り消しを比較する。
2. 外付けworktree helperを使い、既存dirty checkoutを保護する。
3. 管理者マージ、強制worktree削除、個人checkoutの依存物共有を実行例に含めない。
4. 固定SHAで復元元を確認し、失敗件数だけで合格としない。
5. 通常のPR/CIを守り、マージと本番反映・readbackを区別する。
6. 診断文書とrunbookの手順が矛盾しない。

対象はrunbookと直接参照する診断文書。実コード・runtime・データの削除、本番復旧は対象外。

## 検証

対象2文書の禁止コマンド・旧参照の残存検索、相対リンク存在確認、受け入れ条件に対する独立レビュー、git diff --check。文書のみの変更でruntimeテストは適用しない。

# 退役SNSの独立モジュール除去

## Story

保守者として、運用入口の廃止後にテストからだけ参照される旧SNS実装を除去し、
現役の個人知識機能と退役実装を混同せず保守できるようにする。

## 対象と判断

対象は `server/services/sns/curator-scoring.js` と
`server/services/sns/sns-posting-auth-health.js`、その専用テスト4ファイルだけ。
ファイル名と公開関数名によるリポジトリ内検索では、実装以外のコード参照は
専用テストのみ。Graphifyは両ファイルに一致したが、鮮度と影響の網羅性は不明。
「共有処理から必要」という代替仮説は、この範囲の参照検索と残存テストで確認する。
リポジトリ外の直接importや本番の稼働状態まで不在と断定しない。

## 受け入れ条件

1. 対象2モジュールと専用テスト4ファイルを除去する。
2. 実行コードに対象パス・公開関数への参照を残さない。
3. SNSのAPI 410・CLI副作用前拒否、残存curator、個人知識readerのテストを維持する。
4. 個人知識・人物同定・会議学習の実装、旧SQL、台帳、保存データを変更しない。
5. 対象を現役として示す旧仕様には履歴資料であることと後継仕様を明記する。

## 検証と境界

削除前に専用4ファイルのテストを確認し、削除後に退役境界・残存curator・
個人知識readerの対象テストを実行する。変更後レビューは1回、通常PRのCIを確認する。
本番配備、ジョブ停止、データ削除は対象外。
退役全体の契約と未検証の本番受け入れは [SNS廃止仕様](retire-sns-spec.md) に従う。

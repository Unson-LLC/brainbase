# Graph検索契約

Story: [質問から判断の根拠に到達する](../stories/story-graph-evidence-retrieval.md)

既存MCP `search` の既定を意味検索にする。`mode: lexical` は従来の文字検索を明示して利用する場合に残す。

自然言語の解釈は呼び出すモデルが行う。意味検索で種ノードを探した後、必要なら同じ `search` に `plan.seed_ids` と `plan.steps` を渡す。stepは `relation`、`direction`（incoming/outgoing）、任意の `target_type`。最大10種ノード・3段階。関係を推測生成せず、実在するedgeだけを返す。

検索はリクエストの認証とproject scopeを使う。Graph本文の共有キャッシュは持たない。モデルのみローカルにキャッシュする。Graphの取得上限に達したときはcoverageをpartialとする。失敗したAPIレスポンスを空配列に置き換えない。

候補には取得した本文・出典ポインタと経路を付ける。出典URLや個人パスを自動的に外部取得しない。本文が存在しても質問への充足や決定の適用可能性は未検証であり、モデルによる確認を必要とする。情報不足はinsufficientとして残す。

検証は意味検索の実モデル実行、固定質問による比較、関係・ライフサイクル・認証・障害・不足の回帰テストを行う。固定質問は探索用の小規模評価であり、未見質問への一般精度とは区別する。

意味検索は上位3候補の実在する関係名を `relation_catalog` に返す。必要な場合にモデルがその関係と方向を選んで再検索する。`inspect_relations: false` で省略可能。取得は1要求40 API呼び出しまで・追加要求開始は45秒以内、各HTTP要求は20秒で打ち切る。予算超過は成功や0件ではなく明示的エラーになる。

運用反映前に `BRAINBASE_EMBEDDING_CACHE_DIR` をモデル保存先へ設定し、単一プロセスでモデルを取得・実行してからMCPを起動する。初回モデル取得は約470MBあり、複数プロセスの同時初回ダウンロードは避ける。既存の全体Hooks設定はこの変更に含めない。

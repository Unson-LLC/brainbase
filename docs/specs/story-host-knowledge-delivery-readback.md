# Host学習イベントの受信確認

## Story

利用者として、Hostが生成した学習イベントがBrainbaseに保存され、読戻しで確認できた場合だけ配送完了と分かるようにしたい。

## 仕様・受入条件

1. 既存の `POST /api/knowledge/events` のイベントID・候補IDを確認し、送信待ち記録に保存する。HTTP成功だけでは削除しない。
2. 既存の `GET /api/knowledge/cycles/:eventId?project_code=...` で `knowledge_cycle_receipt.v1`、同じイベントID・候補ID、検索可能かつ有効な状態を確認する。
3. 受信証跡を永続化した後だけ送信待ちを解消する。GET失敗、不一致、不明、隔離状態は成功にしない。
4. POST応答保存後の再起動・再試行はGETから再開する。POST応答保存前の障害は同じイベントIDで再送し、既存の冪等性を利用する。409や再試行上限でもイベントを失わず、既存の隔離保存先に保持する。
5. 証跡保存失敗では送信待ちを削除しない。認証情報を証跡に保存しない。
6. judgment final completeと配送完了は別状態のまま保つ。Stopを受信処理待ちにせず、循環依存を作らない。

## 対象外

VibePro sender、新API、権限拡張、本番更新、共有トークン更新。

## 検証

既存outbox単体テストに、正常配送、ID不一致、GET失敗からの再開、隔離、409、再起動、証跡保存失敗を追加する。最初に失敗を確認してから実装する。実環境の配送確認は別途、対象SHAと受信証跡を照合する。

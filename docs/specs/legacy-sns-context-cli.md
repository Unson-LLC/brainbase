# 退役SNSコンテキストCLIの縮小

## Story

Brainbaseを保守する人として、廃止済みのコマンドがDBや個人設定に依存せず、常に廃止を通知して終了する状態にしたい。

正本の境界は [SNS廃止仕様](retire-sns-spec.md)。今回は `scripts/build-sns-generation-context.js` だけを通知用の入口へ縮小する。

## 受け入れ条件

1. 旧パスは維持し、通常起動・`--dry-run --json`・`--confirm-public-post` のすべてで終了コード1、標準出力なし、`SNS_CLI_RETIRED` と操作未実行の説明を返す。
2. Node組み込みと退役通知ヘルパーだけで実行できる。隔離fixtureにこの2ファイルのみを置き、DBライブラリ・個人設定・サービス実装なしで条件1を満たす。
3. importしただけでは標準出力・標準エラー・処理終了を発生させない。CLIの実行判定を維持する。
4. 到達不能の生成・DB・ファイル出力・引数処理を除去する。共有サービス、SQL、保存台帳、他のCLIは変更しない。
5. 既存の退役境界CIでこのCLIと通知ヘルパー・退役テストの変更を検知し、SNS CLI退役テストとAPI410境界テストを実行する。

## 判断と検証

代替案は旧ヘルパーの外部import互換のため本文を残すこと。repo内にはこのCLIのexportを使う呼出元がなく、現行仕様が入口を退役させているため、通知パスを残して旧本文を除去する。repo外の直接import利用は未確認であり、不在とは断定しない。

隔離fixtureの失敗を先に確認し、変更後にSNS退役CLI、API410境界、配布境界の対象テストを実行する。一度の独立レビューと通常PR/CI経路を使う。本番反映・ジョブ停止・保存台帳の変更は対象外。

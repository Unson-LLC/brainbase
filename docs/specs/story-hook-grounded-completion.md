# Graphを実参照した後に回答を完了する

VibePro Story: `story-hook-grounded-completion`。機械可読Specは同名の `.input.json`。

## 目的と責任境界

Graphの参照先を決めただけで参照済みとして完了していたため、実取得と質問に対する根拠確認を分ける。

1. MCPはGraph payloadの決定本文・理由・出典を保持して返す。検索と単体取得は共通の本文フィールド判定を使う。
2. モデルは取得内容が質問を裏付けるか判断し、`brainbase_knowledge_evidence_record`へ判定・実取得ID・理由を渡す。
3. Hostは同じturnの参照先解決後に実取得したIDと判定を照合する。本文がないIDや失敗した取得は「十分」の根拠にできない。追加取得後は再判定が必要。
4. Stopは参照先解決だけの完了を差し戻す。根拠不足は不足として完了できるが、不在確定とはしない。再差し戻しは既存の有限回制御に従い、未充足は監査縮退として残す。

Hostが保証するのは取得と判定の対応であり、モデルの意味判断の正しさではない。既存の取得内容を使うので、検証のための追加Graph検索やベクトル生成は行わない。

## 導入と戻し方

MCPに新しい判定toolと取得メタデータを先に導入し、次にBrainbase限定Hostへ反映する。旧MCPのままHostだけ更新すると必須参照turnが完了できなくなる。戻す場合はHostを先に旧版へ戻す。全体hooksの設定は変更しない。

## 検証

- `tests/unit/knowledge-evidence.test.js`: 未取得、別ID、本文なし、失敗、再取得後の判定失効。
- `tests/unit/judgment-resolver-host.test.js`: Graph参照先解決だけのStop差し戻し、実取得と十分/不足判定後の完了、失敗routeの監査縮退。
- MCP `knowledge-evidence`, `knowledge-owner-audit`, `engine`, `graphapi-source` tests: 本文・出典保持、空構造、未知と空の区別、失敗応答。

実ランタイムの正常・不足・MCPエラーと新規子タスク起動は別途確認する。単体テスト成功だけで全体展開可とはしない。

## 実タスクで判明した追加条件

2026-09-10の限定反映後、検索候補のIDが未読込索引から取得されて該当なしになることと、Codexが失敗MCPにPostToolUseを発火せず監査から欠落することを確認した。単体取得は認可されたGraph正本へ問い合わせ、失敗はCodexの信頼済み実行記録から次の監査前に照合する。索引全件読込や追加の意味検索で補わない。

本文がGraph正本にない決定は、取得経路を直しても根拠不足である。存在確認と回答を裏付ける本文の充足を別々に検証する。

子タスクの圧縮後の同一turn_context再掲は、別系統のBrainbase限定Host（canary）のSpecとテストで扱う。配布版へ未統合のbootstrapをこの変更に混ぜない。

根拠取得を要求するStop差し戻し後は、実取得・根拠判定後の最新監査と本文に更新する。取得前の本文や監査を固定しない。監査形式だけの修復では従来の本文保護を維持する。

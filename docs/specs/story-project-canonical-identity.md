# Story: 指定したプロジェクトを別の詳細へ切り替えない

## ユーザー価値

ホストが指定したプロジェクト、または利用者が選択しているプロジェクトの記録が一覧から読めなくなったとき、別のプロジェクトの詳細を誤って表示しない。利用者は、指定したIDが現在のGraph一覧にないことを確認してから再読込や正規化を判断できる。

## OSSの範囲

共通の `GraphProjectsView` が、プロジェクト一覧と選択中の詳細の同一性を保つ。組織ホスト側のプロジェクトコード、別名、権限、Graphの正規化はこのStoryの対象外であり、共通UIに暗黙の名寄せを追加しない。

## 最小Spec

- 初期選択がない場合は、従来どおり一覧の先頭を選択し、そのIDの詳細を読む。
- `selectedId` が指定されている場合、一覧にそのIDがないときも選択IDを保持する。
- 選択IDが一覧にない状態では、そのIDを `not_found` として表示し、一覧の先頭や別のIDの詳細を自動で読まない。
- 選択中のIDが再読込後に一覧から消えた場合も同じ扱いとし、`onSelect` を通知しない。
- 一覧に存在する選択IDは従来どおり詳細を読む。利用者が一覧行をクリックして選択を変える操作も従来どおり動作する。

## 受入条件

1. `selectedId: project-gone` で一覧を読み込むと、`selectedId` は `project-gone` のまま、詳細状態は `not_found` になり、`project-atlas` など別IDの詳細リクエストが発生しない。
2. `project-atlas` を選択した状態で一覧から `project-atlas` が消えて再読込されると、選択IDは維持され、別プロジェクトへの `loadDetail` と `onSelect` は発生しない。
3. 初期選択なしで一覧にプロジェクトがある場合、一覧の先頭が選択される既存テストが通る。
4. `aitel` と `aitle` のような異なるIDの同一視は共通UIが行わず、ホストが渡したIDをそのまま扱う。
5. 一覧から消えた後に先行する詳細読込が完了しても `not_found` を上書きせず、対象が一覧へ戻ると詳細を再取得する。

## 検証とレビュー

- プロジェクトUIの回帰テスト48件とビルドが成功。
- 選択なし、明示指定の欠落、再読込による消失、遅延応答、復帰を確認。
- 親レビューで別IDへのフォールバックと非同期応答の整合性を確認。組織固有の識別子や認可処理は追加していない。

## 非対象

- Graphのエンティティ統合、別名解決、ライフサイクル状態の変更
- ホスト側のプロジェクト一覧APIや認可ルールの変更
- npmのバージョン変更や公開作業

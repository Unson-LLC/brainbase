# Resolverの意味解釈と接続回復

## Story

利用者として、調査依頼が単語一致で実装依頼に変わらず、実際に回復した接続が過去の失敗だけで利用禁止にならないことを求める。

## 受入条件

1. モデルのintentを保持する。既存の安全上のaction/risk下限と追加義務は削除しない。
2. 同じセッションの相関したResolver呼出しに対する、構造化された解決成功応答はラッパー経由でも接続回復として認める。
3. 単なる成功文字列、関係ないcall_id、失敗を含む応答は回復証拠としない。
4. 接続回復は現在turnの判断契約成立を意味しない。現在turnのResolver実行義務を残す。
5. 委任Stop recoveryを生成前の判断と表現しない。認証や書込権限を変更しない。

## 検証

serviceとHostの対象テストで失敗を再現してから修正する。通常タスクと委任タスクの実動確認は別途、実行SHA・journal・最終回答を照合する。

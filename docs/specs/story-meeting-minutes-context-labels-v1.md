# Meeting minutes UI context labels and create guard v1

このSpecは [story-meeting-minutes-context-labels-v1](../stories/story-meeting-minutes-context-labels-v1.md) の最小実装契約を固定する。共有UIは会議データの表示と作成操作だけを担当し、ラベルの解決と作成可否の判断は呼出し元へ委譲する。

## API

`createMeetingMinutesUI(options)` は次の省略可能なオプションを受け付ける。

```ts
type MeetingLabel = (meeting: Record<string, unknown>) => string | undefined;
type CanCreateMeeting = boolean | (() => boolean);
type CanEditMinutes = boolean | (() => boolean);

interface MeetingMinutesUIOptions {
  meetingLabel?: MeetingLabel;
  canCreateMeeting?: CanCreateMeeting;
  canEditMinutes?: CanEditMinutes;
}
```

既存の `root`、`fetcher`、`token`、`basePath`、`versionActionExtensions` などの契約は変更しない。

## 補助ラベル

- `meetingLabel` が関数の場合、一覧と詳細の各会議に対して表示用文字列を取得する。
- 戻り値が文字列なら前後の空白を除き、空でない値だけを一覧と詳細へ表示する。非文字列、空文字、コールバック例外はラベルなしとして扱う。
- ラベルはDOMの `textContent` 相当の文字列として挿入する。HTML、属性、イベントハンドラとして解釈しない。
- コールバックへ渡す会議はAPIから受け取った会議レコードである。共有UIは値を別のレコードへ保存せず、ラベルから会議の所属、権限、保存先を推測しない。
- `meetingLabel` が省略された場合、一覧と詳細の従来表示を維持する。

## 作成ガード

- `canCreateMeeting` が省略または `true` の場合、会議作成ボタンを有効化し、既存のフォーム表示と作成POSTを維持する。
- `false` の場合、会議作成ボタンを無効化し、画面に「この画面では会議を作成できません。」という理由を表示する。
- 関数の場合は一覧を描画するときとフォーム送信の直前に評価する。戻り値が厳密な `true` のときだけ許可し、`false` または評価例外は拒否として扱う。
- 拒否状態で作成ボタンのクリックハンドラが呼ばれてもフォームを表示しない。フォーム表示後に拒否へ変わった場合も、送信前の再評価で保存リクエストを送らない。
- 作成ガードは会議作成のUI操作だけを制御し、一覧取得・詳細取得・議事録版保存の認可を変更しない。

## 議事録編集ガード

- `canEditMinutes` が省略または `true` の場合、版保存・議事録文書追加のフォームと未確認版の確認ボタンを表示・有効化し、既存の保存POSTを維持する。
- `false` の場合、版保存と議事録文書追加のフォームを表示せず、未確認版の確認ボタンを無効化し、「この画面では議事録を編集できません。」という理由を表示する。
- 関数の場合はフォーム・確認ボタンを表示するときと各書き込み操作の直前に評価する。戻り値が厳密な `true` のときだけ許可し、`false` または評価例外は拒否として扱う。
- 拒否状態でフォームまたは確認ボタンのハンドラが呼ばれても保存リクエストを送らない。表示後に拒否へ変わった場合も同じく送信を防ぐ。
- 編集ガードは会議一覧・詳細の取得を制御せず、ホストの認可判断を共有UIが推測することもない。

## リクエスト世代

- 一覧更新と詳細表示は、それぞれ開始時に世代番号を進める。
- 返却時の世代番号が最新でないレスポンスは、一覧、詳細、エラー、ステータスを更新しない。
- 一覧更新で選択中の会議が結果に含まれない場合、選択と詳細をクリアし、保留中の詳細レスポンスが後から詳細を復活させない。

## 境界

共有UIはホストが渡したラベルを表示するだけで、所属情報の解決、権限判定、保存先の選択を行わない。ホスト側は必要な認証・認可を維持し、許可済みの会議データへだけ適切なコールバックを渡す。

組織、テナント、メンバー、ロール、承認、プロバイダ接続などの概念やデータ項目をこの共有契約へ追加しない。

## 受入検証

1. 追加オプションなしで既存の一覧、詳細、会議作成を開き、表示とリクエストが変わらないことを確認する。
2. 特殊文字を含むラベルを渡し、一覧と詳細に文字列として表示され、HTML要素が生成されないことを確認する。
3. `canCreateMeeting: false` でボタンの無効化と理由表示を確認し、ボタン操作・フォーム送信がPOSTを送らないことを確認する。
4. 関数が拒否から許可へ変わった後に一覧を再描画し、フォームが使えることを確認する。フォーム表示後に再び拒否へ変えた送信はPOSTを送らないことを確認する。
5. `canEditMinutes: false` で版保存と議事録文書追加のフォームが表示されないことを確認し、許可状態で表示したフォームを拒否状態へ変えて送信してもPOSTを送らないことを確認する。
6. 一覧・詳細の古いレスポンスを新しいレスポンスより後に解決し、最新状態を維持することを確認する。絞り込み結果から選択中の会議が外れた後に古い詳細が復活しないことも確認する。
7. `tests/ui/meeting-minutes.test.mjs` の既存ライフサイクル回帰と追加ケースを実行する。

# 個人基盤 v1 コア仕様

## 不変条件

- INV-1: `PersonalKnowledgeContext` は5フィールドだけを持つ厳密なオブジェクトである。未知のフィールド、欠落したフィールド、空の識別子、不正なscope、不正な組織IDの組合せは拒否する。
- INV-2: コンテキストヘッダーは、正規化したJSONをUTF-8でエンコードしたbase64url値であり、名前は `X-Brainbase-Personal-Context` とする。
- INV-3: 登録・検索では期待するコンテキストを検証し、すべての操作結果に含まれるコンテキストが一致することを確認する。コンテキスト確認エンドポイントは、期待ヘッダーなしで認証済みコンテキストを返す。
- INV-4: ローカルのコンテキスト識別情報は、独立した `personal-knowledge-v1` ディレクトリに一度だけ初期化し、再起動や後続の呼出し側引数の変更で変えられない。
- `occurred_at` と `captured_at` は、指定された場合、タイムゾーンを含む厳密なISO 8601 timestampとし、入力された表記を保持する。不正な暦日付はローカル保存またはmanaged APIへの送信前に拒否する。
- INV-5: ローカル登録は永続的なファイルロックで直列化する。既存の `event_id` に対する同一内容の再試行は冪等とし、そのIDに異なる正規化イベントを登録する再試行は拒否する。
- 取得できないロックはタイムアウト時にfail closedとし、実装はロックの経過時間だけを根拠に削除しない。復旧時はロック所有者が停止していることを確認したうえでロックファイルだけを削除し、イベントファイルとコンテキストファイルは削除しない。
- INV-6: managed HTTPの接続先は明示的に扱う。`managed_cloud` はHTTPSと非loopbackホストを要求する。loopback HTTP clientは明示的なtest/development接続としてのみ利用できる。OSSのローカル動作はstdio+filesystemであり、HTTP待受を開始しない。リダイレクトや失敗したリクエストは明示的なエラーとし、フォールバックしない。
- INV-7: MCPのcontext、register、search入力には、識別情報やファイルシステム選択のフィールドを含めない。これらの値は信頼できる設定から決める。
- INV-8: 既存の `search_personal_kg` は、従来のローカルPersonal KGとの互換経路として残す。

## シナリオ

- S-1: 有効な個人所有および組織内本人専用のコンテキストをエンコード・デコードし、バイト単位で比較できる。フィールドが異なる場合は、そのフィールド名を示して失敗する。
- S-2: 不正、パディング付き、未知フィールドを含む、または組織設定と整合しないヘッダーは、managed registerリクエストを送る前に拒否する。
- S-3: ローカル保存はプロセスを再起動しても維持され、独立した新しいディレクトリから元のコンテキストとイベントを返す。
- S-4: 同じイベントを同時に再試行すると一つの永続イベントに収束し、内容が異なる再試行は失敗する。
- S-5: managedのGET context、POST register、POST searchは期待ヘッダーを使用し、ラップされたv1レスポンスのコンテキストと結果を検証する。
- S-6: loopbackおよびHTTPSの接続先規則、認証情報の欠落、リダイレクト、HTTP障害は、別の保存先を試すことなく明示される。
- S-7: MCPは3つのv1 personal-knowledgeツールを一覧に含め、従来の `search_personal_kg` ツールも維持する。

# Personal Value Proof Home Cold Read v1

Story: `docs/stories/story-personal-value-proof-home-cold-read-v1.md`

## 目的

判断の見返しの読み取りで、判断journalの全フォルダをリクエストのたびに一覧するのをやめ、変わったフォルダだけを一覧し直す。表示の中身（value-proof、会話で先に進んだ、利用不可、形式の誤り、記録の停止の可能性）の意味は変えない。

## 何を覚え、何を毎回読むか

覚えるのは、判断journalの直下の各フォルダについて、一覧した時点のフォルダの識別子（inode）、変更時刻（mtime と ctime、ナノ秒）、一覧した時刻、そのフォルダにあった `*.value-proof.json` の名前だけである。value-proof の中身は覚えない。

毎回読むのは、判断journalの直下の一覧、各フォルダの stat、value-proof の中身、待ちの判断（`waiting_human`）の会話フォルダの一覧と `.final.json` である。会話が先に進んだかの判定（`conversation_moved_on_at`）は、覚えた一覧を使わず、従来どおり毎回その会話フォルダを読み直す。

フォルダを一覧し直すのは、次のどれかのときである。

1. 覚えていない（最初の読み取り、新しいフォルダ）。
2. inode、mtime、ctime のどれかが、覚えた値と違う。判断のホストは value-proof と final を一時ファイルからの link で作り、上書きしない。ファイルが増えても消えてもフォルダの mtime が変わる。ctime は権限の変更なども拾う。
3. 一覧した時刻が、フォルダの mtime から3秒以内だった。時刻の刻みが粗いファイルシステム（HFS+ の1秒、exFAT の2秒）では、一覧の直後の変更が同じ時刻のままになりうるので、落ち着くまで毎回一覧する。

直下から消えたフォルダは忘れる。

## 失敗の扱い（変えない約束）

- 判断journalが無い・読めない: `status: 'unavailable'` を返す。前回の結果は使わない。
- フォルダの stat や一覧に失敗した: 読み取り全体を失敗させる（見返しのHTTPは500）。覚えた一覧で代えない。権限の変更は ctime を変えるので、一覧し直して失敗する。
- value-proof が壊れている: 毎回読み直すので、壊れていれば `rejected` に理由を出し、直れば受理する。
- `possibly_stalled` は従来どおり、読めた value-proof の最新の記録時刻から決める。

## キャッシュの持ち主と範囲

`JudgmentValueProofJournalCache` を見返しのHTTPのハンドラーが1つ持ち、`GET /home`、`POST /answers`、`POST /feedback` の読み取りで共有する。プロセスの外には保存しない。再起動後の最初の読み取りは、従来どおり全フォルダを一覧する。`readJudgmentValueProofJournal` は `cache` を省くと、毎回全フォルダを一覧する。

## 一覧と stat の並び

フォルダの stat と一覧は、従来の1つずつ順にではなく、同時に最大16件まで進める。Node のファイル操作は小さなスレッドプールで動くので、16件は待ち行列を切らさないための上限で、同時の実行数そのものではない。

## 検証

- 一時ディレクトリの実ファイルで: 変わらないフォルダを一覧し直さないこと、ファイルが増えたフォルダ・新しいフォルダ・作り直したフォルダを拾い消えたフォルダを落とすこと、その場で壊した・直した value-proof を次の読み取りで反映すること、後の `.final.json` で会話が先に進んだが付くこと、判断journalが消えたら利用不可になること、一覧できなくなったフォルダで失敗すること、変更の直後のフォルダを落ち着くまで一覧し直すこと。一覧の回数は、実ファイルの動作を保ったまま `readdir` の呼び出しを数えて確かめる。
- 実サーバーで: home を読んだ後に保存した value-proof が次の home に出ること、判断journalを消すと利用不可になること。
- 常駐の Personal Web で: 反映後、しばらく読まれなかった状態の最初の home の時間を計る。

# SNS廃止仕様

## 境界

`/api/sns-growth`は全操作をHTTP 410で拒否する。台帳・投稿実行器を初期化しない。
SNS専用CLIは副作用を始める前に廃止を通知して異常終了する。
SNSのnpm起動項目とlaunchd配布定義を現役運用から外す。
稼働中のジョブ停止は別途、実機上で対象を特定して確認する。

共通M5-Aの既定選択・明示選択にSNS台帳を含めない。
移行選択はDB接続前に検証する。`SNS_POSTING_LEDGER_DATABASE_URL`は共通移行先に使わない。
旧SQLと台帳は保全する。DROP、削除、帰属付け替えはしない。

`server/services/sns`内でも個人知識の読取り・人物同定・会議学習に使う共通処理は残す。
旧SNS内部実装を残しても、実運用入口から到達できないことを確認する。

## 検証

1. APIの読取り・投稿要求が410で、投稿実行器を呼ばない。
2. SNS CLIは環境変数や秘密情報なしで廃止応答となり、書き込みをしない。
3. M5-Aの既定選択にSNSがなく、明示指定はDB接続前に失敗する。
4. SNS専用URLを設定しても共通移行先が変わらない。
5. 個人知識・知識昇格・権限関連の既存テストが通る。

## 本番受け入れ（未検証）

マージSHA・配備SHAを固定し、API 410、SNS予約ジョブ停止、既存台帳件数の保全、共通機能を読み戻す。
これらが揃うまでは本番廃止完了としない。T0/A0/P0/G0の完了とは別に扱う。

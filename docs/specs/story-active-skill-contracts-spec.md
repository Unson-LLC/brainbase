# 現行開発指示の整合

入力は現行AGENTS、対象Skill本文、32入力の再チェック結果。dev-ops/dev-shipの自動削除・通常routingへの復帰は対象外。

- TDDは必要な振る舞いの失敗/成功を確認する。件数、モデル、工程数を成功条件にしない。
- リファクタリングは外部振る舞いの保持を確認する。設計とセキュリティは変更に関係する境界を選ぶ。安全要件は維持する。
- Host bootstrapと返されたTurnContractを正本とし、表示文言をSkillで固定しない。実装/操作は要求されるstateを最後に記録する。
- 委任は上位指示のモデル・権限・検証範囲を引き継ぐ。cc-router固有のprovider bindingを全workerへ強制しない。
- AGENTSは既存の配布原則を短く保持し、既存dirtyの分類方針作業をこのPRへ取り込まない。
- 読み込み元の更新は対象ファイルだけを、開始時hashと照合しバックアップして反映する。AGENTSの既存変更箇所は保持し、他のdirty/stagedファイルは変更しない。

## 検証

変更本文と参照先の照合、frontmatter、AGENTS/CLAUDE同一性・行数、diff check、一度の独立レビュー。反映前後hashと既存変更の保持を確認する。実際のモデル性能向上は別の実務比較が必要で、文書整理から断定しない。JevのkeepやAPI失敗を合格証拠にしない。

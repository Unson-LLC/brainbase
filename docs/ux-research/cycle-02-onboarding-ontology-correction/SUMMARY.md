# 初心者向けペルソナ固有再評価サマリー

## 結論

前回の「32 / 32 `clear_success`」「収束」は撤回した。前回は、1回の共通操作の成功判定を32ペルソナへ複製しており、各人の性格による感じ方を評価できていなかった。

再評価では、32ペルソナそれぞれについて、役割・業務経験・技術習熟度・時間圧・中断状態・作業スタイル・入力環境・アクセシビリティ条件を組み合わせ、共通の実画面証拠をどう受け取るかを個別に記録した。

| 判定 | 人数 | 意味 |
|---|---:|---|
| 摩擦なしで安心して使えると確認済み | 0 / 32 | 今回は該当なし |
| 完了可能だが性格に応じた摩擦あり | 10 / 32 | 支援技術指定なしの合成ペルソナ。専門語、英語識別子、中断復帰、確認不足などの摩擦が残る |
| 未確認 | 22 / 32 | スクリーンリーダーまたは動きの抑制を必要とするが、その条件で実操作していない |
| 実在の初心者 | 0人 | 人数・成功率とも不明 |

したがって、このサイクルの正しい状態は `not_converged` である。

## 性格ごとに変わった評価

- 速度重視かつ時間圧が高い人は、説明より先に「次の一手」を探し、長いJSONを読み飛ばす。
- 確認重視の人は、実行前に変更内容と取り消し可能性が分からないと止まりやすい。
- 頻繁に中断される人は、復帰時に「現在地・済んだこと・残り」の要約を必要とする。
- 業務初心者または技術習熟度が低い人は、`runId`、`candidateId`、`relations`などの英語識別子に負荷を感じやすい。
- オントロジー管理担当は、やさしい説明から正式な型・関係・版管理の根拠へ辿れることを求める。
- 復旧重視の人は、正常系の完了だけでなく、失敗理由、戻し方、責任者を必要とする。

これらは実在利用者の発言ではなく、ペルソナ属性から合成した反応要約である。

## 次に直す候補

1. 「次の一手」を詳細JSONより上へ固定する。
2. 中断復帰用に「現在地・済んだこと・残り」を表示する。
3. 実行前に変更内容と取り消し可能性を日本語で示す。
4. 日本語の業務例から正式な型・関係・変更手順へ段階的に開けるようにする。
5. スクリーンリーダーと動きの抑制設定を実際に有効化して再評価する。

機能上の行き止まり5件を修正した事実は維持する。ただし、それは全性格の初心者が安心できることの証明ではない。

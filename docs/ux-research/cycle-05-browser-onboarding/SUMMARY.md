# cycle-05: OSS初回導入UX

## 結論

3ラウンド、各32人の独立ペルソナによる可視ブラウザ評価を行い、初回導入の最短導線と中断時の再開方法を改善した。Round 3で確認済み重大ゲート違反0件、確認済み回帰0件、新規の繰り返しテーマ2件となり、収束条件を満たした。

## 変更した利用者体験

1. トップから「10分で試す」へ直接進める。
2. 一枚で、準備、開始、MCP、任意のJudgment Host、成功確認、復旧を追える。
3. 既存設定を自動上書きせず、dry-run、バックアップ、手動追加を近接して確認できる。
4. 中断前に「現在地メモ」をコピーし、完了済み・次の操作・未確認・最後の実結果を分けて残せる。
5. 明示的なSVG faviconにより、再現できた既定faviconの404を避ける。

## 生データと判定

- ペルソナ構成: `rotation-manifest.json`
- 評価契約: `evaluation-contract.md`
- Round 1〜3の個別JSON: `rounds/`
- Round 1〜3の個別スクリーンショット: `screenshots/`
- 変更前後の独立観測: `baseline-observation.json`、`after-observation.json`
- 採用・延期・未確認の理由: `decision-log.md`、各Round summary

個別JSONは表現を正規化せず保存している。集計値はローテーション、ファイル数、独立再検証に基づき、生の単発所見を削除しない。

## 証拠境界

確認済みなのは、ローカルVitePress UI、ソース契約、ビルド、合成ペルソナによるPlaywright Chromium操作である。実在利用者、実機、VoiceOver、実MCP登録、実Judgment Host登録、実行モデルbindingは `not_collected` のまま残す。

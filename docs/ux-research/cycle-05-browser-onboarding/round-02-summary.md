# Round 2: 最短導線追加後のブラウザ評価

## 結論

Round 1で採用した「10分で試す」導線を追加したHEADを、32人の独立したペルソナが同じ4タスクで再評価した。32件のJSONと32件のスクリーンショットを保存した。

トップから開始地点へ入る迷い、既存設定を上書きする不安、成功条件を探す負担は軽減した。一方、頻繁に中断される利用者は、ブラウザを閉じる前に完了済み・次の操作・未確認・最後の実結果を自分で再構成する必要がある、という摩擦が複数の評価で残った。

このため、チェック状態を自動保存する機能を追加するのではなく、ページ先頭にコピー可能な「現在地メモ」を追加してRound 3へ進めた。

## 観測結果

| 観測 | 件数 | 判断 |
|---|---:|---|
| 可視Playwright Chromiumによる個別評価 | 32/32 | 評価完了 |
| 個別JSON | 32 | 保存済み |
| 個別スクリーンショット | 32 | 保存済み |
| 主な残存摩擦 | 1テーマ | 中断時の進捗引き継ぎを採用 |
| 実在利用者・実機・VoiceOver | 0 | `not_collected` |

## 採用した変更

- 「現在地メモ」に、完了済み、次にやること、未確認、最後に確認した実結果を近接して置く。
- 画面のチェック状態は保存されないことを明記し、中断前にメモを手元へコピーするよう案内する。
- 実行済みと未確認を混ぜず、再開時に実結果を再照合できる形にする。

## 採用しなかった変更

- ブラウザ内の自動進捗保存は、静的マニュアルの境界を越え、実MCP・Hook状態とのずれを新たに生むため今回は追加しない。
- 設定の自動統合は、既存設定を壊さない境界を優先して追加しない。

## 証拠境界

- 個別評価は合成ペルソナによる実ブラウザ操作であり、実在利用者の観察ではない。
- 個別JSONの表記には揺れがあるため、人数とローテーションは `rotation-manifest.json`、生の所見は各JSONを正本とする。
- 実MCP登録、実Judgment Host登録、VoiceOver、物理端末、実行モデルbindingは `not_collected` とする。

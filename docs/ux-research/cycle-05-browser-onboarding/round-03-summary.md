# Round 3: 現在地メモ追加後のブラウザ評価

## 結論

コピー可能な「現在地メモ」を追加したHEADを、32人の独立したペルソナが同じ4タスクで評価した。32件のJSONと32件のスクリーンショットを保存した。

新たに繰り返された所見は、手動メモが自動保存ではないことと、詳しい成功確認では詳細ページも読む必要があることの2テーマだった。どちらも静的な初回マニュアルの安全境界を壊してまで今回追加する機能ではない。独立再検証で確認できた重大ゲート違反と回帰は0件だったため、3ラウンドで収束と判定する。

## 観測結果

| 観測 | 件数 | 判断 |
|---|---:|---|
| 可視Playwright Chromiumによる個別評価 | 32/32 | 評価完了 |
| 個別JSON | 32 | 保存済み |
| 個別スクリーンショット | 32 | 保存済み |
| 繰り返された新規テーマ | 2 | 収束条件の3件未満 |
| 独立再検証で確認できた重大ゲート違反 | 0 | 収束 |
| 独立再検証で確認できた回帰 | 0 | 収束 |

## 再現確認を分離した所見

1人が `/guide/mcp-install` を「HTTP 200だがtitleと本文が空」と報告した。これは重大ゲート報告として生のJSONに残す。

同じHEAD・同じローカルサーバーへ別のPlaywright Chromiumからアクセスして再確認した結果は、HTTP 200、title `MCPを登録する | Brainbase`、本文1,373文字、失敗レスポンス0件だった。16ブラウザを同時実行していた時間帯の単発観測であり、再現しないため、確認済み回帰ではなく `unconfirmed` とする。

複数の評価がURL不明の404を記録したが、独立確認では必須ページの失敗レスポンスは0件だった。対象URLを取得できていないため、これも `unconfirmed` とし、0件や修正済みには丸めない。

## 残した摩擦

- 現在地メモは利用者がコピーする運用であり、実MCP・Hook状態と自動同期しない。
- クイックスタートは一枚で完走できる要点を持つが、詳細な理由や補足は既存ページへ段階的に開示する。

## 証拠境界

- 実在利用者の観察、VoiceOver、音声入力、物理端末は `not_collected`。
- 実MCP登録と実Judgment Host登録は `not_collected`。
- ペルソナが要求したモデルと、実行時モデルのbindingは同一と確認できないため `not_collected`。
- 収束は合成ペルソナとローカルブラウザ証拠に対する判定であり、本番公開の証明ではない。本番はマージ後に別途readbackする。

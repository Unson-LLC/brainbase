# cycle-05 ブラウザ・オンボーディング評価契約

## 北極星

初見の利用者が、Brainbaseの用途を理解し、自分に合う導入経路を選び、既存設定を壊さず成功確認まで進める。

## 対象

- 製品面: 公開VitePressマニュアルのトップ、導入5フェーズ、準備と目的、MCP登録、Judgment Host登録
- 利用者役割: 初回個人利用者、チーム運用者、オントロジー管理者、復旧中の利用者
- 制約: ローカルファースト、Node.js 20以上、既存設定の上書き禁止、人の承認前に正本を書き換えない
- 対象外: 管理画面の新規開発、ホスト型サービス、バックエンド機能追加、実在ユーザー調査

## 全ペルソナ共通タスク

1. トップからBrainbaseで得られる価値を一文で説明する。
2. 初回導入を開始するための前提条件、最初の依頼文、実行コマンドを見つける。
3. CodexへMCPとJudgment Hostを登録する順序と、それぞれの成功確認を見つける。
4. 既存設定がある場合に上書きを避け、問題時に戻れる案内を見つける。

## ハードゲート

- 未完了を成功と表示する
- 現在地または次の操作が分からない
- 既存設定を破壊する可能性がある
- 失敗後の復旧手段がない
- AIから人への確認・引き継ぎがない
- 主要操作がキーボードまたは支援技術から到達不能

## 証拠区分

- `source_inspection`: Markdown、VitePress設定、CLI実装の確認
- `automated_test`: VitePress build、リンク・表示契約テスト
- `synthetic_browser_evaluation`: 独立ペルソナが実ブラウザを操作して得た合成評価
- `human_observation`: `not_collected`
- `real_device_evidence`: `not_collected`

支援技術属性はペルソナ判断の観点として使うが、VoiceOver、音声入力、実端末で検証していない限り実機証拠とは扱わない。

## 判定

- `adopt`: 共通して再現し、北極星またはハードゲートを直接改善する
- `defer`: 有益だが今回の公開マニュアル境界を越える
- `reject`: ペルソナ固有で、他の利用者や安全性を悪化させる
- `human_decision`: 製品方針または不可逆な公開判断が必要

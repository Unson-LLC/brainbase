# cycle-08 UX改善ループ結果

## 結論

合成ペルソナ評価では、32件すべてが10分以内にBrainbaseの価値を認識し、再利用意思を示した。

ここでいう10分はCLIの応答時間ではない。公開npm版の取得開始から、最小文脈の保存、実CodexでのBrainbase MCP利用、現実の依頼に対する具体的な回答の確認までである。最新の候補ジャーニーは129,357msだった。

## 認識された価値

利用者はAtlas導入の背景、田中さんの最終承認責務、「実測と利用者成果を分けて判断する」という基準を毎回説明し直さなくても、Brainbaseを使った実Codexから次を得られた。

- 確認済みの事実
- まだ決まっていない事項
- 次に合意すべき判断条件
- 田中さんへそのまま使える相談文

さらに中断後も、保存済み文脈を再入力せず同じ判断へ戻れた。

オントロジー管理者は、Atlas導入・田中さん・判断基準をエンティティ、関係、知識種別として点検し、正規データと投影の重複候補、関係断絶、敬称付き検索の表記ゆれを発見し、具体的な正規化案まで得られた。

## 改善ループ

Round 2では、recovery_userの1件が「中断後にも価値へ戻れる証拠がない」として`uncertain`になった。

そこで、初回回答だけでなく、中断後に実CodexがBrainbase MCPの`get_context`と`search`を再実行し、確認済み前提・未決定事項・次の相談文を返す経路を実行コーパスへ追加した。

Round 3では当初32件すべてを`recognized`と集計したが、証拠を再確認すると、オントロジー管理者1件は汎用的な判断メモに自分の専門業務との差分を見いだせず、正しくは31件が`recognized`、1件が`not_recognized`だった。集計を訂正し、収束を取り消した。

そこでRound 4では、実CodexとBrainbase MCPが保存済み文脈のエンティティ・関係・知識種別を点検し、不整合・重複・未確認・正規化案を返す実行経路を追加した。32件すべてが`recognized`、`reuse_intent=yes`となり、6つのハードゲートを通過した。

一方で、実行結果から「Atlas導入と判断基準の明示的な接続不足」「正規エンティティと投影の区別不足」「敬称付き人物名の検索正規化不足」という同系統の製品Majorを1件残した。専門ペルソナは、まさにこの問題を短時間で発見して改善案を得られることに価値を認識したため、合成価値評価は収束しているが、知識構造の改善は次サイクルへ残る。

## 証拠境界

これは固定された実行証拠を32の独立した合成ペルソナが評価した結果であり、「実在利用者32人が価値を感じた」という結果ではない。

実在利用者の観察、実機、音声入力、スクリーンリーダーなどの支援技術は`not_collected`である。ただし評価契約上、これらの未収集だけを理由に合成価値認識を失敗へ変更していない。

# 判断の種類ごとに、どこまで任せているかを見渡せる

## 利用者成果

所有者として、見返し画面を開いたとき、1件ずつの判断ではなく、判断の種類ごとに「任せている」「確かめ中」「戻している」を見たい。聞かずに進めたが自分が直した判断と、「次回は聞く」と評価した後も聞かずに進めた判断は、任せている範囲と同じ画面で目立たせたい。

## 所有と対象

- 登録・実装repo: `Unson-LLC/brainbase`
- 対象: 見返しのホーム生成（`buildJudgmentValueProofReviewHome`）、見返しのHTTP、見返し画面（`ui/value-proof-review`）

## 受入条件

- [ ] AC-01: 見返しの対象になる判断を、`decision.judgment_kind.key`ごとの行に分ける。種類が無い判断は`interruption.reason_code`ごと、どちらも無い判断は「種類の記録なし」の1行にし、種類の行の後に別の見出しで並べる。文面から種類を推定しない。
- [ ] AC-02: 行の状態を次の順に決める。行の最新の判断が人に戻したものか、行の最新の評価が「次回は聞く」「取り消し」、または任せる範囲の「訂正」なら「戻している」。行の最新の判断が聞かずに続行したもので、行の最新の評価が「採用」なら「任せている」。それ以外は「確かめ中」。状態の根拠（最新の判断か最新の評価と、その日時）を行に示す。
- [ ] AC-03: 行に、聞かずに続行・人に戻した件数、評価の内訳、訂正・取り消しの件数、引き継ぎがあった判断の件数、最新の判断日時を示す。
- [ ] AC-04: 聞かずに続行し、最新の評価が「訂正」か「取り消し」の判断を、地図の上に別の枠で示す。同じ行で「次回は聞く」の後に聞かずに続行し、採用されていない判断も別の枠で示す。
- [ ] AC-05: 記録の範囲に人の判断を待っている件数を示し、押すとその判断を含む行と判断だけに絞り込む。
- [ ] AC-06: 判断の種類も評価もまだ無い場合は、それぞれ「まだ記録されていない」と示し、空の地図や推定で埋めない。地図が欠けた応答は0件ではなく不正として扱う。

## 対象外

評価から改訂候補を作ること。行の状態に件数の条件を加えること。

## 検証と完了

行分け・状態・強調の規則は合成データの純粋関数で、HTTPは一時ディレクトリの実ファイルで、画面は簡易DOMと実ブラウザ（合成データ）で確認する。

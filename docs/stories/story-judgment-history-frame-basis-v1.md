# 判断を開くと、何を根拠に、誰の考えで判断したかが分かる

本人として、判断の履歴で1件の判断を開いたときに、Brainbaseがどの哲学・目的・世界モデルをどう使って判断したかを知りたい。また、自分の判断の材料（個人KG）が入った判断なのか、組織の記録とAIの判断だけで進めた判断なのかも知りたい。これで「Brainbaseが自分の代わりに何を判断したか」を確かめられる状態を到達点とする。

出発点は、2026-10-16 に佐藤さんが組織版の判断の履歴で指摘したこと。前提台帳の §1 問い3、P9、P11、D6（根拠の層）に当たる。

## 開発モードの決定

この変更は **EXTENSION** とする。新しい台帳・APIは作らず、既存の記録の型 `JudgmentHistoryReference` の `kind`・`usage` に決まった値を入れて運ぶ。

- 判断の枠組みの記録（`safe_metadata.judgment_frame`）には、採用した案での使い方（制約・基準・予測）と判定がすでにある。手元の読み取りは、それを捨てている。
- 個人KGの回答（`personal_answer` の事象）も同じ判断の事象の中にある。
- 組織版の公開投影の契約は、参照の `kind`・`usage` をすでに受け付ける（2026-10-16、origin/main の検証を実行して確認）。名前（label）の欄は受け付けない。そのため名前は、読み取り時に閲覧者の権限で引く。

## 受入条件

- AC-01: 判断を開いたとき、最初の区画「判断の根拠」に、使った哲学・目的・世界モデルを種類ごとに名前で出す。名前を引けないときは、「名前を確かめられません」と出す。IDで代用しない。
- AC-02: 各参照の使い方を人の言葉で出す。哲学は「守る制約」として扱い、判定（守れた・反した・ぶつかった）を添える。目的は「照らした基準」とする。世界モデルは「置いた予測」として扱い、確かめた結果（当たった・外れた・未確認）を添える。使い方の記録が無い参照には「使い方の記録なし」と出す。
- AC-03: 区画「本人の考え」で、次の3つを区別する。
  - 個人KGの材料を使った（件数を添える）
  - 使っていない
  - 記録なし
  使っていないと言えるのは、使い方の記録がある書き手の記録だけとする。古い記録や記録の無い判断は「記録なし」とし、使っていないように見せない（P9）。
- AC-04: 一覧の各行に、本人の考えの印を付ける。使った判断は目立つ印、使っていない判断と記録なしの判断は控えめな印にする。
- AC-05: 内部ID・版は、判断の「記録の詳細」の折りたたみの中に置く（#801・#812の方針）。参照を選んだ理由（`why`）は人の言葉なので、根拠の各参照の下に出す。
- AC-06: 個人KGの中身（本文・回答）は画面に出さない。出すのは使ったかどうかと件数だけとする。名前の取得は、ホストが渡す関数で、閲覧者の今の権限で行う。
- AC-07: OSSの手元の読み取りは、判断の枠組みの記録の採用案から使い方と判定を、`personal_answer`（resolved）から個人KGの参照を、決まった値で記録へ移す。
- AC-08: 組織版はこの共通UIをそのまま使う。組織版の中でコピーや作り直しをしない（P16）。

## 対象外

- unson Host が組織へ送る公開記録に `kind` と使い方を入れる変更。同じ値の約束で、後続のカードで行う。
- 組織版のホストで名前の取得関数をつなぐ変更。後続で行う。
- 個人KGの中身の表示、記録の書き換え。

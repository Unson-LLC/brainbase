# STR-012: MCPのイベントストリーム応答をマナへ返す

## 背景

マナが利用するMCP経路では、通常のJSON応答だけでなくイベントストリーム形式の応答が返る。イベントストリームを正しく扱えないと、上流では処理が成功していてもマナ側に応答が届かず、チャンネルから見た機能が消えたように見える。

## 誰が

Slackチャンネルからマナを利用する利用者と、その経路を運用する開発者。

## 何を

- MCPのイベントストリーム応答を、内容を保ったままマナへ返せる状態にする。
- 通常のJSON応答を利用する既存のMCP操作も継続して利用できる状態にする。

## なぜ

上流の応答形式に合わせて返せることで、MCPの実行結果をマナが受け取れる。これにより、Slackチャンネルからの利用が応答形式の違いだけで失敗する状態を防ぐ。

## 受け入れ基準

- [ ] MCPのイベントストリーム応答が、本文全体と応答種別を保ったままマナへ返る
- [ ] イベントストリーム応答を通常のJSON応答として解釈しない
- [ ] 通常のJSON応答を利用する既存MCP操作の挙動が維持される
- [ ] 既存の認証・テナント境界を変更しない
- [ ] 上記の応答形式を固定する回帰テストがある

## スコープ外

- MCPサーバー本体の応答生成やイベント内容の変更
- 認証・テナント認可の仕組みの変更
- 本番の秘密設定更新、配備、Slack実チャンネルでの受信確認

# 判断履歴で取得済みの参照を保ち、再読み込みを押しやすくする

## 利用者成果

判断履歴が部分取得・未接続になったとき、通知内の「再読み込み」を押せる大きさで読みやすく表示する。取得元の説明が同じ通知にある場合も、ボタンが通知の本文幅いっぱいに広がらない。

通常判断の詳細取得が待機中または失敗した場合は、一覧で取得済みの当時の参照を詳細に残す。正本の詳細取得に成功した場合は、読み戻した詳細を優先する。

## 受け入れ条件

- [ ] AC-01: `bb-jh` 内の取得通知で、直接の再読み込みボタンは内容幅で左寄せになる。通知全体や共通ボタンの幅は変更しない。
- [ ] AC-02: 本文だけの通知、本文と取得元の説明がある通知、部分取得・未接続・取得失敗の通知で、再読み込み操作を同じ契約で表示する。
- [ ] AC-03: 通常判断の詳細が待機中または取得失敗でも、同じ一覧レスポンスに含まれる参照を「使った参照（当時の記録）」へ表示する。参照が未記録なら未記録の表示を維持する。
- [ ] AC-04: 正本の詳細取得に成功した場合は詳細の参照・理由・案・実行結果を優先し、一覧の参照を詳細へ補完しない。
- [ ] AC-05: 認証、API、履歴の件数、canonical record、フィードバック保存の契約を変更しない。

## 対象

- `ui/judgment-history.css`

- 本Storyと同IDのSpec

## 検証

取得元の説明を含む通知で再読み込みボタンが通知の直接の子であること、対象画面にだけ内容幅のCSSがあることを確認する。通常判断の詳細取得を遅延・失敗させても一覧参照が表示され、成功した異なる詳細参照は正本の値へ更新されることを確認する。

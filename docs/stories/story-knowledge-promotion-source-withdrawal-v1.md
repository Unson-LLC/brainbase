# 本人が撤回した個人の記憶を、審査待ちの申請と組織のGraphから外す

## 利用者成果

- 組織で働く人として、個人KG v1の記憶を撤回したら、その記憶からの共有の申請が審査待ちのまま残らず、後から承認されて組織のGraphに入ることがないと確信したい。
- 既に組織のGraphに入った記憶を撤回したときも、それ以後の検索に出ないようにしたい。一方で、いつ誰が承認し、いつ撤回したかの記録は消えないでほしい。
- 組織のGM・CEOとして、撤回された共有を誤って承認してしまわないようにしたい。撤回と承認がほぼ同時に起きても、撤回された記憶がGraphに残らないことを確かめたい。

## 背景と決定

- 横断ADR（`brainbase-project` ADR-006「D4・D12」）は「共有の取消・権限失効は将来の取得へ反映し、過去の監査や既に発生した外部効果を無かったことにしない」と決めた。共通の昇格処理（`story-knowledge-promotion-common-v1`）は、取消をこのStoryに回した。
- 審査者は本人の原文を読めないため、組織レビューは本人が申請・承認した控えで行う。このため、本人が元の記憶を撤回しても、審査者の側からは撤回に気づけなかった。
- 2026-10-02、佐藤が選択肢カードで次を決めた。本人が、既に組織のGraphに入った記憶を撤回したときは、Graphの事実を自動で「撤回済み・検索対象外」にする。系譜・組織の知識イベント・承認の記録は消さずに残す。組織としてその事実を残したいときは、GM・CEOが組織候補（D12）として自分の権限で登録し直す。
- 撤回は本人の記憶についての本人の権利なので、組織の審査規則には諮らない。プロジェクトへの権限が失効していても、本人は撤回できる。

## 受入条件

- [ ] AC-01: 本人が元の記憶を撤回すると、その記憶からの審査待ちの申請（`pending_owner_approval`・`pending_org_review`）は「取消済み」（`source_withdrawn`）になり、以後は本人承認も組織レビューも受け付けない（`knowledge_promotion_source_withdrawn`、409）。
- [ ] AC-02: 撤回の時点で組織のGraphに入っていた申請（`org_accepted`）は、Graphの事実を「撤回済み・検索対象外」にしてから「取消済み」にする。Graphの取り下げに失敗したら、撤回ごと戻して失敗を返す。
- [ ] AC-03: 取消は、まだ撤回されていない記憶や、本人以外・別組織の記憶には行えない。サービス主体は取り消せない。組織の審査規則には諮らず、プロジェクトの権限が無くなった本人でも取り消せる。
- [ ] AC-04: 取消ごとに、取消前の状態、Graphの取り下げの有無、取り消した人、元の記憶の版、理由を、追記のみの取消の記録に残す。承認の系譜・組織の知識イベント・受領記録は書き換えない。
- [ ] AC-05: 撤回と承認が重なったとき、どちらが先に確定しても、撤回された記憶は最後にGraphで検索対象外になる。撤回が先なら承認は拒否され、承認が先ならその直後の撤回でGraphから取り下げる。
- [ ] AC-06: 取消は呼び出し側のトランザクションの中でも実行でき、撤回の記録と取消を同時に確定できる。同じ撤回の再試行では、二重に記録しない。
- [ ] AC-07: 却下済み・古い版・取消済みの申請は、取消の対象にしない。

## 対象外

- 個人KG v1の撤回の操作そのもの（記憶の状態を「撤回済み」にする記録）。保存先と経路を持つ組立て側（`brainbase-unson`）が作り、その同じトランザクションの中でこの取消を呼ぶ。
- 撤回でなく内容を直したとき（`superseded`）の扱い。承認の直前の版の確認（既存のAC-06）で「古い版」として止める。
- 組織候補（D12）の元の候補の撤回。審査者は候補を直接読めるため、承認の直前の確認で止まる。
- 撤回されたGraphの事実の物理削除と、組織候補としての登録し直し。
- 本番への配備。

# 主ボタンが目立ち、薄い文字が読め、画面全体の失敗の理由が最初から見える

利用者として、受信箱でいちばん重い操作（「承認して送る」など）を迷わず見つけ、パンくずや「期限切れ」の札を読み、受信箱を読めなかったときはその理由をすぐ知りたい。

10/29に impeccable の `critique` の手順で受信箱を点検し、次の3点が分かった。

- 共通の主ボタン（`.bb-ws-button.is-primary`）の背景と枠が `--bb-color-rail`（今は白）になっている。9/27に組織版の古い値を写したとき、当時は濃い色だった rail を使ったためで、組織版が今使っている主ボタンは `--bb-color-accent` の地に白い文字。白いカードの上では主ボタンが枠の無い太字に見え、普通のボタンより弱く見える。「人と会社」の画面は、同じ色を画面のCSSで上書きして避けていた。
- パンくず（`--bb-color-quiet` #76767f、背景 #f6f6f8）は 4.17:1、受信箱の「期限切れ」の札（`--bb-color-danger` #d92335、背景 #fde9eb）は 4.25:1 で、11〜12px の文字に要る 4.5:1 に届かない。
- 受信箱を読めなかったときのカード（`workspaceErrorCard`）は、理由を閉じた `<details>` に入れている。「0件ではありません」が、開かないと読めない。

## 開発モードの決定

この変更は **EXTENSION** とする。トークンの値は変えない（値の正本は組織版のデザイン、前提台帳D8）。主ボタン・パンくず・期限切れの札が使うトークンを、既にある別のトークンへ替える。`workspaceErrorCard` は既定を閉じたまま残し、開いた状態で置く `open` を足す。閉じた通知として使っている画面（目的と現状・判断の履歴・記憶）の見た目は変えない。

## 受入条件

- AC-01: `.bb-ws-button.is-primary` は `--bb-color-action` の地と枠、`--bb-color-action-text` の文字、hover は `--bb-color-action-hover` で描く（白に対して 6.1:1、hover は 8.2:1）。「人と会社」の画面にあった同じ上書きは消す。
- AC-02: パンくず（`.bb-ws-breadcrumb`）の文字は `--bb-color-muted` で描く（背景 #f6f6f8 に対して 4.89:1）。区切りの色は変えない。
- AC-03: 受信箱の「期限切れ」の札（`.bb-inbox-due.is-expired`）の文字は `--bb-color-inline-error` で描く（背景 #fde9eb に対して 5.76:1）。背景は変えない。
- AC-04: `workspaceErrorCard` に `open: true` を渡すと、最初から開いた状態で置き、理由を読める。渡さないときは今のとおり閉じている。
- AC-05: 受信箱は、全体を読めなかったときと、お知らせを読めなかったときのカードを開いた状態で置く。

## 対象外

- トークンの値の変更と、組織版への取り込み。組織版の独自の `.breadcrumb` も同じ `--quiet` を使っているので、組織版の側で直す。
- 失敗のカードの再試行ボタンの大きさ、暗い色の通知という見た目。目的と現状の画面の通知として作られた部品なので、変えるなら持ち主と決める。
- 点検で出たほかの指摘（操作後のフォーカス、行の中の結果の知らせ、スマホの押す場所の大きさ、今日の画面の区画名）。

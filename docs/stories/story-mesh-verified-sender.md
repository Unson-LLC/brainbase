# Mesh送信者の本人確認と認可（後続・未着手）

利用者として、ローカル文脈を開示する前に、誰のどの権限で問い合わせられたかを検証できるようにしたい。

## 起点

[境界整理](story-brainbase-boundary-cleanup.md)で受信者自身の権限を送信者へ渡す不具合を閉じた。現在は送信者の本人確認がない受信queryを拒否する。sealed-box暗号化、自己申告nodeId、relayが送るroleだけでは本人確認にならない。

## 別途設計・承認が必要な受入条件

- 組織と本人に結び付いた信頼できる鍵登録・失効経路を定義する。
- 送信前にも宛先本人と暗号化鍵の結び付きを検証する。relayによる公開鍵の差し替えを信頼せず、未確認なら本文を送らない。
- 署名または同等の仕組みで送信者・宛先・本文・再送条件を検証する。
- 検証済み本人の組織・project権限を正本で確認し、失効や不明時に開示しない。
- 改ざん・なりすまし・別組織・再送・失効の否定テストを通す。

今回の変更はこの機能の実装・外部送信・本番再開を含まない。

# 目的と現状の行を押すと、その目的でできることが分かり、「確認待ち」は誰の何を待っているかで出る

## 利用者成果

「目的と現状」を開いた本人として、目的の行を押したら、その目的で何ができるのか（直す・現状を記録する）、できないならなぜかが分かりたい。一覧の「確認待ち」が、誰の何を待っているのかを読んで分かりたい。

## 背景

- 2026-10-16、佐藤が組織版の「目的と現状」で指摘した（UX点検 7-7・7-8）。目的の行を押しても何もできず、何をすればいいか分からない。「確認待ち」が何を待っているのか分からない。
- 共通コア（develop `b6f9bf66e`）で再現した原因:
  - 組織版の一覧は `renderFoundationCollectionOverview`（読み取り専用）で描く。行を押すと詳細の対話窓が開くが、中身は達成条件・確認の根拠・出典だけで、操作も「ここでは直せない」という説明もない。直す画面（`objective-editor.js`）は、組織版ではプロジェクトを選んだうえで「目的を詳しく確認・編集」を開いたときだけ出る。
  - 「確認待ち」の欄は、記録の `current_state.missing`（保存時点で未確認と書かれた項目）か、未記録の欄（目指す状態・評価基準・評価期間・責任者・記録上の現状）を並べるだけで、誰を待っているかは出ない。本番の組織の目的のうち13件は `current_state.missing` が「評価期間の確定・評価者・計測方法・実績」、責任者（`accountableId`）は全件未記録（2026-10-16、`/api/foundation/catalog` を読み取り専用で確認）。
- 前提台帳 P12（哲学・目的・現状は必要な時だけ出す）は変えない。言葉と操作の直しに留める。P9（推測で埋めない）、P16・D8（直しはOSSの共通UIで行い、組織版は渡すだけ）。

## 受入条件

- [x] AC-01: 一覧の欄「確認待ち」を「待っていること」にし、何を待っているか（「未確認：…」＝保存時点で未確認と記録された項目、「未記録：…」＝記録されていない欄）と、誰を待っているか（責任者が記録されていれば「責任者の確認待ち」、無ければ「責任者が未記録のため、確かめる人が決まっていません」）を出す。どちらも目的の記録からだけ出す。
- [x] AC-02: 行を押して開く詳細の先頭に「待っていること（何を・誰が）」と「この目的でできること」を出す。
- [x] AC-03: ホストが `callbacks.objectiveAction(context)` で直す行き先を渡したときは、「目的を直す・現状を記録する ›」のボタンを出し、押すと詳細を閉じてホストの行き先へ進む。`context` は目的のID・版・題名・読み込んだプロジェクト（`scopeIds`）と記録。
- [x] AC-04: ホストが直せない理由（`{ unavailable }`）を渡したときはその理由を、何も渡さないときは「この画面は読むだけです。ここからは記録を変えられません。」を出し、押しても何も起きないボタンを出さない。
- [x] AC-05: 一覧の下に、行を押すと何が開くか（操作があるときは「この目的でできること（直す・現状を記録する）」、無いときは「この画面は読むだけです」）を出す。

## 検証

- 試験: `tests/ui/foundation-objective-actions.test.mjs`（3件。変更前のコードでは3件とも落ちる）。既存の `foundation-overview.test.mjs` は変更なしで合格。
- 実ブラウザ（Chrome、1440×900）: 本番の目的の記録の形（`current_state.missing` あり2件・現状なし1件、題名と目指す状態は見本に置換）を、変更前と変更後の `renderFoundationCollectionOverview` で描き、行を押した。
  - 変更前: 欄名「確認待ち」、値「評価期間の確定・評価者・計測方法・実績」だけ。行を押すと達成条件から始まる対話窓で、操作も説明もない。
  - 変更後: 欄名「待っていること」、値「未確認：評価期間の確定・評価者・計測方法・実績」「責任者が未記録のため、確かめる人が決まっていません」。行を押すと先頭に「待っていること」と「この目的でできること」。行き先が渡されたとき・権限がないとき・何も渡されないときの3通りを確認した。
- 画像は組織の記録の一部（評価基準の変数名）が写るため、OSSのリポジトリには置かない。

## 組織版への取り込み

組織版が `callbacks.objectiveAction` を渡すまで、組織版の対話窓は「この画面は読むだけです」と出す（嘘にはならないが、直す画面へは進めない）。取り込みでは `apps/web/public/company-os.js` の `loadFoundationOverview` の `callbacks` に、`context.scopeIds[0]` を `canEditScope` で確かめ、編集できるならそのプロジェクトを選んで「目的を詳しく確認・編集」を開く行き先を、できないなら `{ unavailable: 'このプロジェクトの目的を保存する権限がありません。' }` を返す関数を足す。

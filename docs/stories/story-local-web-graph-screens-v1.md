# ローカルWebで「プロジェクトと関係者」「情報と関係」を確かめ、理由つきで直せる

## 利用者成果

単独所有者として、`brainbase web:serve`で開いたブラウザで、どのプロジェクトに誰がどう関わっているか（関係者）と、手元のGraphに何がどう登録されているかを確かめたい。誤りを見つけたら、その場で1文の理由を書いて直し、直した内容が次のMCPの`search`・`get_context`・`resolve_entity`で使われることを確かめたい。Graphがv1のときや読み取れないときに、0件と見誤りたくない。

## 所有と対象

- 登録・実装repo: `Unson-LLC/brainbase`
- 情報契約: brainbase-project `docs/architecture/oss-personal-web-v1-remaining-screens-contract.md`（§1のナビ、§3、§4の1〜4、§5、§6、§9の4・5・6・8。単位W4とW5）
- 対象: ローカルWebホストのGraphの経路（`src/local-web-host.ts`の`createGraphWebModule`。読み取りと訂正の処理は既存の`src/graph-web-http.ts`）、上位ナビ（`ui/local-web-shell.js`）、共通UI部品（`ui/graph-view-shared`、`ui/graph-projects-view`、`ui/graph-registry-view`）

組織、メンバー、役割、承認、外部サービスを必須にしない。組織のGraph（C1、単位W6）は扱わず、その欄の仮置きも出さない。

## 受入条件

- [ ] AC-01: 上のナビに「今日」「目的と現状」の後ろへ「プロジェクトと関係者」「情報と関係」をこの順で出す。2画面はホストがGraph v2と報告したときだけ中身を出し、v1なら画面名を添えて移行のコマンドを出す。`web:serve`は2画面のURLも表示する。
- [ ] AC-02: ホストは`/api/graph`の読み取りと訂正を、ホストが決めたデータの場所に対して配線する。Hostがループバックの名前と待ち受け中のポートの組でない要求は断る。訂正は起動ごとのトークンと同一オリジンを、ホストの確認に加えてGraphの経路の中でも確かめ、どちらかが無ければ何も書かない。
- [ ] AC-03: 「プロジェクトと関係者」は、プロジェクトの一覧（名前、状態、目的、関係者の数、有効期間）と、詳細（目的、状態、判断の原則、関係者の表：人物、関わり方〈参加・責任〉、役割、有効期間、出典の種類）を出す。表示語は「関係者」とし、ログインや共有の設定と誤読させない。RACIの型は出さない。
- [ ] AC-04: 関係者を加える（参加・責任、役割と開始日は任意）、役割と文脈を直す、関わりを終える（終了日。既定は今日）、プロジェクトの名前・目的・状態を直す、ができる。削除はしない。
- [ ] AC-05: 「情報と関係」は、名前・別名で探し、種類と有効時点で絞れる。対象の詳細は、種類、名前、別名、要約、有効期間と、出る関係・入る関係（関係の意味、役割、有効期間、出典の種類、手元の候補・オンボーディング・訂正の記録を指す出典はその記録、指さない出典は元のIDに「未解決」）を出す。相手の名前から、その記録へたどれる。
- [ ] AC-06: 訂正はどれも1文の理由を必須にし、表示した記録のダイジェストを送り、利用者が変えた項目だけを送る。競合したときは今の内容を示し、入力を残し、次の保存は今の内容を元にする。保存したときは読み直した値と、次のMCPの`search`・`get_context`・`resolve_entity`で使われることを示す。
- [ ] AC-07: 情報の種類とつながり方（関係の種類ごとの起点と終点の種類、意味、件数と有効な件数、情報の種類ごとの件数）を読み取りだけで出す。変更案の提出は置かない。
- [ ] AC-08: Graph v1は両方のコマンドつきで「移行が必要」、データが無いときは始め方、読み取りの失敗は理由と再試行、一部の記録が読めないときは読めた記録と読めない件数・理由を分けて出す。空と表示するのは正本が空と確認できたときだけとする。IDやダイジェストは「記録の詳細」の中だけに出す。
- [ ] AC-09: 新しい部品は、共通の見た目の定義（`ui/brainbase-tokens.css`の`--bb-*`）だけで色・文字・余白を決め、幅375pxで横にスクロールしない。

## 対象外

組織のGraph（C1）の欄。Ontologyの変更案の提出。RACIの型。記録と関係の削除、IDと種類と関係の種類の変更。取り込み候補やオンボーディングの記録そのものをWebで開くこと（出典として、ファイルと候補を示すところまで）。

## 検証と完了

ホストの経路は一時ディレクトリの合成データ（Graph v2とv1）で実際のホストを通して、部品は簡易DOMと実際のGraphの処理の組み合わせで確かめる。実ブラウザ（幅375pxを含む）で、今日から目的と現状、プロジェクトと関係者（関係者の追加、役割の訂正と競合、関わりの終了）、情報と関係（検索、対象、関係をたどる、出典、情報の種類）へ移り、Graph v1で移行が必要と出ることを確かめる。

# 都市の中に仕事の現場を置き、業務の状態と「把握できていないこと」を分けて読めるようにする

## 利用者成果

佐藤さんが世界を開くと、全タスクや本文を順に読まなくても、次が分かる。

- どの事業（都市）に、記録の上で未完了の仕事がどれだけあり、どこに「把握できていないこと」があるか。
- 都市に降りると、その事業の目的・方針、仕事の現場、担当・関係者、事業をまたぐ関係が同じ街の中で読める。
- 現場を選ぶと、分かっている事実、未接続・未確認の対象と範囲、出典と確認時点、次に何を確認すれば見通しがよくなるかが読める。
- 戻ると、元の都市・選択・縮尺のまま全体の中に位置づけられる。

## 背景

世界（P17）は事業を都市、案件を区画として描くが、都市の内側の仕事・人・判断・成果へのつながりが無かった。2026-10-06に、組織版のある顧客案件を実データで調べると、世界では「案件0・決定0」の都市だが、実際はタスクが30件以上あり、担当欄は全件空、出典リンクは大半が0件、待ちの多くは見直し予定を過ぎて更新が無かった。本文に組織Graphの人物IDがあるのに担当欄が空の仕事、本文に完了条件があるのに成果物・提示の記録へのリンクが無い仕事もあった。その案件に関する決定は親の事業の範囲コードで記録され、案件との関係は構造化されていなかった。

これらは本文を読んで初めて気づく。街の上で「どこでつながりが切れているか」が分かること自体に運営上の価値がある（佐藤さんの依頼、2026-10-06）。

## 縮尺と実データの対応

| 縮尺 | 街の表現 | 実データ（正本） |
|---|---|---|
| 世界 | 都市の並び | 組織Graphの事業（プロジェクト記録） |
| 都市 | 目印の建物・区画の家 | 事業とその案件（既存） |
| 現場 | 都市の外周の小さな建物 | その事業・案件のコードを持つCanonical Task（Task API）。Story・Run・Initiativeとは同一視しない |
| 現場の詳細 | 右の欄 | タスクの記録・本文中の人物ID・出典リンク・Graphの関係と決定 |

## 業務の状態と把握の状態

- **業務の状態（A）**: タスクの記録の `status` をそのまま「記録上」として出す（未着手・進行中・待ち・完了・取消）。待ちの理由は `waiting_on` の原文。原文を分類して「停止」とは言わない。
- **把握の状態（B）**: 構造化された欄だけから決定論的に出す。
  - 担当欄が空で、本文に組織Graphの人物（IDか氏名）がある → 「担当欄に未接続（本文に人物あり）」。本文の人物は推定の関係として示す。
  - 担当欄が空で、本文にも人物が見つからない → 「担当の記録なし」。「担当者不在」とは言わない。
  - 出典リンクが0件 → 「出典リンクなし」。
  - 本文に完了条件があり、出典リンクが0件 → 「完了条件はあるが成果物・提示の記録が未接続」。
  - 見直し予定日を過ぎても未完了 → 「見直し予定を過ぎた（古い情報の可能性）」。
- 読めなかったもの（取得失敗・権限外・未接続・一部だけ読めた）は件数0や問題なしにしない。

## 受入条件

- [ ] AC-01: `projectWorldWork` が、ある事業のタスク・人物・決定・Graphの関係から、現場（タスクごとの業務の状態Aと把握の状態B）、目的と方針、人と関係、事業の要約を返す。各項目に出典（取得元・対象ID・欄）と時点を持つ。
- [ ] AC-02: 把握の状態は上の5種類を構造化された欄から出す。本文に人物がいるのに担当欄が空のタスクを「担当なし」と同じにしない。証拠が無いことから「止まっている」と言わない。
- [ ] AC-03: 関係は「記録された関係（Graphの辺・担当欄・統合記録の出典決定）」「本文や名前から推定した関係」「読めなかった関係」に分け、同じ種類として返さない。
- [ ] AC-04: `summarizeWorldWork` が事業ごとに、未完了の件数、記録上の状態の内訳、把握の状態の種類ごとの件数と、その件数を生んだタスクIDを返す。読めなかった事業は理由つきの状態で返し、0件と区別する。
- [ ] AC-05: 世界は要約を読んで、把握できていない仕事がある都市に「確認が必要」の印を、仕事を読めない都市に別の印を出す。件数から危険度や進捗の点数は作らない。
- [ ] AC-06: 都市を選ぶと、その事業の現場だけを読み込み、外周に仕事の建物を置く。置き場所はタスクIDから決まり、再取得や状態の変化では動かない。
- [ ] AC-07: 右の欄は、事実（目的・方針、記録上の状態）→ 把握できていないこと → 人と関係 → 出典と時点の順に並べる。把握の状態の種類を選ぶと、その件数を生んだ仕事の一覧と街の中の位置が出る。
- [ ] AC-08: 現場を選ぶと、分かっている事実・未接続/未確認の対象と範囲・出典と確認時点・次に確認することが読め、ホストが渡せばタスク画面で開ける（直した結果はタスクの正本に保存され、世界は再読み込みで反映）。
- [ ] AC-09: 戻る・Escは一つ上の縮尺へ戻り、選んでいた都市の選択を保つ。選択（都市・現場）はURLに残り、別画面から戻っても同じ場所が開く。
- [ ] AC-10: タスクの正本を持たないホスト（OSS Personal）では、現場の層を「未接続」と出し、都市は従来どおり描く。

## 区画に入る（2026-10-06 追加、佐藤さん選択B）

佐藤さんの評価：「街の区画に入るイメージではない。もうちょっと街っぽさがあるとワクワクする」。上から眺める地図に札を貼った管理画面ではなく、歩いて入れる街で、異変が街の様子として見えることを求めた。記録に無い暮らしの演出（歩く人・煙）も入れる案Bを、「進んでいないのに進んでいるように見える」おそれを承知で選んだ。

- [ ] AC-11: 都市を開くと、外の世界から区画の中へ切り替わる（別の縮尺。斜めから見下ろす透視の視点、門・大通り・裏通り・庁舎前の広場）。Escと「全体に戻る」で世界へ戻り、選んでいた都市は保たれる。
- [ ] AC-12: 仕事は通りに面した区画に建つ。置き場所はタスクIDと作成順で決まり、状態の変化では動かない。形は記録上の状態で決まる（未着手＝杭と縄の空き地、進行中＝足場と緑のネット、待ち＝灰色の覆い、完了＝明かりのついた家）。
- [ ] AC-13: 断絶は札ではなく街の現象で見える。担当欄が空＝誰もいない現場、担当欄の人＝ヘルメットの作業員、本文にだけいる人＝柵の外に立つ人（足元に破線の輪）、出典リンクなし＝通りへの道が無い区画、完了条件はあるが成果物の記録なし＝図面の看板だけ、見直し予定を過ぎた＝雑草と色あせ、仕事を読めない＝霧。
- [ ] AC-14: 方針の決定は庁舎前の石碑（記録＝石、題名の一致による推定＝枠だけの石碑）、ほかの事業への関係は門の外の道しるべ（記録＝実線、推定＝破線）。
- [ ] AC-15: 通りを歩く人と煙は街の雰囲気で、記録とは関係しないことを凡例に書く。歩く人は仕事の区画に入らない。動きを減らす設定では止まる。

## 何のための仕事かで通りを分ける（2026-10-06 追加）

佐藤さんの評価：「どの建物が何を指しているのかを、街がゴチャつかないように表示したい」「プロジェクトより細かい意味づけで管理できていないのが大きな問題」。施策の記録・承認手順・確信度は作らず、タスクに「何のための仕事か」を短い言葉で1つ付け（AIが既存の言葉を優先して付け、人は間違いだけ直す）、街はその言葉ごとに通りを作る、というシンプルな形を選んだ。言葉はタスクの正本の欄（`purpose_label`）に置き、世界は投影するだけ。

- [ ] AC-16: 区画の中の仕事は、タスクの `purpose_label` が同じものを同じ通り（街区）に並べる。街区の入口には通りの名前の看板を立て、言葉と件数を出す。言葉の無い仕事は門の近くの「未分類の空き地」にまとめ、言葉が無いことを看板で示す（分類を推測で補わない）。
- [ ] AC-17: 街区は、その言葉の仕事のうち最も古い作成日時の順に庁舎側から並ぶ。街区の中の区画は作成順に埋まり、新しい仕事が古い仕事を動かさない。言葉を変えた仕事だけが別の街区へ移る。
- [ ] AC-18: 建物の名前は近づいたときだけ出し、遠くからは通りの看板だけが読める（名前の札で街がゴチャつかない）。

## 区画の入口が分かる（2026-10-06 追加）

佐藤さんの評価：「どこをクリックしたら街に入れるのかがあんまりわからない」。都市の名札は押せそうに見えて押せず、右の欄は「選ぶとここに出ます」だけで入口が無かった。

- [ ] AC-19: 何も選んでいないとき、右の欄に事業ごとの「区画に入る」ボタンを並べる。要確認の件数・仕事を読めない・一部だけ読めた、をボタンの横に出し、要確認の多い順に並べる（件数は点数ではなく並び順の手がかり）。
- [ ] AC-20: 都市の名札を押しても区画に入れる。名札や建物にマウスを乗せると「区画に入る ›」と出る。案件から開いたときのボタンも「〇〇の区画に入る」にする。

## 区画の中の完成度を全体図にそろえる（2026-10-06 追加）

佐藤さんの評価：「街に入ったところの完成度も全体図と同じようにあげてください」。

- [ ] AC-21: 区画の中は全体図と同じ景色の部品（時刻で変わる空・太陽と補助光・まだらな芝・角の丸い敷地・歩道と中央線のある道路・街灯・針葉樹と広葉樹・窓の描かれた外壁と夜の窓明かり）で描く。全体図の「空」ボタンは区画にも効く。意味を持つ形（足場とネット・ブルーシート・杭と縄・明かりのついた家・人・図面の看板・雑草と色あせ・霧・通りの看板）は変えない。景色の部品は全体図と区画で共有する（`world-scenery.js`）。

## 対象外

- 待ちの理由（自由文）の分類、総合スコア、新しいタスクの自動生成。
- 成果物・顧客合意などの新しい記録欄の追加（Task契約の変更）。不足は「追加データが必要」として示すだけ。
- 判断（value proof）の現場への配置。

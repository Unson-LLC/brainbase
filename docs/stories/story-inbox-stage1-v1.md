# 自分が動かないと止まるものを、受信箱の1か所で見渡し、その場で片付けられる

利用者として、自分が動かないと止まるもの（答える・承認する・振り分ける・取り込む・タスク）を、1つの画面で見渡したい。今は世界の待っている一覧、タスク、振り分け待ち、取り込み待ち、Slack（Mana）の知らせに分かれていて、どこを見れば全部なのかが分からない。受信箱を開けば、自分宛ての待っているものが、することごとに並び、読めなかった種類も分かる状態を到達点とする。

画面の前提は、brainbase-project の前提台帳 D16（受信箱）と D10（左メニュー、2026-10-17改訂）に置く。この Story は D16 の段1のうち、OSSの共通UIの部品を作る。集約のAPIと左メニューへの組み込みは組織版の Story（`story-organization-inbox-stage1-v1`）で行う。

## 開発モードの決定

この変更は **EXTENSION** とする。新しい正本は作らない。部品は待っているものを自分で取りに行かず、ホストが渡す読み手（port）から受け取る。片付けた・あとでの状態もホストが持つ（D16「受信箱が正本」）。組織版はこの部品を組み込み、作り直さない（P16、D8）。

## 受入条件

- AC-01: 画面の上に「対応待ち」と「お知らせ」の2つのタブを置く。同じ受信箱の2つの切り口なので、タブにする（D10「タブは同じものを違う面から見るときだけ」）。開いたタブはアドレスに残す。
- AC-02: 対応待ちは、することごとに「答える・決める」「承認する」「振り分ける・取り込む」「タスク」の順に区画を分けて並べる。行の無い区画は出さない。
- AC-03: 区画の中は、他の人やAIを止めているものを先にし、次に期限の近いもの、最後に届いた新しいものの順に並べる。
- AC-04: 行は、題名・1行の説明・届いた時刻・期限・止めている印を出し、押すと元の画面（ホストが渡すアドレス）へ移る。ホストが行にボタン（その場で決める操作）を付けたときは、行の中に出し、押すとホストの操作を呼ぶ。書き込みの経路は部品に持たせない。
- AC-05: 行に「あとで」を置く。選んだ時刻（今日の夕方・明日の朝・来週の月曜の朝）まで対応待ちから隠し、時刻を過ぎたら戻す。隠している件数は「あとで N件」で開ける。
- AC-06: 行に「片付けた」を置く。押した行は「片付けた」に移し、後から開いて戻せる。行の中身が変わったとき（新しい件数・新しい版）は、片付けた・あとでを解き、対応待ちへ戻す。
- AC-07: 待っているものは、種類ごとに読む。読めなかった種類は、その区画に「〈種類〉を読めませんでした」と理由を出し、0件に見せない。読めた種類が0件のときだけ「待っているものはありません」と出す。
- AC-08: まだ集めていない種類（ホストが名前を渡す）があるときは、対応待ちの下に1行で「まだ集めていない種類があります」と名前を添えて出し、件数に数えない。接続の無い種類は「未接続」と出す。
- AC-09: お知らせは、ホストが読み手を渡さないときは「お知らせはまだ集めていません」と出し、0件と見せない。
- AC-10: 左メニューに付ける対応待ちの件数を、部品と同じ規則（隠したもの・片付けたものを除き、読めた種類だけ）で数える関数を出す。読めなかった種類があることも返す。
- AC-11: 読み込みの途中は前の表示を保ち、全体が読めなかったときは理由と再試行を出す。
- AC-12: 部品は ui/ に置き、Personal Web と組織版の両方が組み込める形にする。待っているものの本文をアドレスに載せない。

## 対象外

- 集約のAPIと、左メニューへの組み込み（組織版の Story で行う）。
- Personal Web の左メニューへの組み込み。Personal Web の左メニューの並べ直し（OSS #830）が入った後に、手元で読める種類（取り込み待ちなど）を決めて足す。
- お知らせの中身、Slack との片付けの同期、朝のまとめ、AIまわりの種類（D16 段2〜4）。

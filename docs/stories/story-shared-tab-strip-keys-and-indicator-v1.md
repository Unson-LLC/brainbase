# 共通のタブを矢印キーで切り替えられ、選んだ印がすべって移る

利用者として、受信箱やプロジェクトの記録のタブを、マウスを使わずに矢印キーで切り替えたい。今の共通のタブ（`workspaceTabList`、#883）は見た目だけをそろえる部品で、矢印キーで隣のタブへ移る操作はどの画面にも無い。選んだ印（下線）も、選び直すたびにその場で付け替わるだけで、どこからどこへ移ったのかが目に入りにくい。

AffectUI（MIT）の segmented-control の操作と動きを参考にし、共通UIの書き方（素の ES module と CSS、トークン）で書き移す。コードは写さない。

## 開発モードの決定

この変更は **EXTENSION** とする。`workspaceTabList` と、その見た目の契約（#883）は変えない。使う画面が選んだときだけ付ける `workspaceTabStrip` を足す。どのタブを選ぶかの正本は、今までどおり各画面の click の処理に置く。

## 受入条件

- AC-01: 画面が `workspaceTabStrip` を呼んだ帯だけが変わる。`workspaceTabList` だけを呼んだ帯と、呼んでいない帯は今のまま。
- AC-02: `role="tab"` のタブの上で、← と → は前と次のタブへ移って選ぶ。端では反対の端へ回る。Home と End は最初と最後のタブへ移って選ぶ。選ぶのは、そのタブの既存の click の処理を呼ぶことで行う。隠れたタブと押せないタブは飛ばす。修飾キーと組み合わせたときは何もしない。
- AC-03: Tab キーで帯に入ると、選んでいるタブに止まる（選んでいるタブだけ `tabindex="0"`、ほかは `-1`）。
- AC-04: キーで選んだ後に画面が帯を作り直しても、フォーカスは新しい帯の選んでいるタブへ戻る。帯が横にはみ出すときは、そのタブが見える位置まで送る。利用者がほかの場所へフォーカスを移していたときは、戻さない。
- AC-05: 選んだ印は、前のタブから選んだタブへすべって移る。画面が帯を作り直しても、同じ名前（`memoryKey`）の帯は前の位置からすべる。
- AC-06: 動きを抑える設定では、印はすべらずに移る。タブの位置を測れないとき（隠れている・まだ画面に無い）は、今までどおり各タブの下線で示す。
- AC-07: 受信箱、情報の「種類」、プロジェクトの記録の3つのタブに付ける。左メニューの画面のリンク（`area-nav`）は、ページの移動でキー操作の型が違うので付けない。

## 対象外

- 組織版への取り込みと npm の公開。
- つまみのドラッグ、選んだときに太字になっても幅が変わらない工夫、見本帳（`brainbase-ui-catalog`）の部品一覧の更新。
- 一覧の表示切替（タスクの一覧・かんばん・ガント）。#883 と同じく対象にしない。

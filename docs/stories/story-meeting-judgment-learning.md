# 議事録の判断と訂正を記憶循環へつなぐ

## 利用者価値
議事録の固有名詞が誤ったとき、実際にどの根拠を取得し、どの判断を経て生成したかを追える。訂正から検索・判断・実装の改善箇所を絞り、同じ誤りの再発を検証できる。

## 開発方針
SIMPLIFICATION。既存のcontext receipt、実行状態、Run Receipt、知識イベント、おやすみ・レトロを接続する。別の監査専用DAGや議事録専用夜間ジョブは増やさない。直近の会議Graph Playbook、stage resume、記憶循環の実装を照合すると、通信の証跡と品質判断が分離しており、実際の判断過程が夜の改善入力になっていなかった。

## 受け入れ条件
1. 実行時にDAGの版・ノード・根拠・結果・未解決を保存し、未実行を完了にしない。
2. 案件と発言の文脈に基づいて固有名詞の候補を取得し、無関係なdecisionによる用語の欠落を防ぐ。
3. 生成・配信の成功と品質の確認状態を分け、根拠のない固有名詞補正を確定しない。
4. 実行と訂正を既存Brainbaseの記録に結び、おやすみで照合・圧縮・検索確認する。
5. レトロの改善案を原因ノード・根拠へ結び、再検証の証拠なしに問題を閉じない。
6. tenant/project境界を保持し、夜間ルーティンは外部再収集や本番ポリシーの自動変更を行わない。

## 確認済みの失敗例
2026-09-14配信の会議議事録ではBrainbase context receiptにproject 4、decision 71、document 5が入り、glossary/personは0だった。原文の「アイテム」等が「AIde」へ変換された。保存・配信成功だけでは用語判断の正しさを示さない。

## 完了境界
コードとローカル統合テスト、レビュー、通常のPRまでを実装成果とする。本番反映と実会議での品質改善は別の確認状態として保持する。過去の実行に存在しない判断履歴を後付けで生成しない。

# Story: Taskのゴールと完了条件を共通APIで保持する

状態: Developに実装済み（PR #720）。0.23.7の公開準備中。

利用者として、Taskに最終成果と確認すべき条件を保存し、成果提出時に同じ条件IDを参照したい。作業量や自己申告を完了条件の代わりにしないための、共通データ契約を用意する。

## 受入条件

1. 任意の `completion_contract` にゴールと一意な条件ID・条件本文を保持する。
2. Taskの作成・取得・更新・一覧で値を維持し、既存のversion/CAS・冪等性・監査を再利用する。
3. 未設定の既存Taskを維持し、不正・空・重複・過大な契約を拒否する。
4. 契約の保存を条件達成や人間受入の証拠と扱わない。
5. Organizationの認証・委任・審査と保存先DB移行を公開kernelへ持ち込まない。

## 全体ゴールとの関係

本Storyは「成果に進まない小作業の反復を止める」ための前提の一部である。後続の条件別証拠・contract版との対応・完了ゲート、Task必須結合、停滞時の質問や方針変更、予算制御、本人による成果評価は未達成のまま残る。

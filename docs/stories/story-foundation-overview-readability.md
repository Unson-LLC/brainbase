# Purpose overview and native scrollbars

The purpose overview should let a reader see the recorded state, outstanding checks and check date before opening a purpose. Selecting a row opens a shared native dialog containing achievement conditions, supporting records and provenance. Philosophy starts expanded at full width; world models start folded. Explanations belong in small shared help controls above the trigger.

Errors stay distinct from confirmed absence. Hosts may receive notification descriptors with the original message and retry callback; a partial catalog must still disclose its incomplete coverage. Owner-private objectives remain separate and read-only, with bundle provenance available in optional details.

Native scrollbar thumbs appear faintly during scrolling, then fade after inactivity. Scrolling, keyboard input and browser tracks remain native. Reduced motion and forced colors retain their existing accessibility behavior.

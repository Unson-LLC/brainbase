# 概要を理解し、次の確認から根拠へ進める

利用者はプロジェクト概要で、何のプロジェクトか、次に何を確認するか、どの資料が根拠かを順に把握する。案件ごとの情報はホストが認可済みの正本から投影し、共通UIは案件名や個人の世界モデルを固定しない。

## 受入条件

- AC-01: ホストの概要投影がある場合、概要は「このプロジェクトについて」「次に確認すること」「{プロジェクト名}に直接紐づく資料」「関連資料」の順で表示する。
- AC-02: サービスの定義、責任者、最終決裁、現在の目標は別項目。未確認を推定値で埋めない。
- AC-03: 直接資料と関連資料は分離する。本文取得状態、出典、内容時点と記録更新時点を区別し、未取得を不在や0件に変えない。
- AC-04: 資料行から同じ正本IDの既存Graph詳細へ進める。本文は概要に全展開しない。
- AC-05: 投影未接続のホストは既存の概要動作を維持する。ホストの接続先表示、Graph権限、既存のタブと詳細導線を保持する。
- AC-06: 不正な文字列・未認可の値を補って表示せず、安全なDOMテキストで表示する。狭幅では表を崩さず読める。

## 境界

ユーザーが承認した第一段階モックと順序を実装する。表示設定の保存、現在KPI、個別案件値のハードコード、接続編集、DB書込みは追加しない。組織側は並行作業「プロジェクト連携表示の消失理由を調査」の接続実装を再利用する。

# プロジェクト個別ページで、今日の仕事から根拠へたどれる

利用者はプロジェクトを開いた直後に、全件を承認するためではなく、今日扱う仕事と前回から変わったことを判断する。必要なときだけ仕事一覧、仕事詳細、記録詳細、Graphへ進み、記録された関係と未確定の観測を分けて確認できる。

## Controller

SIMPLIFICATION。既存のGraph詳細、Sigma.js、ホストが渡す補足コンテキストを再利用する。業務専用API、別の正本、全関係の承認フロー、永続的な画面状態は追加しない。概要は量を把握する指標と優先項目だけを表示し、長い本文と全件比較は下位画面へ送る。

## 受入条件

- AC-01: 概要はプロジェクト名、状態、取得時点、量を確認する指標、今日扱う仕事、前回からの変化、最近の記録を表示する。未取得・失敗・未確認を0件や空の成功として扱わない。タスク区分が応答に無い場合は、指標と「今日判断・対応すること」の両方で未確認と示し、仕事がないとは表示しない。
- AC-02: タスクなど大量の補足項目は検索・状態・担当・期限で比較できる一覧へ遷移し、行から同じIDの詳細へ進める。一覧の表示件数と総数の意味を分け、部分取得を全件取得と表示しない。
- AC-03: 仕事詳細は状態、担当、期限、本文、関連記録、履歴、関連情報を表示し、記録IDを保持したまま記録詳細へ進める。記録が未接続の場合は未接続と明示する。
- AC-04: 記録詳細は要点、状態、出典、取得時点、未確定事項、関連する仕事・人物を表示する。未反映の観測をGraphの確定した線へ追加しない。
- AC-05: Graphタブは既存のSigma.jsマウントと実際のGraphエンティティ・関係を使う。選択ノードの文脈を表示し、観測から記録詳細へは出典IDを使う。概要に常設の右サイドバーを要求しない。
- AC-06: 概要、一覧、仕事詳細、記録詳細、Graphの主要導線は同一プロジェクトID・仕事ID・記録IDで往復できる。タブや選択状態を補足情報の段階読み込みで失わない。
- AC-07: 既存のGraph読み取り・訂正権限、個人情報の境界、未知の型・関係の表示を維持する。UI操作だけでGraphへの書き込みや承認を行わない。
- AC-08: 概要はタスク、判断、知識、用語集をそれぞれ独立した区分として表示する。長い本文と全件比較は概要に展開せず、該当区分の一覧へ進める。Graphの判断・関連情報も概要では全件展開しない。
- AC-09: 「すべて見る」はタスク、判断、知識、用語集ごとの一覧を開く。一覧は選択したセクションの項目だけを表示し、項目の種類を混ぜない。各行から同じIDの詳細へ進める。
- AC-10: 各セクションの一覧は初期表示を16行以内に制限し、17件以上ある場合は表示範囲を示すページ送りで続きへ進める。完全な総数を取得できない場合は総数や最終ページを推測せず、表示中の範囲と「未確認」を区別する。
- AC-11: タスク、判断、知識、用語集の詳細は、選択した項目の本文、状態、出典、更新時点、未確定事項を表示する。詳細から戻るとプロジェクトIDと元の区分を保持する。
- AC-12: タスク、判断、知識、用語集は、取得中・空・未接続・取得失敗をセクションごとに表示する。取得できないセクションや不明な総数を0件や空の成功として表示しない。

## 実装境界

- `ui/project-workspace.js` がコンテキスト項目の正規化、画面状態、遷移、Graph選択を担当する。
- `ui/project-workspace.css` が高密度の概要・一覧・詳細・文脈パネルを担当する。
- `ui/graph-projects-view.js` とホストは既存のGraph API、補足コンテキスト、Sigmaマウントを渡すだけにする。
- 新しいAPIルート、データベース、Graphエッジ、業務専用モデルは追加しない。

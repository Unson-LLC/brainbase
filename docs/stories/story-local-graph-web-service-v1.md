# 手元のGraphのプロジェクト・関係者・関係を読み、理由と履歴つきで訂正できる

## 利用者成果

所有者として、ローカルWebの「プロジェクトと関係者」「情報と関係」の画面から、手元のGraphに誰がどのプロジェクトにどう関わっているか、何がどの出典で登録されているかを確かめたい。誤りを見つけたら、その場で理由を1文書いて直し、次のMCP利用（`search`・`get_context`・`resolve_entity`）から直した内容が使われるようにしたい。後から「いつ何を、なぜ直したか」をたどれるようにしたい。

## 所有と対象

- 登録・実装repo: `Unson-LLC/brainbase`
- 情報契約: brainbase-project `docs/architecture/oss-personal-web-v1-remaining-screens-contract.md`（§0、§3.2、§4.2、§5、§6、§9の4・5・7。組織のGraphの検索はW6で扱う）
- 対象: Graphの読み取りと訂正の処理（`src/graph-web.ts`、`src/graph-corrections.ts`）と、それを載せるHTTPハンドラ（`src/graph-web-http.ts`）。画面（W4・W5）とホストへの組み込み（W1）は別のStoryで扱う。

## 受入条件

- [ ] AC-01: プロジェクトの一覧と詳細、対象の検索（名前・別名、種類、有効時点）、対象の詳細（入る関係と出る関係の種類・役割・有効期間・出典）、関係の種類ごとの件数を、ホストが決めたデータディレクトリから読む。各記録に、正規化したJSONのSHA-256（ダイジェスト）を付ける。
- [ ] AC-02: Graphがv1のときは、どの読み取りも「移行が必要」とv1の件数と移行のコマンド（previewと書き込み）を返し、0件として見せない。自動で移行しない。正本が無いディレクトリは「まだ登録がありません」と始め方を返し、ディレクトリを作らない。読み取りの失敗は失敗として返し、空の一覧にしない。
- [ ] AC-03: 出典の`sourceId`が手元の候補ファイル（`candidates/extracted-*.json`）、オンボーディングの記録（`runs/connected-onboarding.json`）、訂正の履歴を指すときは、その記録への参照を返す。それ以外は未解決のIDとして返す。読めない参照ファイルは、読めた記録とは別に件数と理由を返す。
- [ ] AC-04: 訂正できるのは、対象の名前・別名・要約・有効期間、プロジェクトの目的・状態、関係の役割・文脈・終了日、新しい関係（`participates_in`・`accountable_for`・`member_of`）の追加だけとする。削除、IDと種類の変更、関係の種類や端点の変更、その他の項目は理由のコードを付けて断る。新しい関係の出典は「利用者が承認」とする。
- [ ] AC-05: 訂正には読んだ記録のダイジェストと1行1文の理由を必須にする。ダイジェストが今の記録と違えば、今の記録とダイジェストを返して断り、何も書かない。
- [ ] AC-06: 訂正ごとに、前後のダイジェスト・日時・理由・訂正した項目（前後の値）を`evidence/graph-corrections.jsonl`へ追記する。Graphの変更、`relationships.json`の投影、履歴の追記は一つの取引で保存し、途中で失敗したらすべて元に戻す。保存後に同じ記録を読み戻してダイジェストを照合する。
- [ ] AC-07: 参加・責任の関係を加えたり直したりしたときは、`relationships.json`の投影をプロジェクト登録と同じ形（人物名、役割、「プロジェクト名: 文脈」）で揃える。終えた関係の投影は外し、外した内容を履歴に残す。
- [ ] AC-08: HTTPハンドラは書き込みの前にホストの`assertWriteAllowed`を呼び、渡されていなければ書き込みを断る。本文は16KBまで、応答は`Cache-Control: no-store`のJSONとし、競合は409、訂正の誤りは400で返す。担当しない経路はホストへ返す。

## 対象外

画面（W4・W5）、ホストへの組み込み・起動ごとのトークン・同一オリジンの確認（W1）、組織のGraph（C1、W6）、CLIからの訂正、RACIの型（契約§9の4）、Ontologyの変更案の提出（§9の6）。

## 検証と完了

合成データの一時ディレクトリ（Graph v2、Graph v1、未作成、壊れたファイル）で、読み取り・訂正・競合・禁止・取引の巻き戻しを確かめる。HTTPは`127.0.0.1`で待ち受ける実サーバーで、経路・書き込みの保護・本文の上限・409と400を確かめる。

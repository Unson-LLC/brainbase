# 外部作用の成否不明を証拠付きで解消できる

外部作用の応答を失い `reconciliation_wait` になった判断について、担当者が外部システムの照合結果を提示したとき、Brainbase はその結果を信頼済みの照合ポートで検証して記録する。実行済みなら元の作用を再実行させず、未実行なら新しい claim と実行時権限確認を経る再試行だけを許す。不明のままなら待機を続ける。

## 受け入れ条件

- 前提変更だけでは `reconciliation_wait` を解除できない。
- 照合証拠・外部操作 ID・照合依頼 ID は保存され、同じ依頼の再送は照合と状態遷移を重複させず、矛盾する再送は拒否される。
- 成否不明への移行時に外部操作 ID と claim ID を固定する。元の実行意図との結合検証に失敗しても、期限後に再実行されないよう待機を隔離する。この場合は照合証拠が届いても自動解除しない。結合済みの場合も、証拠が示す外部操作 ID・claim ID・証拠参照が完全一致しない限り解除しない。ID のない旧記録も自動解除しない。
- 確認済みの実行は終端状態になり、再 claim・再 resume を拒否する。未実行と確認された場合は古い lease を破棄し、新しい claim ID と request ID を要する。
- 検証ポートがない、検証が失敗した、結果が不明、ACL が失効した、または並行更新があった場合に危険な解除をしない。再起動後も同じ証跡と状態を読む。

外部作用そのものの照合方法と実行時権限の再検証はホストの責務とする。OSS store は結果を推測しない。

# 世界を3つの縮尺で見て、縮尺ごとに「いまの動き」を出す

世界（全事業）→ 事業（区画）→ 仕事の集まり（通り）の3つの縮尺を、同じ世界の寄り引きとして見せる。縮尺ごとに出す情報を絞り、一覧を開かなくても「どこが動き、どこが待っているか」を見て取れるようにする。別の画面・別の保存先・AIだけの一覧は作らない。

## 縮尺ごとに出すもの

- 世界: 事業ごとの動きの量だけ。都市の名札と「世界のいま」に、進行中・待ちの件数を出す。仕事の記録が無い事業は「仕事の記録なし」と書き、0件とは書かない。
- 事業: 仕事の集まり（通り）ごとの進み。通りの看板と「〈事業〉のいま」に、終えた・進行中・待ち・これからの内訳と、そこにいるAIの印を出す。AIの数は「N体のうちM体が動いている」と書く。
- 仕事の集まり: 看板を押すと通りへ寄る。その通りの仕事は濃く、ほかは薄くする。仕事1件ごとに、どのAIがいて、動いているか・待っているか・終えたかを名札と「ここにいるAI」に出す。AIの担当が記録されていない仕事は「AIのいない仕事」に分けて出す。

## 守ること

- 主語は仕事の集まり。AIはその中の働き手として出し、AIを主語にした一覧は作らない。
- 表示は記録からの計算だけ。タスクの状態と、ホストが確かめた稼働の知らせ（story-world-task-actors-v1）から毎回計算し、世界は何も保存しない。
- 「動いている」は、進行中のタスクで5分以内の稼働の知らせがあるときだけ。古い知らせは「静か」、確認できないものは「未確認」。記録に無いAIを作らない。
- 見ている縮尺はパンくず（世界 › 事業 › 仕事の集まり）で示し、押すと1つ上へ戻る。Escapeでも1段戻る。
- 名札は右上の操作と通知の下に入らず、画面の端で切れない。
- 階層を移る飛行の途中で記録が更新されても、行き先に着く。それ以外の飛行は、従来どおり更新でその場に止まる。
- reduced motion では動きを付けず、状態は文字と色で読める。

## 検証

tests/ui/world-pulse.test.mjs（動きの計算）、tests/ui/world-clickable-honesty.test.mjs（看板から通りへ）、既存の world-district / world-work-rail。実ブラウザでは、見本データで3つの縮尺を開いて確かめる。組織版は共通UIの公開版を依存pinして使う。未公開の変更が本番で動くとは扱わない。

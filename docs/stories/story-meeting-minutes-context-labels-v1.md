# 会議の補助ラベルと作成可能状態を確認できる

会議を扱う利用者として、ホストが提供する補助ラベルを一覧と詳細の両方で確認し、会議や議事録を作成・編集できない状態ではその理由を画面上で理解したい。

## 完成時の利用者成果

共有の議事録画面は、会議データに対する任意の文字列ラベルを一覧と詳細に表示する。ラベルはホストが解決した表示値だけを受け取り、共有UIが所属や権限を推測しない。作成・編集不可の状態では該当操作を無効化または非表示にし、フォーム表示と送信を防ぐ。既存ホストが追加オプションを渡さない場合は従来どおり利用できる。

## 受入条件

- [ ] AC-01: `meetingLabel(meeting)` を渡すと、空でない戻り値が会議一覧と会議詳細に補助ラベルとして表示される。戻り値はHTMLとして解釈せず、文字列として表示する。
- [ ] AC-02: ラベルコールバックの例外、非文字列、空文字は画面を壊さず、補助ラベルを表示しない。共有UIはラベルの意味や所属を推測しない。
- [ ] AC-03: `canCreateMeeting` が省略または `true` のとき、会議作成ボタン、フォーム、保存リクエストは既存の動作を保つ。
- [ ] AC-04: `canCreateMeeting` が `false`、または戻り値が `false`／評価中に例外となるコールバックのとき、作成ボタンを無効化し、作成できない理由を表示する。クリックによるフォーム表示と送信によるPOSTを発生させない。
- [ ] AC-05: 共有UIの単体DOM・ライフサイクルテストで、省略時互換、一覧と詳細のラベル表示、文字列の安全表示、作成ガード、拒否状態から許可状態への再描画を確認する。
- [ ] AC-06: `canEditMinutes` が `false`、または戻り値が `false`／評価中に例外となるコールバックのとき、版保存と議事録文書追加のフォームを表示せず、未確認版の確認ボタンを無効化し、編集できない理由を表示する。フォームや確認ボタンの表示後に拒否へ変わった場合も、操作直前の再評価でPOSTを発生させない。
- [ ] AC-07: 一覧更新または詳細表示を複数回実行したとき、後から返った古いレスポンスが最新の一覧・詳細を上書きしない。絞り込み後の一覧に含まれない選択中の会議の詳細は画面に残さない。

## 範囲と境界

ラベルの解決、表示値の意味、会議を作成できるかの判断はホストへ委譲する。共有UIは受け取った文字列を安全に描画し、作成ボタンとフォーム送信を制御する。

組織、テナント、メンバー、ロール、承認者、プロバイダの概念を共有UIへ追加しない。共有UIは一覧取得の認可範囲や保存先を変更せず、表示用コールバックの値から権限を推測しない。

## 実装・検証方針

既存の `createMeetingMinutesUI` に省略可能なコールバックと真偽値のオプションを追加し、既存の呼出し元の引数なし利用を維持する。一覧と詳細のリクエストには世代番号を持たせ、最新の要求だけが状態と表示を更新できるようにする。変更対象は共有UI、既存のスタイル、対応するUIテストに限定する。

# 「人と会社」で選んだ人・会社を詳細のページで開き、できる操作を見出しの近くに置く

## 利用者成果

「人と会社」を開く人として、人か会社を選んだら、どの画面の幅でも、その場で詳細とできる操作を見たい。消せるのか、直せるのかを迷わず、「消さずに終える」ことが名前と一言で分かるようにしたい。

## 背景

- 2026-10-16、佐藤が組織版の「人と会社」で次を指摘した。「選んだときに出てくる詳細の位置が一番下になる。どうしたらいいのか分からないように見える」「修正がそもそもできないのか、消したりできないのかが分からない」「編集・削除・追加のやり方を、もっと分かりやすくしてほしい」「もともと参考にした見本のUIがあったはず。それをそっくりそのまま真似ればいい」。
- 原因（実ブラウザで確認）: 部品は詳細も操作も右の欄だけに出していた。組織版の外枠は幅1180px以下で右の欄を本文の下へ回すため、行を押しても画面は変わらず、詳細の見出しはページの末尾（画面の外）に出ていた。組織版にこの画面専用のCSSの上書きは無い。
- 見本（Arc CRM。2026-10-15に佐藤が挙げた有料テンプレート。コードは使わず見た目だけを参考にする）は、一覧の行を選ぶと本文が詳細のページに切り替わる。上に一覧へ戻る道と「N件中の何件目」と前後の移動、見出しの右に操作、横に「詳細」の欄を置く。一覧の右上には「新しい会社」の主ボタンを置く。
- 前提台帳 D14（2026-10-16 採用）は「情報と関係」で、選んだ対象を1画面で開き戻るで一覧へ帰る形を決めた。この Story は同じ形を「人と会社」にあてる。
- 書き込みの規則は変えない。情報契約（brainbase-project `docs/architecture/people-and-companies-screen-contract.md` §3）のとおり、人・会社を作る、所属を付ける、所属を終える（終了日を入れる。消さない）だけ。書けるかはホストが決め、部品に役割名を書かない（台帳D8）。

## 受入条件

- [ ] AC-01: 人か会社を選ぶと、本文が詳細のページに切り替わり、ページの先頭（見出し）へ移る。どの幅でも、選んだ直後に見出しが画面の中に見える。
- [ ] AC-02: 詳細のページの上に「人と会社の一覧へ」と「人 N / M」（会社なら「会社 N / M」）と前後の移動を出す。一覧へ戻ると、選んでいた行へ戻る。
- [ ] AC-03: 見出しの下に、その人・会社への操作をまとめて置く。人は「所属を付ける」と有効な所属ごとの「「会社名」の所属を終える」、会社は「所属する人を加える」。所属を付ける・終える画面は、その操作のすぐ下に開く。
- [ ] AC-04: 操作のそばに「消す操作はありません。所属は終了日を入れて終えます。終えた記録は履歴に残ります。」の旨を出す。名前・別名・要約の訂正は「情報と関係」で開く道を置き、ホストが `recordFixNote` を渡したときは、その理由を出してリンクを置かない。
- [ ] AC-05: 書けない閲覧者（`canCorrect` が無い）には、操作のボタンを押せない状態で出し、押せない理由を出す。理由はホストの `readOnlyNote`、無ければ一般的な文（役割名を含まない）。`correctionScope` で外した操作は出さない。
- [ ] AC-06: 一覧の上部に「人を加える」「会社を加える」を目立つボタンで並べる（書けないときは押せない状態と理由）。作る画面は一覧の上に開き、保存すると作った記録の詳細のページを開く。
- [ ] AC-07: 区分（社内・社外・所属未確認）・種類・有効期間・IDは「詳細」の欄に出す。ホストが右の欄を持つときは右の欄に、持たないときはページの中に出す。
- [ ] AC-08: 段の構成（人→会社、社内・社外（会社ごと）・所属未確認）、並び順、書き込みの経路と規則は変えない。

## 範囲外

- 「関わるプロジェクトを付ける」、人・会社の名前の訂正をこの画面から保存すること。組織版の中継が受け付けない（`member_of` の作成・終了と、人・会社の作成だけ）ため、書き込みの経路の追加として別に出す。
- 開いた記録をURLに載せること（ホストの役割）。
- 組織版の取り込み（`readOnlyNote`・`recordFixNote` を渡す）。OSSの公開の後に組織版のPRで行う。

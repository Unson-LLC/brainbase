# UX33 同じ下書きへの競合回復

## 開発モード
SIMPLIFICATION。直近の変更は入力保持・競合再試行・画面説明を追加しているが、実画面では回復操作が消えている。既存のAPI adapterとcommit controllerを修正し、新しい回復状態機械やサービスは追加しない。

## Story
利用者として、正本保存直前に下書きが更新されても、入力・出典・提案の編集内容を保持したまま最新版を確認し、画面で明示的に再適用して保存を完了したい。

## 最小Spec
- codeなし例外でもHTTP status・payloadを保存し、409を競合として表示する。
- 409後は同じdraft IDをGETして最新版を確認する。GETのみではPATCH/POSTしない。
- 同じ対象の空でない最新版revisionが確認できたときだけ「保持した内容を再適用して保存」を表示する。
- 操作は保持した入力・出典・提案・create/reuse選択を使い、取得済みrevisionでPATCHし、その応答revisionで正本save/reuse、正本GETによる照合まで進める。
- 最新版の内容を比較できるよう表示する。ID/版不足・取得失敗・権限不足・操作中では再適用できない。二重クリックは追加mutationを起こさない。
- 新規提案生成や下書き作成を競合回復で行わない。

## 検証
API adapter回帰と描画後のボタンクリックによる409→同一draft GET→明示再適用PATCH→save/reuse→正本GETの結合テスト。入力/出典保持、取得不能時のロック、二重クリックを確認する。その後、凍結ORG fixtureと修正OSS UIを新しいsource bindingで結び実ブラウザUX33を再試験する。旧run OはFAILのまま保持する。

## 対象外
本番反映、OAuth接続、外部送信、人間受入、Round4全体完了。

# 情報と関係で調べる：一覧はその場で絞り込み、対象は1画面で開く

利用者として、Brainbaseがこの会社の人・会社・案件をどう理解しているかを調べたい。一覧は条件を変えたらすぐ絞り込まれ、今の条件が見えて外せるようにしたい。対象を押したら、その対象の画面が開き、何者か・何とつながっているか・根拠は何か・直すとどこに効くかを順に読みたい。戻れば元の一覧に帰りたい。

2026-10-16、佐藤さんが組織版の「情報と関係」で次のように指摘した（記録 14-5・14-6・14-7・14-9・14-10・14-18）。

- 検索結果を押しても何も出てこないか、出ていても別の場所（下や横）が変わっていて、何も起きていないように見える。「動線として最悪」
- 他の画面は絞り込むとすぐ反映されるのに、ここだけ「探す」を押さないと反映されない
- 絞り込みの外し方が分からない
- 「有効時点」の意味が分からない
- 「要約」の列は、ありと無しがあるが、その差が分からない
- 「記録の詳細」が、何に紐づいた詳細なのか分からない

実ブラウザ（組織版と同じ3列の枠・同じCSS・組織版と同じ形の応答）で確かめると、幅1440pxでは詳細が右の欄だけで変わり、幅1040px以下では詳細が一覧の下の約2,000px先に出て、押した位置からは何も変わらなかった。名前の欄に打っても、「探す」を押すまで一覧は変わらなかった。

佐藤さんは「情報設計してからじゃないとまずい」として、直す前に論理構成を決めた。正本は前提台帳 D14（brainbase-project `docs/architecture/oss-personal-web-ux-premises.md`）。このStoryは、D14のうち「調べる」の一覧と対象の詳細を扱う。

## Controller

MODIFICATION。共通UI `ui/graph-registry-view.js` の一覧と、選んだ対象の表示を作り直す。対象は右の欄ではなく、アドレスを持つ1画面で開く。HTTPの契約・正本の記録・訂正の流れは変えない。組織版はこの部品をそのまま組み込み、自前で作り直さない（台帳 P16・D8）。

自分の束（引き継いだ自分の分）の候補の確認への移設と、情報の種類とつながり方の設定への移設は、別のStoryで扱う。

## 受入条件

### 一覧

- AC-01: 名前・別名の欄は、打つのを止めて少し待つと反映する。日本語の変換中は反映しない。Enterで待たずに反映する。「探す」ボタンは置かない。読み直しの間も前の一覧を消さず、「探しています」と添える。
- AC-02: 種類はタブにして件数を添える。人・会社・プロジェクトを先頭に置く。内部の型名は出さず、日本語の名前が無い種類はタブにしない（「すべて」に含まれ、種類は「その他の記録」と出す）。件数を読めない種類は件数を出さない（0件に見せない、P9）。
- AC-03: 条件があるときは、今の条件を札で並べ、札ごとに外せる。「すべて外す」で全部外す。
- AC-04: 有効時点は「詳しい条件」の中の「過去のある日の状態で見る」にする。札には「◯◯ の状態で見ています」と出す。
- AC-05: 各行に、名前・種類・ひとことの説明（無ければ「説明の記録なし」）・最終更新を出す。最終更新は、ホストが更新日時を返すときだけ列を出す（推測で埋めない、P9）。終わった記録は名前の下に終了を出す。

### 対象の詳細

- AC-06: 行を押すと、その対象の画面に切り替わり、見出しに名前と種類を出す。ホストはその画面にアドレスを与えられる（`onRouteChange`）。OSSの手元のWebでは `#graph?entity_id=…`。「← 情報と関係の一覧に戻る」・Escape・ブラウザの戻るで一覧に帰り、開いていた対象の行に焦点が戻る。
- AC-07: 並びは、何者か → つながり → 根拠と履歴（折りたたみ）→ 直す。使われた場所は、読み取りの経路がまだ無いので欄ごと出さない。
- AC-08: つながりは文で読める形にし、出る関係と入る関係を分けず、相手の種類ごとにまとめる。関係の名前は日本語にそろえ、日本語の名前が無い関係は「とつながる」と読む。つながりを読めないときは「確認できない」と出し、0件に見せない。相手の名前を押すとその対象の画面に移り、「前の記録に戻る」がある。
- AC-09: 出典・認証（ホストの出典の案内）・読めない出典の案内・有効期間・訂正の履歴・IDは「根拠と履歴」に入れ、画面全体の注意としては出さない。IDの折りたたみは「この記録のID（技術情報）」「この関係のID（技術情報）」と名前で示す。
- AC-10: 「直す」では、先に影響する先（名前・別名で探す検索とMCPの search・get_context・resolve_entity、つながる記録の詳細）を見せてから、「この記録を直す」「関係を加える」と関係ごとの「この関係を直す」を出す。直せないホストでは、ホストの案内だけを出す。

## 実装境界

- 引き継いだ自分の分（`ownShare`）と情報の種類とつながり方は、#817（D14の移設）で画面から外れた。このStoryはそれを取り込み、種類のタブの件数のために `/ontology` を読み続ける。根拠と履歴は、#817 の共通部品 `renderEvidenceAndHistory` に、有効期間・つながりの出典・IDを足して使う。
- 種類と関係の日本語名は、#817 で広げた共通の名前表（`typeLabel`・`GRAPH_RELATION_LABELS`）を使う。この画面では、人・会社・プロジェクトだけを D14 の呼び方にそろえて先頭に置く。
- 右の欄は空のままにする。組織版で右の欄を閉じるのは、組織版の取り込みのときに行う。

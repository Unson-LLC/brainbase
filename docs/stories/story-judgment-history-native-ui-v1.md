# 参照と代わりに行った判断を、既存Webで見返す

本人として、OSSと組織版の既存画面で、何を参照し、何を自分の代わりに判断したかを新しい順の履歴と件数で読みたい。評価や確認済みの入力なしで振り返れることを到達状態とする。

## 開発モードの決定

トップレベルのcontrollerを親エージェント一つに限定し、両repoの直近Story、累積複雑性、外部成果を読んだうえで、この変更は **SIMPLIFICATION** とする。

- OSSの既存見返しStoryは区分・委任の地図・本人評価を求め、現在の利用目的より操作が多い。既存journal readerと共通workspace部品を再利用する。
- 組織版の最新Storyは評価不要の履歴へ更新され、ローカル実データの表示は確認済み。一方、製品入口は旧評価案内、取得APIは未接続の固定応答である。
- 新しい台帳や複製UIを追加せず、既存入口の主表示を共通履歴へ置き換える。組織版は認証とcanonical APIの境界を所有する。
- 本番のowner-bound source接続、外部利用者の受容、時間・金額の削減は未確認。ローカル表示と件数をそれらの証明にしない。

この決定は両repoで一度だけ行う。実装担当が独立したモード判定を増やさない。

## 受入条件

- AC-01: OSSの既存ローカルWeb入口と組織版の既存主ナビから、各版のシェル・文字・色・余白に合う履歴を開ける。
- AC-02: 日時、使った参照、行った判断を新しい順で表示する。詳細は任意で開き、実行・結果は補足に置く。評価入力は要求しない。
- AC-03: 同一intentの最新記録を選んでから期間・検索を適用する。履歴・代理判断数・そこで使った参照数・判断N回分は同じ絞り込み範囲を用いる。本人への確認・判断内容なし・再試行を代理判断へ加えない。
- AC-04: 参照はdecision.basisとdecision.inheritance.sourcesからIDと版で重複除去する。実行・結果の証拠を参照数に加えず、未記録は未記録と表示する。出典がないURLや時間・金額換算を作らない。
- AC-05: 読めた記録の履歴と未接続・取得失敗・部分取得・確認済みの空を区別する。失敗や部分取得を全体0件として表示しない。再試行できる。
- AC-06: 共通UIと集計はOSSで所有し、組織版は配布済みのOSS依存を消費する。本人のjournalをBFFから直接読まず、組織・tenant・person・projectを確認したcanonical readerを経由する。
- AC-07: 実際の本人journalを変更せずOSSの製品ホストで表示し、APIと画面集計を照合する。組織版のscope境界・空/部分/失敗・切替後の遅延応答を検証する。個人データをGitへ保存しない。
- AC-08: 841/1150/1600pxの同じ履歴の3列の上下端と罫線が揃い、390pxでは横にはみ出さず、キーボードで詳細を開閉できる。

## 対象外

本人評価の保存を新設すること、個人journalの組織への自動共有、仕事全体の削減認定、新しいSSOT、未接続の本番sourceを接続済みとみなすこと。

既存の評価・回答APIおよび公開UI exportは互換性のため維持する。今回の履歴画面から評価の入力は求めない。

仕様: [履歴の投影](../specs/judgment-history-native-ui.md)。組織版のsource境界は同repoの`docs/architecture/judgment-history-projection.md`とreader仕様に従う。

- OSSの製品ホストで本人の保存済み21記録を読み、独立したモックの集計と照合した。過去30日は履歴19件・代理判断17件・参照3件、全期間は履歴21件・代理判断19件・参照4件。本人journalは変更していない。
- 各版の実画面で11項目を確認した。期間・検索と件数の一致、再読込、取得失敗からの復帰、Enter/Escapeでの詳細開閉、390pxの表示が通った。841/1150/1600pxの3列の上下端差は0pxだった。
- 組織版の画面確認はローカル専用の仮の本人・組織bindingと正本readerを使った。実際の本番binding/source接続や本番配備の証拠ではない。個人情報を含む画面証跡はGit外に保存した。
- 関連6ファイル108テスト、ビルドが通った。全体の低並列実行は1552テスト成功、既存のexact git依存インストール1テストが120秒制限を超えた。単独再実行でも同じ時間制限に達したため、CIの結果を統合条件とする。

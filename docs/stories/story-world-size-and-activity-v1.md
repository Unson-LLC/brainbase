# 都市の広さで規模を、高さと明かりで今の勢いを読めるようにする

## 利用者成果

世界を見渡したとき、都市の広さでその事業がいま抱えている案件の多さが、建物の高さと窓の明かりで最近動いているかが分かる。完了した案件が多いだけの事業が大きく見えたり、動いている事業が小さく見えたりしない。

## 背景

これまで都市の広さも目印の高さも、完了・終了を含む案件の総数だけで決めていた。「どれだけ育っているか」ではなく「どれだけ案件を抱えてきたか」を表していた。佐藤さんが「広さ＝進行中の案件の数、高さ・明かり＝最近の動き」を採用した（2026-10-05）。最近の動きには、プロジェクト記録の更新日時を使わない（一括の保守作業でまとめて更新され、動きを表さないため。実データで30日に51件）。

## 受入条件

- [x] AC-01: 都市の広さは進行中の案件の数で決まる。完了・終了した案件は更地として描き、広さには数えない。
- [x] AC-02: 各事業に `activity`（30日の決定件数・最新の決定日）を返す。決定は、組織Graphの範囲コード（事業か案件のコード）か、手元Graphの `governs` で事業に結び付ける。日付は `decided_at`、無ければ `validFrom`。日付の無い決定は数えない。
- [x] AC-03: 目印の高さは最近30日の動き（決定＋その事業に置かれた判断）で決まり、動きが0件なら窓は暗い。
- [x] AC-04: 都市を選ぶと、右の欄に「進行中の案件（都市の広さ）」と「最近30日の動き（高さ・明かり）」を数で出す。判断を持たないホスト（組織版）では「判断は未接続」と書く。

## 検証

- `tests/world-extension.test.ts` で、範囲コードと `governs` による決定の結び付け、30日の窓、日付の無い決定を数えないこと、組織APIの決定記録からの集計、広さ・高さ・明かりの計算を確かめる。
- 実データのプレビューで、決定と判断のある事業だけが高く明るく描かれ、コンソールのエラーが無いことを確かめる。

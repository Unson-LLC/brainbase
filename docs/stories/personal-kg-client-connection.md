# ManaとCodexから本人の記憶を使う

利用者として、自分とのDMまたは認証済みCodexから、自分の記憶を登録・検索したい。他人の記憶や共有チャンネルへ漏らさず、同じイベント契約で保存先を選びたい。

## 受け入れ条件

- Manaは認証されたSlack利用者・workspaceを既存の会社権限経路で本人へ解決する。未解決・複数候補・期限切れは拒否する。
- Manaの個人検索・登録は本人とのDMだけで使える。モデルが本人ID、組織ID、送信先を指定して境界を変更できない。
- Brainbaseは署名、本人、組織、配置、対象資源、操作権限を独立に検証する。汎用サービス資格情報だけでは個人KGに入れない。
- Codexは明示したlocalまたはmanaged_cloudを同じイベント契約で使う。接続失敗時の暗黙切替・二重書込みはしない。
- 個人原文は組織へ自動共有しない。既存の本人同意・組織レビュー経路を維持する。
- テストで登録後検索、他人・別組織・共有チャンネル・偽造・期限切れを確認する。本番利用可否は配備と実操作確認を別に報告する。

## 開発判断

NORMALを選択。直近の個人KG変更は保存・昇格・認証を整備しており、残る問題はクライアント接続にある。既存の署名済み会社権限とPersonal Vaultを再利用し、別の本人対応表・代理認証・同期デーモンは追加しない。

引用されたcheckoutは競合を含む旧状態だったため、最新origin/developを実装基準にする。Graphifyの対象グラフは未取得で影響範囲は不明。現行コードと呼出し側・対象テストで補う。

# 議事録の画面で直し、取り下げる

## 利用者成果

プロジェクトの議事録を読む人として、本文の誤りを画面で直したい。直しても、前の版は残っていてほしい。議事録を作った本人としては、誤って公開した議事録をプロジェクトから取り下げたい。そのとき、何が消えて何が残るのか、何を取り消せないのかを、確定する前に知りたい。

## 背景

- 佐藤さんは 2026-10-16 に、組織版の議事録の画面で次の5点を指摘した。編集できない。削除できない。見るだけで、できることが少なすぎる。「第1版」を最初に強調する意味がない。タイトルが2回出ている。
- 2026-10-14 の PR #780 は、承認済みモック 02-version-readonly に合わせるため、版の保存フォームを外した。佐藤さんは 2026-10-16 に、このモックの読み取り専用をやめ、編集を戻すと決めた。取り下げは作った本人だけができ、照合はサーバーでする。
- 会議の正本は Brainbase にある（ADR-022）。本文を Brainbase が持つ版は、Brainbase で直す。本文が外にある版（`source_ref`）は、これまでどおり元の記録で直す。
- 取り下げは消すことではない（台帳 D9、story-meeting-minutes-withdraw-v1）。Git へ書き出した分と、Slack で送った知らせは取り消せない。

## 受入条件

- [ ] AC-01: 本文を Brainbase が持つ版を開いていて、書き込める人には［編集］が出る。押すと、今の本文の入った入力欄に切り替わる。そこに「保存すると第n+1版になります。前の版は残ります」と、公開した分の Git と Slack は前の版のまま変わらないことが出る。［新しい版として保存］を押すと新しい版ができ、その版が「確認待ち」として表示される。
- [ ] AC-02: 本文が外にある版には［編集］を出さず、元の記録で直す案内を出す。古い版を表示しているときも［編集］を出さない。
- [ ] AC-03: `withdraw_minutes` は、議事録の文書を作った本人（`created_actor_id`）だけが実行できる。書き込める人でも、作った本人でなければ `authorization_denied` になる。
- [ ] AC-04: 画面の［取り下げる］は、見ている人が作った本人のときだけ出す。見ている人がわからないホストでは常に出し、断るかどうかはサーバーが決める。押すと確認の欄が出て、一覧から外れること、版と本文と取り下げた記録が残ること、Git の書き出しと Slack の知らせは取り消せないこと、元に戻す操作が無いことを示す。［取り下げる］で確定すると、一覧から外れる。
- [ ] AC-05: 取り下げた議事録を詳細で開くと、「取り下げ済み」と、取り下げた人と日時が出る。編集・確認・取り下げの操作は出ない。
- [ ] AC-06: 見出しの直下に版の帯を置かない。状態（確認待ち／確認済み）と操作だけを置き、版の情報は本文の下に1行で出す。［版の履歴］は版が2つ以上あるときだけ出す。古い版を見ているときの案内は、今どおり上に出す。
- [ ] AC-07: 本文の先頭の見出しが会議の題名と同じ文なら、その見出しは出さない。全角と半角、空白の違いは無視して比べる。本文そのものは変えない。
- [ ] AC-08: OSS のローカルの HTTP に `POST {base}/{meeting_id}/minutes/{minutes_id}/withdraw` を足す。本文は `expected_revision` だけ。

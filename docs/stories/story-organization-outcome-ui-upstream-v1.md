# 組織版が知識とMana委任の共通UIをコピーせずに使える

## 利用者成果

組織版の開発者として、知識とMana委任の画面をOSSの共通部品から読み込み、組織固有の違いはホストから渡すオプションだけで表したい。組織版のコピーで直した不具合をOSSへ戻し、同じ修正を版ごとに二重に行わないようにしたい。個人版の利用者として、新しいオプションを渡さない限り、画面の構成と送信内容が今のままであってほしい（不具合の修正を除く）。

## 所有と対象

- 登録・実装repo: `Unson-LLC/brainbase`
- 対象: 知識画面（`ui/outcome-knowledge.js`）、Mana委任画面（`ui/outcome-mana.js`、`ui/outcome-mana.css`）とそのテスト
- 組織版は、この変更の公開後に自身のコピーを削除し、オプションを渡して読み込む（別の変更）。

## 受入条件

- [ ] AC-01: 知識画面は`canEditDestination(session, projectCode)`を受け取り、`true`を返した利用者にだけ保存先の登録フォームを出す。渡さないときは今と同じ`canManageKnowledge`で決める。改訂・置換・失効の可否は変えない。
- [ ] AC-02: Mana画面は`connectors`で接続の一覧・順序・アイコンを置き換えられる。アイコンは常に一覧の定義から取り、APIの応答からは取らない。
- [ ] AC-03: Mana画面は`connectionCatalog`（`ids`・`load`・`labels`・`sourceLabel`・`reasonLabels`・`copy`）を受け取ると、接続状態をホストの`load`から読み、「接続」「このプロジェクトで使う資源」「委任単位の許可範囲」を分けて示す。資源はプロジェクトの登録から取り、ホストの接続状態で登録済みに見せない。読み込み前と失敗時は各接続を未確認のまま示し、確認日時を作らない。`onManageConnection`を渡したときだけ接続の管理ボタンを出す。渡さないときは今の基盤確認（`paths.foundationCheck`）と一覧のままにする。
- [ ] AC-04: Mana画面は`executionProfiles`を受け取ると、成果契約のフォームで仕事の種類を選ばせ、入力資料・この委任で使う接続資源・保存先を読み込んだ接続資源から選ばせる。一覧に無い既存の参照と保存先は消さずに保持し、保存先・環境・仕事の種類が変わらない既存契約は選び直さずに保存できる。事前確認の可否は、保存済みの契約版と仕事の種類に一致する実行だけから示す。渡さないときは今の自由入力のフォームと送信内容のままにする。
- [ ] AC-05: 隔離試験は受理された試験IDの結果を追跡し、再取得で新しい試験を作らない。試験IDは利用者・プロジェクト・契約ごとにタブの保存域へ残して復元する。取得に失敗したら、エラーコード・HTTP状態・理由を示して自動の再取得を止める。Mana実行状態・現在の段階・エラーコードと理由・完了条件の評価・隔離成果物の読戻しを示し、観測した本文は示さない。
- [ ] AC-06: 実行の事前チェック（不足理由・必要な対応・再開地点）を、隔離試験と実行詳細に日本語で示す。実行履歴は作成日時の新しい順に並べ、最新の実行の詳細を開く。
- [ ] AC-07: 権限は契約版に結び付ける。契約の詳細を読み込み中の間や、別の契約・版に切り替わった後に届いた権限の応答は採用しない。権限の段階を初めて開いたときに読み込み、上流が空と確認したときだけ最初の権限を追加するフォームを出す。
- [ ] AC-08: 共通UIに組織・テナント・役割名・組織固有の理由コードを新たに書き込まない。新しいオプションは中立な名前でJSDocに記す。

## 対象外

デザイントークンの導入。接続アイコンの枠の配色の変更（組織版の白い枠は組織版の側で上書きする）。組織版のコピーの削除と、組織版ホストでのオプションの受け渡し。

## 検証と完了

オプションを渡さない挙動は既存のUIテストで確認する（権限の読み込み条件を満たすよう契約の読み込み完了を明示した1件だけを直す）。組織版で直した挙動は移植したテストで、各オプションはそのオプションを無視すると失敗するテストで確認する。

# 開発判断: プロジェクト概要の集計を、置かれた場所の幅で並べ替える

- story_id: `story-project-metrics-container-query`
- 日付: 2026-11-12
- 根拠決定: 佐藤さんの指示（2026-11-12）。`story-modern-web-guidance-standard` で範囲外にした「使っていない新しい機能」を、画面の体験が良くなるものだけ画面ごとに選ぶ。

## Story

プロジェクトの記録を開く人として、どの画面幅でも概要の数字を読みたい。800px前後の画面では、概要の4つの数字のうち「未確認」が「未確／認」と語の途中で折れていた。

## 原因

概要は左のレールの横に置かれるので、画面幅800pxでも概要の幅は約520pxしかない。4列の切り替えは画面幅760px以下の `@media` だけだったため、800pxでは4列のまま1列あたり約130pxになり、30pxの3文字が入らなかった。

## 受け入れ条件

1. 概要（`.bb-pkw-dense-overview`）が、名前つきの幅の container になる。
2. 概要の幅が600px以下なら、画面幅に関係なく集計は2列になる。
3. 600pxより広ければ、これまでどおり4列のまま。
4. 集計の2列の並べ替えは `@media` に残さない。
5. 実ブラウザの1280・1000・800・375pxで、値が1行に収まり、横スクロールが出ない。

## Spec

`tests/ui/project-workspace-metrics-layout.test.mjs` が、CSSの構造で条件1・2・4を確かめる。変更前のCSSでは3件とも落ちる。条件3・5は実ブラウザで測った（PRに記録）。

## Scope OUT

- 共通部品（`workspace-kit.css`）の `@media`。今の画面では、列の幅が足りずに崩れる箇所を見つけられなかった。drawerや固定位置の部品は、画面幅を基準にするのが正しい。
- 同じ画面の `.bb-pkw-overview-facts` など、ほかの760pxの切り替え。崩れを確認していない。

## 対応ブラウザ

container queryは Baseline Widely available（2023年から）。共通UIの規約の区分では「そのまま使う」に入る。

# Executor Routing

## 目的と入力

親が要件・重要な判断・権限・統合を持ち、境界が明確な作業をworkerへ渡す。入力は成果、変更可能な範囲、完了条件、使える委任機構、利用者と実行環境のモデル指定。

## 実行先の選択

- 親モデルは利用者の指定を維持する。workerは現在のAGENTSとツールが定義する役割を使う。Codexの`worker`役割を、別providerの同名aliasへ読み替えない。
- 独立した定型実装、対象を絞った調査、機械的修正、テストは委任候補。委任の手間が作業を上回る場合は親が行う。
- 要件・設計・権限・secret・課金・破壊的変更・公開契約などの重要判断は親が保持する。workerに渡すのは明確に切り出した許可範囲だけ。
- `cc-router`やNousを明示的に使う場合だけ、そのproviderの設定・alias・subscriptionの対応を確認する。Skillで現在のbindingや価格を断定しない。APIキーの値は表示・記録しない。
- Claude CodeからCodex CLIへの委任自体が目的なら[codex-delegate](../codex-delegate/SKILL.md)を参照する。

## 委任の境界

- 成果、変更可能なファイル、変更禁止範囲、必要な検証、commit/pushの可否を伝える。子への委任で親の権限範囲を広げない。
- 並行作業の書き込み対象は重ならないようにする。隔離checkoutが必要なら[branch-worktree-rules](../branch-worktree-rules/SKILL.md)を使う。共有DB、固定ポート、同じファイルを扱う操作は直列化する。
- 同時実行数は独立した作業数と利用可能な枠に合わせる。並列数を増やすことを目的にせず、rate limitや実行失敗があれば縮小する。
- 検証失敗、範囲逸脱、要件の再解釈、同一エラーの反復、不確実性が出たら、diff・失敗出力・未達条件を親へ戻す。同じ指示で無制限に再投入しない。

## 出力と完了条件

workerは変更ファイル、実行した検証と結果、残る不確実性を返す。親は最終メッセージだけを成功証拠にせず、差分と実検証を確認する。

- 許可範囲、受け入れ条件、既存変更の保持を満たす。
- テストやfixtureを弱めて成功にしていない。
- secretや個人環境の絶対パスを成果物へ混ぜていない。
- 未確認・失敗を明示し、対象の変更・新たな失敗がない検証は繰り返さない。

安いモデルへの委任が有効だったかは、修正・再検証を含めた実測で判断する。モデル名や単価だけで品質・費用削減を主張しない。

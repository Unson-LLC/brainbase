# Daily Reflection

## 目的

`/oyasumi`は「今日を閉じる」報告ではない。人間の睡眠と同じように、その日の経験を整理し、記憶として固定し、関連付け、翌日以降に思い出せる状態へ整える夜間処理である。

成果物は`/oyasumi`の睡眠レポートとして夜に生成・保存する。利用者は翌朝そのレポートを読み、誤った記憶、関連付け、重要度を訂正する。訂正結果はBrainbaseの記憶状態へ戻す。`/ohayo`の役割や表示には混ぜない。

## 責務境界

### このSkillが行うこと

- 未処理、矛盾、期限切れ、未配信を照合する
- 同じEpisodeの経験を圧縮し、記憶と関連付けを作る
- 再編した記憶を思い出せるか再読取する
- 深い睡眠か浅い睡眠かを判定する
- 浅い場合は、その原因と記憶への影響を先頭で説明する
- 再編された記憶に正式event IDを付け、翌朝の訂正対象として返す
- Personal KG登録候補とGraph昇格レビュー待ちを別枠で返す
- 実行結果と睡眠レポートをRun Receiptへ残す

### このSkillが行わないこと

- `/ohayo`の生成または表示変更
- カレンダー、メール、Slack、SNSなど元サービスの直接巡回
- Graph SSOTへの自動昇格
- 利用者の確認前の記憶訂正
- 外部送信、公開、削除、購入その他の不可逆操作

外部連携の事実は、Brainbaseへ正規化されたRun Receiptがある時だけ利用する。元サービスへフォールバックしない。

## 正本の分担

| 正本 | 睡眠処理での役割 |
|---|---|
| Graph SSOT | 組織の正式な経験と判断を再編する。正式event IDを訂正対象へ付ける |
| Personal KG | 本人の判断基準、制約、学びを再編する。所有者だけが訂正する |
| Run Receipt | 実行結果、部分取得、未確認、失敗を照合する |
| Episode compaction | 同じ経験に属する記憶、関連付け、出典event IDを固定する |

## 実行手順

### 1. 対象期間を確定する

- 明示期間があればその期間
- 夜間自動化では、その日の前回実行後から今回実行時刻まで
- 期間を確定できない場合は推測で成功扱いにせず、確認不能を睡眠原因へ出す

### 2. 睡眠を妨げた状態を照合する

取得前に0件を置かない。未処理、矛盾、期限切れ、未配信ごとに、確認済み件数か未確認理由を保持する。

- 未処理: 経験を記憶へ統合しきれていない
- 矛盾: どの記憶を優先するか確定していない
- 期限切れ: 古い記憶の整理が残っている
- 未配信: 経験の取り込みが完了していない

### 3. 経験を記憶へ再編する

同じEpisodeに属する判断、結果、未解決事項を圧縮する。圧縮成果物には対象event ID集合、版、ハッシュ、記憶の要約、関連付けを持たせる。Personal KGとGraph SSOTは混ぜない。

### 4. 思い出せることを確認する

圧縮後の成果物と対象eventを再読取する。全対象の保存と再読取が確認できた場合だけ圧縮完了とする。HTTP成功やINSERT成功だけでは完了にしない。

### 5. 睡眠状態を判定する

- `deep`: 4つの妨害要因が確認済み0件で、圧縮と再読取が完了
- `shallow`: 妨害要因が1件以上、圧縮未確認、または再読取未確認
- `unconfirmed`: 必須入力を取得できず、深浅自体を確定できない

浅い睡眠は評価語だけで終えず、最初の原因を見出しに含める。全原因には件数と記憶への影響を付ける。

### 6. 睡眠レポートを出す

本文は次の順にする。

1. 睡眠状態と一番大きい理由
2. 浅くなった理由の全件
3. 固定・更新された記憶
4. 新しく作られた関連付け
5. 未解決のまま残った項目
6. 翌朝に訂正できる記憶（正式event ID付き）
7. Personal KG登録候補
8. Graph昇格レビュー待ち
9. 折りたたんだ確認根拠

内部ログや正常なFYIは本文に出さない。「何が起きたか」より先に「睡眠はどうだったか、なぜか」を示す。

### 7. 翌朝のフィードバックを受ける

利用者のフィードバックは`feedback_targets`のevent IDへ紐付ける。

- 正しい: 採用として記録する
- 間違い: 元記憶を訂正または撤回する
- 関連が弱い: 関連付けを訂正対象へ戻す
- 重要でない: 今後の想起優先度を下げる根拠として記録する

フィードバック処理は`/oyasumi`成果物への応答であり、`/ohayo`へ混ぜない。適用できない場合は成功を装わず、対象ID、未適用理由、次の再試行を残す。

## 失敗時の停止線

- 必須入力を取得できない: `unconfirmed`とし、深い睡眠を主張しない
- 圧縮保存または再読取を確認できない: `shallow`または`partial`にする
- Personal KGが未接続: 個人記憶を空として扱わず、未確認理由を出す
- 訂正対象へ正式event IDを付けられない: 訂正可能とは表示しない
- 実行記録を残せない: レポートを生成できても全体を成功にしない

同じ失敗を無制限に再試行しない。安全な既定回数を超えたら、原因、影響、次の確認をレポートへ残す。

## 関連コマンド

- `/oyasumi`: 睡眠処理を実行し、睡眠レポートを生成・保存する
- `/ohayo`: 別責務。起床後の一日をどう見るかを示す
- `/retro`: 睡眠履歴から繰り返す問題を仕組み変更へ変える

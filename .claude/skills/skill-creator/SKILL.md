# Skill作成支援

Skillの依頼を、再利用できる小さな入口と必要時に読む資料へ整理する。通常の実装や一時的なメモには使わない。

## 入力

- ユーザーが残したい作業・判断・知識
- 対象の利用者と起動条件
- 既存Skill、関連文書、所有者、配置規約
- 新規作成か既存Skillの更新か

## 進め方

1. 再利用する知識と一回限りの文脈を分け、Skillの対象を一つの作業に絞る。
2. `.claude/skills/*/SKILL.md` と関連資料を検索し、既存の所有者・重複・参照先を確認する。
3. `name` はkebab-case、`description` は「何をするときに使うか」を一文で書く。広すぎる起動条件や宣伝文句を入れない。
4. 入口には判断に必要な概要だけを書き、長い手順・例・ドメイン知識は `references/` やスクリプトへ分ける。必要時だけ資料を開く段階的開示（progressive disclosure）にし、入口から全資料を読むよう要求しない。
5. 既存Skillを更新するときは対象ファイルの所有範囲を保ち、無関係なSkill、個人配布物、利用者の変更を上書きしない。

## 出力

最低限、次を満たす `SKILL.md` を作成・更新する。

- **使用条件**: 起動条件と対象外
- **入力**: 判断に必要な情報
- **出力**: 利用者へ返す成果物
- **完了条件**: frontmatter、相対リンク、所有・重複の判断、必要な検証が確認済み
- **参照資料**: 必要時だけ読む相対リンク

小さなテンプレート:

```markdown
---
name: example-skill
description: 具体的な作業をするときに使う。
---

# Example

## 使用条件
この作業を依頼されたとき。無関係な作業には使わない。

## 入力・出力・完了条件
入力、成果物、完了条件をそれぞれ短く書く。

## 参照資料
必要なときだけ `references/detail.md` を読む。
```

## 境界と確認

- 秘密情報をSkillや参照資料へ書かない。外部送信、公開、登録、削除は別の権限と承認を確認する。
- 重複Skillを新設せず、既存Skillの所有者・利用者・参照先を確認して統合先を決める。判断できなければ推測で統合しない。
- 変更後はfrontmatter、相対リンク、重複、差分を確認する。テストは変更の不変条件を観測する最小のものを選ぶ。
- 作成・更新・検証の結果、未確認事項、残した参照先を利用者へ返す。

## 関連資料

- Skill固有の手順や例は、対象Skillの `references/` またはリンク先を必要なときだけ読む。
- リポジトリの所有・配布・Git境界は `AGENTS.md` と関連Skillを優先する。

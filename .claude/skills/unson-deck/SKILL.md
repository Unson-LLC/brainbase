# 合同会社雲孫 資料制作

## 正本を解決する

制作前に [正本マニフェスト](references/canonical-sources.md) を読む。

次の順番を変えない。

1. Graphで組織 `unson` とブランド `brand_unson` を取得する。
2. このSkillと `presentation-deck-design` を制作手順の正本として読む。
3. Google Driveの `資料テンプレート/CURRENT.md` を取得し、そこが指す版だけをテンプレート正本として使う。
4. CURRENT版フォルダからテンプレート、ロゴ、写真その他の原本を取得する。
5. workspaceは入力・生成・検品の作業場所としてのみ使う。

Graph、Drive、Skillのいずれかが取得できない、CURRENTが存在しない、またはCURRENTと版フォルダが食い違う場合は `未確認` として停止する。過去のローカルコピーへ自動でフォールバックしない。

## 固定ガードレール

- 法人正式表記は必ず `合同会社雲孫` とする。`株式会社雲孫` に変換しない。
- BAAOのロゴ、色、レイアウト、ページ文法、Skillを使用しない。
- `旧参考資料` は比較・監査を明示された場合だけ参照する。通常制作の入力候補から除外する。
- ブランドモードは `brand-led` を正本とする。`simple-monochrome` はユーザーが明示的に指定した案件だけの派生テーマとする。
- ロゴ画像やテンプレート本体をこのSkillへ複製しない。Driveの正本IDを参照する。
- Graphの事実、Driveのアセット、repoの手順、workspaceの作業状態を混在させない。

## 制作する

1. `presentation-deck-design` のBrainbase Source Gateを通す。
2. 用途、読み手、必要な判断、公開範囲、編集可能形式の要否を確定する。
3. 構成案、ページ役割、強弱、読書量、視覚資産を先に設計する。
4. CURRENT版のデザインシステムを固定し、ページ単位で制作・検品する。
5. 一覧画像で全体を確認し、失敗ページだけを直す。
6. PowerPointまたはGoogleスライドが必要なら編集可能正本を作り、画像だけを最終正本にしない。
7. PDFを出す場合はページ数、順序、寸法、先頭・末尾ページを検証する。

## 公開・版更新

- 制作途中はworkspaceへ置く。
- レビュー済みのバイナリと共同編集物だけをDriveの新しい版フォルダへ配置する。
- 既存版を上書きせず、意味のある変更は新しいセマンティック版として追加する。
- 新版承認後にDriveのCURRENTを更新し、その後Graphのテンプレートポインタを同じ版へ更新する。
- 顧客への送信、外部公開、共有範囲の拡大は別途承認を得る。

## 完了条件

- Graphの正式社名とブランドを参照した。
- DriveのCURRENTと版フォルダIDが一致した。
- BAAOと旧参考資料が通常入力に入っていない。
- ページ単位検品と一覧検品を完了した。
- 編集可能性、PDF検証、未確認事項を明示した。
- 使用版、Drive ID、Graph ID、生成物の保存先を実行レポートへ残した。
